호출·초기화·종료 순서는 변경 시 정적으로 확인하며 실제 출력 검증과 구분합니다. 마지막 애니메이션 보완은 플레이어/동료의 모션 교체·전환·취소·복귀를 다룹니다. 계약·확인 범위는 [사운드](../SOUND_SYSTEM.md)·[VFX](../VFX_SYSTEM.md) 시스템, 외부 연결은 [사운드 연계](../../LJ_INTEGRATION_GUIDE.md#공통-관리자와-사운드-연결)·[VFX 연계](../../LJ_INTEGRATION_GUIDE.md#공용-vfx-연결)를 참조합니다.

### 부활 — 구현/기본 동작 사용자 확인, 추가 검증/외부 연결 남음

PlayerReviveData의 구현 기준은 사망 연출 완료 후 5초/최대 HP의 50%/스테이지당 2회입니다. 이전 무제한/최대 HP 부활 규칙은 폐기합니다. 실제 처리 흐름과 API/이벤트 계약은 [COMBAT_SYSTEM.md의 플레이어 사망/부활 처리](../COMBAT_SYSTEM.md#플레이어-사망부활-처리), 완료 기록과 검증 수준은 [DONE.md](../../DONE.md)를 참조합니다.

기본 부활 대기·체력 복구·행동 복귀·횟수 소진은 사용자 확인 범위입니다. 상세 이력은 [DONE.md](../../DONE.md)를 참조합니다.

- [ ] 세 번째 사망의 OnReviveExhausted 인자/발행 횟수 확인

- [ ] HP/부활 이벤트 시 최종 위치와 부활 연출 완료 전 행동 제한 확인
- [ ] 실제 중복 완료 신호와 비활성화/재활성화/일시정지의 대기시간 및 행동 상태 확인
- [ ] 테스트용 즉시 부활의 대기 취소·횟수 유지, 실패 요청의 대기 유지, 실제 체력·연출 완료 후 행동 복구와 남은 쿨타임 확인

## B 담당 적 재사용 연동

- [ ] 실제 적의 풀링/재사용 도입 시 초기화·반환 순서 합의. 현재는 스포너가 생성·초기화하고 사망 연출 완료 후 제거하며 풀 반환은 미구현
- [ ] 비활성화와 새 생명 초기화를 구분하고 피해 이벤트 중 동일 객체의 즉시 반환/재초기화를 피하는 규칙 확인

적의 풀링/재사용은 B 담당 구현에 맞춰 공통 API 연결을 협의합니다. DamageTargetTest에 재사용 기능을 추가하는 LJ 후속 작업으로 취급하지 않습니다.
