2026-10-29 동료 보완 후 사용자 기본 기능 확인을 마쳤습니다. 고용·인원 제한·전투 시작·대상 전환·공격의 기본 흐름을 확인했으며, 기존 3종 공격·배치·사망/재고용 확인 기록을 유지합니다.

실제 맵·화면 통합과 아래 경계 조건은 추가 확인 대상입니다. 현재 계약은 [COMPANION_SYSTEM.md](../COMPANION_SYSTEM.md), 남은 작업은 [COMPANION_TODO.md](../Todo/COMPANION_TODO.md)를 참조합니다.

## 씬과 프리팹 연결

| 대상 | 연결 |
| --- | --- |
| TestScene | 히어로, 재화/보상/콤보 설정, 고용 데이터 맵, 고용/배치 컨트롤러 |
| 고용 프리팹 | Companion/이동/탐색/공통 전투 모듈과 AnimatorHandler. 내장 무기를 Companion의 Source에 연결하며 CompanionTest는 제거 |
| 고용 데이터 | 고용 데이터 맵의 검사/궁수/마법사 설정. 각 설정은 프리팹/CompanionData/비용/대기시간 보유 |
| 원거리 실행자 | CompanionProjectileAttackExecutor, CompanionAimProvider, 발사점/경로 시작점과 ProjectileData |
| 배치 컨트롤러 | 맵의 CompanionPlacementPoint 배열. 히어로/고용 관리자는 씬 Init에서 전달 |
| 배치 포인트 | Trigger BoxCollider 영역과 NavMesh 바닥의 생성 기준점 |
| 적 루트 | Health, DamageReceiver, CombatTarget. 기존 적 초기화에서 Health와 Enemy 진영을 피해 수신에 전달 |
| 이동/탐색 | Agent Type/NavMesh, 적 탐색/타격 레이어와 생성 방해 레이어 설정 |

모델에 맞는 Animator/Avatar/컨트롤러와 공격 타격/종료/사망 종료 신호를 연결합니다. 이동은 CompanionMover가 담당합니다. 타이머 방식의 단독 테스트와 실제 애니메이션 신호를 동시에 사용하지 않습니다.

씬 Init은 재화 → 보상 → 고용 → 배치 참조를 연결하고 BeginStage는 히어로 준비 → 재화/보상 도전 → 고용 도전 순서로 시작합니다. 포인트의 Trigger가 생성 장애물로 취급되거나 표시용 모델이 NavMesh를 막지 않도록 구성합니다.

## 고용/배치 테스트

| 조작 | 의미 |
| --- | --- |
| Play 시작 / 상단 새 도전 시작 | 자동 시작은 설정과 저장된 선택 무기가 있을 때만 실행. 수동 시작도 무기 선택 후 요청 |
| 6 / 7 / 8 | 검사 / 궁수 / 마법사 고용. 같은 타입의 재고용 가능 기록 우선 |
| Z / X | 타입과 무관하게 첫 번째/두 번째 고용 기록 배치 |
| 진행 관리 → 전투 시작 | TestScene.BeginCombat으로 미배치 동료 자동 추종 생성 후 전체 동료 행동 허용 |
| 플레이어/동료/전투 대상 | 고용 기록을 선택해 전투 대상으로 지정하고 별도 적 발생원으로 피해·넉백 요청. 현재 HP와 적용 결과 확인 |
| P | 전투 중 생존 동료를 고용 순서로 한 명씩 치명 피해 테스트 |
| TestScene.RequestEndStage | 정산 후 고용 기록과 동료 정리. 실제 완료 결과 확인 |

P는 CompanionHireTest를 부착한 경우에만 사용하는 직접 키 입력입니다. 정상 피해/사망 연출/재고용 대기 경로를 사용하므로 무적 등 피해 거절 조건은 그대로 적용됩니다.

재고용은 사망 판정 때 시작한 타입 공통 대기와 해당 개체의 사망 연출이 모두 끝난 뒤 스테이지 재화로 요청합니다. 영구 재화는 사용하지 않으며 재화 부족은 생성 전에 거절됩니다.

확인 순서는 Play 진입 → 같은 타입 두 명 고용 → 서로 다른 포인트에서 Z/X 배치 → 전투 시작 → P로 개별 사망 → 연출/대기 완료 후 재고용 → 도전 종료/재시작입니다. 한 명을 미배치로 남겨 자동 추종 생성도 함께 확인합니다.

배치 키는 현재 도전의 고용 순번을 사용합니다. 첫 번째 동료를 배치할 수 없어도 두 번째 동료로 건너뛰지 않는지 확인합니다.

## 연계와 추가 회귀 검증

동료 소환·공격음과 고용 VFX의 기본 출력은 사용자 확인을 마쳤습니다. 사망·재고용·비활성화 등 전체 출력 수명은 추가 검증이며 [사운드](../SOUND_SYSTEM.md#확인-범위와-후속)·[VFX](../VFX_SYSTEM.md#확인-범위와-후속) 시스템에 둡니다.

고용 VFX는 준비 중 최초 배치, 미배치 동료의 첫 전투 자동 생성, 전투 중 고용·재고용에서 각각 1회 출력되는지 확인합니다. 기록만 있는 고용·준비 실패·기존 동료 재배치에는 출력이 없어야 합니다. 상태 효과 테스트는 [공통 절차](COMBAT_TEST.md#상태이상넉백-연결)를 따릅니다.

기절 출력 중 동료를 사망시켰을 때 쓰러진 뒤에도 공전·잔상이 남지 않고 즉시 제거되는지 확인합니다. 이 경로는 사용자 확인을 마쳤으며 다른 상태 효과·타입별 재고용·비활성화 수명은 추가 검증입니다.

실제 맵·설정에서 다음 결과를 확인합니다. 표의 항목은 아직 전체 통과로 확정하지 않은 추가 검증입니다.

| 대상 | 절차와 기대 결과 |
| --- | --- |
| 타입별 대기·HUD | 같은 타입 2명 고용 → 1명 사망 즉시 해당 타입 슬롯 차단/대기 시작 → 다른 생존 개체 HP·초상화 유지 → 사망 연출 종료 후 사망 개체 HUD만 비움 → 대기 중 같은 타입 추가 사망 시 전체 대기로 갱신하고 슬롯 표시 동기화 |
| 타입 간 독립·비용 | 다른 타입의 대기가 서로 영향을 주지 않는지 확인. 해당 타입 대기 종료 후 재화·인원 조건 재확인, 최초 고용과 같은 비용으로 재고용. 인원 제한은 현재 기록 한도 정책 기준으로 확인 |
| 배치·재배치 | 준비 중 미배치 동료 Z/X 배치 → 이미 배치된 동료를 다른 포인트로 재배치 → 전투 중 추종/방어형과 재고용 동료 배치. 고용 순서 유지, 점유·NavMesh 실패 시 기존 상태/포인트 보존 확인 |
| 목표 우선순위 | 동료에 가까운 적과 방어 목표에 가까운 적을 다르게 배치 → 유효 탐색 범위 내에서 방어 목표 기준 선택 확인. KMB 목표 정보와 합의한 전환 기준으로 기존 타겟 유지/변경 확인 |
| 원거리 이동 | 설정한 시작 거리에서 후퇴하고 확보 거리·방어 반경·유효 경로에 맞게 이동. 경로 실패 후 정지 공격과 재시도, 범위 밖 복귀 확인 |

## 진단 설정

Show Debug Log를 켜면 Companion은 대상·후퇴 전환을, CompanionHireController는 타입 대기·배치·사망 정리를 출력합니다. 수치 변경 방법은 [CSV 사용법](../COMPANION_SYSTEM.md#csv-수치-관리)을 참조합니다.

## 기존 단독 AI 테스트

CompanionTest는 씬에 미리 둔 동료의 초기화/H키 피격/기즈모 확인용으로만 사용합니다. GameManager의 Sound·Vfx 서비스를 동료의 PrepareHire 전에 전달하며 별도 매니저 생성·초기화나 공용 전체 정리를 요청하지 않습니다. 추종형은 Hero, 방어형은 Placement Point를 연결합니다. 적을 초기화하는 책임은 없으며 CombatTarget.Init 호출도 필요하지 않습니다.

탐색/활동 범위, 공격 사거리와 실제 타격 범위를 구분해 확인합니다. 사망/비활성화/범위 이탈 시 타겟 해제, 공격 회차 취소, NavMesh 접근/복귀와 상태이상/넉백 회귀는 동료 TODO에서 관리합니다. 공통 조작은 [COMBAT_TEST.md](COMBAT_TEST.md)를 참조합니다.
