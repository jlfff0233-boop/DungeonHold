# SHOP_SYSTEM

LJ 담당 공통 상품 조회와 소모품·무기·설치물 구매 계약입니다.

## 기획상 판매·해금 범위

Notion A 기획의 상점·해금 기준입니다. 아래 가격은 기획 초기값이며 최종 밸런스가 아닙니다.

| 대상 | 기획 |
| --- | --- |
| 무기 | 최초 선택 1종 무료, 나머지는 각각 영구 골드 300으로 해금. 입장 전 해금된 무기 1종 선택 |
| 설치물 | 화살 발사기·가시 함정 기본 해금, 나머지는 각각 영구 골드 200으로 해금 |
| 소모품 | 체력 물약 50·에너지 물약 75 영구 골드로 구매해 수량 보유 |
| 동료 | 상점 구매와 분리. 처음부터 3종 고용 가능하며 스테이지 골드로 고용/재고용 |

상품 구매는 로비/스테이지 입장 전에만 허용합니다. 구매 해금과 장착 선택은 구분하고 미보유/보유/장착 중 상태를 표시합니다. 설치물의 영구 해금 비용과 도전 중 실제 설치 비용은 별개입니다.

## 적 정보 열람

- 로비 상점에는 적 정보를 표시하지 않습니다. 플레이 중 상점에는 도감 해금 여부와 분리된 간략 정보를 제공합니다.
- PlayScene.TryGetEnemyBriefInfo(stageId, enemy, out data)로 이름·특징·공격 설명에 사용할 EnemyCollectionData를 조회합니다. 현재 도전의 준비/전투 구간에서 등록된 원본 적을 조회하며 종료 예약 이후에는 거절합니다.
- API는 현재 스테이지 출현 여부를 검사하거나 목록을 제공하지 않습니다. KMB의 표시 대상 전달과 LHJ의 화면·갱신 연결은 후속입니다. 원본 SO의 스토리·상세를 간략 화면에 그대로 공개하지 않습니다.
- 정보 열람은 구매 허용 조건과 분리하며 기존 구매 제한을 완화하지 않습니다. 도감 해금·최초 보상·신규 표시 해제를 처리하지 않습니다.
- 도감의 상세 정보·배경 스토리와 클리어 해금 기준은 [COLLECTION_SYSTEM.md](COLLECTION_SYSTEM.md#정보-공개-범위)를 참조합니다.

## 현재 구현 범위

IShopProduct로 세 종류를 묶고 ShopData에서 같은 맵으로 조회합니다. 구매·선택과 해금 제한은 아래 계약을 따릅니다. 담당자별 연결 상태는 [상점·해금 연계](../LJ_INTEGRATION_GUIDE.md#상점해금-후속-안내)에서 관리합니다.

## 구성·연결

로비에서는 LobbyController, 플레이 씬에서는 PlayScene의 공통 상품 조회/구매·무기 선택·보유 조회를 사용합니다. 기존 TestScene 호출은 상속으로 유지하며 소모품 전용 API와 구분합니다. 로비 초기화·요청 수명은 [로비 시스템](LOBBY_SYSTEM.md)을 따릅니다.

- ShopData: 기존 소모품 배열을 보존하고 무기·설치물 배열을 추가합니다. 초기화에서 참조·가격·중복을 검사하고 전체 Products와 상품 맵을 확정합니다. 검사 실패 시 맵은 비어 있습니다.
- ShopProduct / WeaponShopProduct / InstallationShopProduct: IShopProduct의 ProductId·Price와 종류별 기존 데이터 참조를 제공합니다. 소모품은 기존 ItemId, 무기는 weapon:숫자, 설치물은 installation:TrapId로 조회합니다. 저장은 기존 WeaponType·TrapId를 사용합니다.
- ShopPurchase: 상품을 한 번 조회해 기존 소모품 또는 EquipmentUnlock에 전달합니다. 소모품은 지불·수량 검사와 기존 통합 저장을 사용합니다.
- EquipmentUnlock: 공유 진행의 해금·선택을 복원하고 구매·선택 저장 성공 후 상태와 알림을 반영합니다. 현재 상품에서 빠진 저장 기록도 보존합니다.
- PlayScene: 공통 GetProductPurchaseState(productId, out price)·TryPurchaseProduct(productId), TrySelectWeapon(type), ShopProducts·SelectedWeapon·IsWeaponUnlocked·IsInstallationUnlocked·OnEquipmentChanged를 제공합니다. 기존 GetPurchaseState(itemId)·TryPurchaseItem(itemId)는 소모품 전용으로 유지합니다.
- 구매 조건: 씬 활성·초기화 완료·재화 도전 미진행·종료 예약 없음. 설치 준비 시간도 도전 중이므로 구매 불가입니다.

## 구매 계약

공통 경로는 입장 전 조건 → 상품 조회 → 종류별 구매 조건 → 통합 저장 → 실행 중 상태 반영 → 잔액 반영 → 변경 알림입니다. 상품 객체를 전달하므로 종류별 함수에서 같은 상품을 다시 조회하지 않습니다.

- 소모품: 지불·보유 상한 → 잔액/수량 저장 → 수량 → 잔액/재화 알림 → 인벤토리 알림.
- 무기: 보유 확인 → 저장 해금 기록이 없으면 가격 0, 아니면 상품 가격 → CanSpend → 잔액/해금/최초 선택 저장 → 보유/선택 → 잔액/재화 알림 → 해금 변경 알림. 이후 구매는 기존 선택을 바꾸지 않습니다.
- 설치물: 기본 해금·구매 보유 확인 → CanSpend → 잔액/구매 ID 저장 → 보유 → 잔액/재화 알림 → 해금 변경 알림. 기본 해금 상품은 AlreadyOwned이며 구매 기록에 추가하지 않습니다.
- 무기 선택: 판매 상품·보유 확인 → 같은 선택이면 저장 생략 → 선택 저장 → 실행 중 선택 → 변경 알림. 자동 구매나 재화 차감은 없습니다.

- 한 번에 한 개 구매하며, 구매로 쿨타임·사용 횟수·효과를 변경하지 않습니다.
- 저장 실패 시 런타임 상태를 유지합니다. `Currency.TrySpend()` 후 수량을 따로 저장하지 않습니다.
- 결과: 기존 값의 순서를 유지하고 AlreadyOwned / NotOwned를 끝에 추가했습니다.

## 초기화·도전 수명

공통 진행 복원·모듈 연결은 [저장 시스템의 초기화](PLAY_FLOW.md#진행-연결과-씬-초기화)를 따릅니다. 해금 조회 객체는 최초 재화 알림 전에 준비하며 생성만으로 저장·재화 변경·알림을 하지 않습니다. 단순 재활성화는 표시 구독만 복구합니다.

기존 1·4인자 입장은 저장된 선택 무기를 사용합니다. 직접 무기를 받는 5인자 입장은 그 도전에만 적용하고 저장된 선택을 변경하지 않습니다. PlaySession은 기존 입장 조건 뒤, Hero/재화 준비 전에 해금 여부를 확인합니다. 무기 미선택 신규 진행은 자동 입장을 기다리며 Inspector 무기를 지급하지 않습니다. Inspector 무기 필드는 편집 중 범위 표시에만 사용합니다.

종료 예약·정산 실패·정리 대기 중에는 기존 조건으로 구매/선택을 차단합니다. 전체 정리 후 다시 허용하며 시작/종료에서 영구 해금·선택을 초기화하지 않습니다. 동료 고용 타입은 플레이어 무기 해금과 무관합니다.

## 검증과 후속

상품 가격은 ShopData의 연결된 상품에서 조회하며 기획 초기값과 개발용 설정을 구분합니다.

기본 구매·선택·저장 복원은 사용자 확인 범위입니다. 확인 이력은 [DONE.md](../DONE.md), 저장 검증 절차는 [SAVE_TEST.md](Test/SAVE_TEST.md), 남은 검증·연계는 [TODO.md](../TODO.md#무기설치물-해금-후속)를 참조합니다.

## 해금 확장 시 책임 경계

LJ 구현 범위와 남은 연계는 다음과 같습니다.

| 담당 | 책임 |
| --- | --- |
| LJ | 최초 무료 선택·기본 해금, 상품/보유 상태, 구매 조건·중복 구매 차단, 무기 선택/입장 제한, 설치물 사용 가능 정보 제공 |
| KMB | 실제 설치 실행의 해금 검사 구현. 직접 선택·설치 경로의 통합 검증은 후속 |
| LHJ | 소모품 구매/사용·시작 무기 구매/선택 연결 구현. 나머지 상품의 가격·잠금·보유·장착 표시와 요청 연결은 후속. 상태·잔액은 각 시스템 API로 변경 |
| 저장 연결 | 잔액·해금·선택 통합 확정과 복원. 저장 형식·확정 순서는 [저장 계약](SAVE_SYSTEM.md#무기설치물-해금과-선택-저장), 남은 검증은 TODO 참조 |

기존 통합 저장 함수를 실제 구매·선택에서 호출하며 최신 확정 데이터의 다른 기록을 보존합니다. 저장 계약은 [SAVE_SYSTEM.md](SAVE_SYSTEM.md#무기설치물-해금과-선택-저장), 남은 검증은 [TODO.md](../TODO.md#무기설치물-해금-후속)를 참조합니다.
