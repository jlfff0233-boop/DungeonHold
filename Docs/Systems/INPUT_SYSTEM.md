# INPUT_SYSTEM

2026-10-28 LJ 단축키 편집·저장·Play 재실행 복원과 실패 처리 검증을 마쳤습니다. KMB 설치·철거·회전·웨이브 시작의 공용 액션 조회와 키 편집 중 실행 차단 코드가 반영됐습니다. 실제 행동·입력 수명 검증과 LHJ 화면 연결은 후속입니다.

## 구성

| 모듈 | 책임 |
| --- | --- |
| KeyBindingEntry | 액션 경로·개별 바인딩 ID·기능명 |
| KeyBindingSettings | 편집 복사본·배정 검사·입력 대기·적용·취소 |
| KeyBindingStorage / LocalSettingsFile | 단축키 직렬화 / 공통 설정 파일 읽기·교체. 진행 저장/Firebase와 분리 |
| SettingsManager / GameManager | 단축키·화면·볼륨 설정 소유 / 전체 초기화·시작·프레임 갱신·포커스/종료 조율 |
| InputHandler | 기존 입력 전달과 재지정 입력 소비 중 이동값 해제/요청 차단 |
| GameManagerEditor | 직접 지정·실제 키 재지정·적용/저장·파일 조회·선택 기능 입력 로그 |
| KeyBindingSaveDebug | 격리된 파일·액션 복사본으로 쓰기 실패/재시도·손상 복원 검증 |

## 대상과 배정 규칙

- 단축키 설정에 22개 액션·키보드/마우스 버튼 30개 배정을 등록합니다. 이동 방향·방향키 보조 배정과 공격의 좌클릭/Enter는 개별 항목입니다.
- 이동·점프·회피·공격·스킬·궁극기, 설치·철거·회전·웨이브 시작, 설치물 선택 5칸·동료 고용 3칸·소모품 2칸, 동료 배치 2칸을 대상으로 합니다. 시점 이동·게임패드는 변경하지 않습니다.
- 삭제된 Interact/Previous/Next와 미사용 Crouch/Sprint는 등록하지 않습니다. 기본 배정 원본은 공용 Input Actions 에셋입니다.
- 키보드 개별 키와 마우스 버튼 5개만 허용하며, 등록된 배정끼리 중복을 거절합니다. 슬롯 키 변경은 슬롯 번호나 실행 대상을 바꾸지 않습니다.
- 예약 키는 재지정 취소용 Esc와 정보 패널용 T입니다. F/V/R/G는 아래 기능의 기본 배정이며 기존 중복 검사로 관리합니다.
- 기본값 복원은 편집값만 변경합니다. 적용 전에는 실제 입력이 바뀌지 않으며, 편집 종료는 이미 적용한 배정을 되돌리지 않습니다.

| 추가 액션 | 기능 | 기본 키 |
| --- | --- | --- |
| Player/PlaceInstallation | 설치 | F |
| Player/DemolishInstallation | 철거 | V |
| Player/RotateInstallation | 설치물 회전 | R |
| Player/StartWave | 웨이브 시작 | G |

네 액션은 기존 편집·검사·저장·복원 경로를 사용합니다. 기존 바인딩 ID와 저장 형식은 유지하며 새 항목의 저장 기록이 없으면 기본 배정으로 시작합니다. 실제 실행부 연결 상태는 [연계 가이드](../LJ_INTEGRATION_GUIDE.md#단축키-연결)를 참조합니다.

## 조회와 요청 API

접근점은 `GameManager.Instance.Settings.KeyBindings`이며 기존 `GameManager.Instance.KeyBindings`도 유지합니다. 설정 화면은 편집 이벤트를 구독한 뒤 TryBeginEdit 성공 후 최초 조회하며, HUD는 적용 배정 변경 이벤트 구독 후 현재 값을 조회합니다. 공통 소유·수명은 [설정 시스템](SETTINGS_SYSTEM.md)을 참조합니다.

| API | 계약 |
| --- | --- |
| Entries | 기능명·액션 경로·바인딩 ID 조회. 저장 식별자는 바인딩 인덱스가 아닌 ID |
| GetBindingDisplay / GetDraftBindingDisplay | 실제 적용 키 / 편집 중인 키 표시 |
| TryBeginEdit() | 현재 적용 상태의 복사본 생성. 중복 편집과 입력 소비 중 시작 거절 |
| StartRebind(entry) | 시작 입력 해제 후 새 키 대기. Esc 취소, 선택/취소 키 해제 프레임까지 소비 |
| TrySetDraftBinding(entry, path, out reason) | 지정 경로로 편집. 실제 키 재지정과 배정 검사/변경 함수 공유 |
| CancelRebind() | 현재 입력 대기만 취소. 이전에 편집한 다른 배정 유지 |
| ResetDraft() | 편집값을 기본 배정으로 변경 |
| TryApplyRuntime(out reason) | 파일 저장 없이 현재 실행에 적용. Inspector 검증 경로 |
| TryApply(out reason) | 전체 편집 배정 저장 성공 후 실제 적용·LoadError 해제·변경 알림. 실패하면 편집값 유지 |
| CancelEdit() | 미적용 편집값 폐기. 남은 키 해제 대기는 유지하며 닫히는 화면에 알림 없음 |
| IsEditing / IsCapturingInput / RebindMessage | 편집·입력 소비·재지정 안내 조회 |
| OnEditChanged / OnBindingsChanged | 편집/입력 대기 변경 / 실제 적용 완료 알림 |
| LoadError | 최초 파일 복원 실패 사유. 저장 없는 적용으로 지우지 않음 |

조회 이벤트는 실제 행동 성공을 뜻하지 않습니다. 공격·스킬·고용·아이템은 기존 행동/에너지/쿨타임/재화 규칙을 따릅니다.

## 저장과 복원

- 경로는 `Application.persistentDataPath/keybindings.json`입니다. `_bindings` 배열에 기본값과 다른 배정의 바인딩 ID·입력 경로만 저장하며 전체 기본값으로 저장하면 빈 배열입니다.
- 배정은 변경/복원 시 검사합니다. 저장 요청은 편집 가능 상태 확인 → 변경 배정 직렬화 → `.tmp` 쓰기 → 기존 파일 교체(최초 저장은 이동) → 실제 적용 → 변경 알림 순서입니다. 쓰기 실패는 자동 재시도하지 않으며 기존 파일·적용값·편집값을 유지해 명시적 재시도가 가능합니다.
- 읽기는 [SaveJsonReader](SAVE_SYSTEM.md#json-읽기)로 원문 배열을 확인한 뒤 배정 ID·허용 키·예약 키·중복을 검사합니다. 목록 누락/null/타입 오류를 정상 빈 배열과 구분합니다.
- 진행 삭제와 Firebase 백업/복원에 포함하지 않습니다. 앱 종료에서 자동 저장하지 않습니다.

## 초기화와 종료

```text
GameBootstrap → GameManager.Awake → 저장 기반 준비 → SettingsManager의 단축키 최초 복원
→ 씬 InputHandler가 같은 설정과 공용 액션 참조
```

- 복원은 기본 배정의 복사본에 전체 기록을 반영한 뒤 최종 배정을 검사합니다. 서로 키를 교환한 기록을 중간 상태의 중복으로 거절하지 않습니다.
- 파일 없음은 기본 배정으로 시작합니다. 읽기/내용 오류는 일부 복원을 폐기하고 기본 배정·LoadError를 제공하며 원본 파일을 덮어쓰지 않습니다.
- 적용은 대상 액션의 활성 상태 보관·비활성화 → 바인딩 변경 → 원래 활성 상태 복구 → 알림 순서입니다. 공용 액션 객체와 기존 입력 처리 순서는 유지합니다.
- 입력 대기는 GameManager.Update → SettingsManager.Update에서 게임 시간과 무관하게 처리합니다. 포커스 상실은 입력 대기만 취소하며 편집값은 유지합니다.
- 씬 전환·재활성화에서 설정을 다시 초기화하지 않습니다. 앱 종료는 입력 대기·복사본·Editor 관찰·이벤트 참조를 정리하고 저장/편집 알림을 발생시키지 않습니다.
- GameManager.IsInitialized는 저장 서비스 준비 상태입니다. 설정 최초 적용과 영구 진행 준비는 [설정 수명](SETTINGS_SYSTEM.md#초기화와-수명)을 따릅니다. UI 액션 활성화·일시정지·커서 수명은 설정 객체가 소유하지 않습니다.

## Inspector 검증

1. Play 후 자동 생성된 GameManager 선택 → 편집 시작.
2. 검증 대상 선택 → 키/마우스 버튼 직접 지정 또는 실제 키 입력으로 재지정. 후자는 Game 뷰 포커스 이동 후 시작합니다.
3. 저장 없이 적용 → 선택 기능 입력 로그 켜기 → Game 뷰에서 이전 키와 변경 키 확인.
4. 재실행에도 유지하려면 저장 후 적용 → 저장 파일 조회 → Play 종료/재실행 후 적용 키 확인. 기본값 복원도 저장 후 적용해야 다음 실행에 유지됩니다.
5. Inspector 대상 변경/종료·플레이 종료는 해당 도구의 편집·관찰·예약 콜백을 정리합니다.

입력 로그는 선택한 Input Action 기준이며 같은 기능의 보조 배정도 관찰합니다. 이동은 값 변화, 버튼은 누른 프레임만 기록합니다. 실제 행동 승인과 파일 저장 성공을 확인하는 로그가 아닙니다.

쓰기 실패·재시도/손상 파일 복원 버튼은 고유 임시 폴더와 비활성 액션 복사본에서 실행합니다. 실패 시 원본·적용값·알림 유지, 원인 제거 후 재시도, 손상 거절과 정상 복원을 확인하고 종료 시 테스트 자원을 정리합니다. 실제 플레이 액션과 사용자 저장 파일은 변경하지 않습니다.
