# COLLECTION_SYSTEM

LJ 담당 적 도감의 데이터·해금·최초 보상·저장·조회와 CSV 임포터를 구현했습니다. 일반 적 4종과 Minotos의 표시 문구를 반영했습니다. 정식 보스 연결·실제 UI·KMB 승리 통합과 추가 검증은 후속입니다.

## 범위와 규칙

- 도감 SO는 설정만 보관하고 단일 진행의 해금·신규 상태는 런타임 진행과 저장 데이터에서 관리합니다.
- 적이 등장하는 스테이지를 클리어하면 관련 적 중 미해금 항목을 해금합니다. 같은 적의 재클리어·다른 스테이지 출현으로 보상을 반복하지 않습니다.
- 적 종류별 해금은 단일 진행에서 난이도 공통으로 관리합니다. 미션의 난이도별 처치/완료 기록과 독립적입니다.
- 최초 해금 보상은 각 도감 SO에 설정한 영구 재화입니다. 현재 설정값은 일반 적 각 50, Minotos 200입니다. 보상 0도 정상 해금입니다.
- 해금 기록·신규 표시·보상 잔액을 함께 저장합니다. 별도 수동 수령이나 보상 수령 상태는 두지 않습니다.
- 도감을 정상적으로 열고 닫으면 확인 대상으로 전달한 신규 표시를 해제합니다. 단순 비활성화·씬 이동을 확인 완료로 간주하지 않습니다.
- 실패·포기·단순 조우·처치만으로 도감을 해금하지 않습니다.

## 정보 공개 범위

- 도감은 상세 정보와 배경 스토리를 제공하며 관련 스테이지 클리어로 해금하는 규칙을 유지합니다. 미해금 도감의 비공개 정책은 아래 표를 따릅니다.
- 특징·공격 형태와 별도로 BackgroundStory를 보관하며 해금된 CollectionEntryInfo에만 스토리를 채웁니다.
- 플레이 중 상점은 해금 여부와 무관하게 이름·특징·공격 설명을 간략 표시합니다. 로비 상점에는 적 정보를 표시하지 않습니다. 대상 목록과 실제 화면 연결은 [SHOP_SYSTEM.md](SHOP_SYSTEM.md#적-정보-열람)를 참조합니다.
- 기존 CollectionEntryInfo는 미해금 항목의 상세 값을 채우지 않습니다. 간략 표시를 위해 이 잠금 처리를 해제하지 않으며 간략 열람으로 해금·최초 보상·신규 확인을 처리하지 않습니다.

## 데이터와 식별

| 항목 | 설정/표시 기준 |
| --- | --- |
| 고정 적 ID | 도감 SO가 소유. 프리팹·SO 이름을 저장 ID로 사용하지 않음 |
| 원본 적 설정 | EnemyData 참조로 연결. 기존 적 코드·프리팹 변경 없이 조회 |
| 분류 | 일반 적 4종과 보스 Minotos. Minotos는 도감 확인용 EnemyData에 연결 |
| 표시 정보 | 이름·3D 대표 이미지·특징·공격 형태·배경 스토리 |
| 수치/저항 | 원본 EnemyData의 기본 HP·피해량·이동속도·기절 면역·감속 저항 |
| 미해금 | 이름은 ???, 이미지·설명·상세 수치를 공개하지 않음. 실루엣 표현은 UI 후속 |
| 최초 보상 | 도감 SO의 적 종류별 영구 재화 |

SO에는 정적 설정만 두고 해금/신규 상태를 기록하지 않습니다. 같은 EnemyData는 한 도감 항목에 연결하며 여러 스테이지에서 재사용할 수 있습니다. 여러 원본 설정을 한 도감 항목에 묶는 변형은 실제 필요가 생긴 뒤 확장합니다.

도감 화면은 기존 CollectionEntryInfo.Kind로 일반 적·보스 책갈피를 구분합니다. 로비의 출현 스테이지 조회는 기존 맵·난이도 목록과 등장 적 제공자의 원본 적 구성을 사용합니다. 머지 전 화면의 별도 출현 장소 문구는 [HUD 브랜치 현황](../LJ_INTEGRATION_GUIDE.md#머지-전-hud-브랜치)을 참조합니다.

EnemyData·전투 수치·적 동작은 KMB가 관리하며 LJ 도감과 임포터는 원본을 참조만 합니다. KillReward는 처치 시 스테이지 재화이고 도감 최초 보상과 다릅니다. 도감 수치는 전투 중 현재 HP나 감속된 속도에서 읽지 않으며 난이도 보정을 별도로 계산하지 않습니다. 대표 이미지는 Inspector에서 수동 연결하며 현재 5종 모두 미연결입니다.

## 모듈과 공개 조회

| 모듈 | 책임 | 주요 함수/조회 |
| --- | --- | --- |
| EnemyCollectionData | 고정 ID·EnemyData·분류·표시·해금 보상 SO | 읽기 전용 설정 조회 |
| EnemyCollectionDataMap | 도감 설정 검사와 원본 적 매핑 | Validate, TryGet(ID/EnemyData) |
| CollectionProgress | 단일 진행의 해금·신규와 잠금 상태별 표시 조회 | GetEntries, TryGetEntryInfo, IsUnlocked, IsNew |
| CollectionUnlock | 도전 결과·최초 해금·신규 확인 저장/적용 | BeginStage, TryUnlock, TryMarkSeen, GetStageResult |
| CollectionEntryInfo | 잠금 상태에 맞는 표시 값 전달 | ID·분류·해금/신규·이름/이미지·상세 정보 |
| CollectionUnlockInfo | 이번 도전의 실제 해금/보상 결과 전달 | 해금 ID 목록·실제 지급 보상 |

로비 UI는 LobbyController의 Collections·TryMarkCollectionSeen·OnCollectionChanged를 사용합니다. 조회 객체/구독 수명은 [로비 시스템](LOBBY_SYSTEM.md)을 따르며 플레이 씬의 공통 진입점은 PlayScene입니다. 기존 TestScene 호출은 상속으로 유지합니다.

로비 준비 후 `LobbyController.TryGetEnemyStages(enemyId, out stages, out isComplete)`로 해금된 적의 출현 맵을 조회합니다. 여러 난이도에서 같은 적이 등장해도 맵당 한 번만 반환합니다. 반환값 `true`는 조회에 성공한 구성이 하나 이상 있다는 뜻이고, `isComplete`는 등록된 모든 맵·난이도의 조회 성공 여부입니다. 일부 구성만 확인한 빈 목록과 조회 자체가 불가능해 반환한 `false`를 구분합니다.

| PlayScene API | 계약 |
| --- | --- |
| Collections | 현재 진행의 잠금 상태에 맞는 상세 표시 조회 객체 |
| TryGetEnemyBriefInfo(stageId, enemy, out data) | 현재 도전과 등록된 원본 적으로 간략 표시용 EnemyCollectionData 조회. 상태 변경 없음 |
| RequestEndStage(result, discardPendingCurrency, collectionEnemies) | 최종 결과와 스테이지 구성의 원본 적 목록 접수 |
| TryMarkCollectionSeen(source, enemyIds) | 화면을 열 때 확보한 조회 객체와 신규 ID로 확인 요청 |
| GetCollectionStageResult(stageId) | 원래 도전의 해금/보상 결과 조회. 다음 도전 시작 성공 전까지 보관 |
| OnCollectionChanged | 최초/변경 상태 재조회 |
| OnCollectionUnlocked(result) | 저장 성공한 최초 해금 결과 알림 |

간략 조회는 활성·초기화 완료·도전 준비·미션 비처리 상태에서 현재 도전 번호와 등록된 EnemyData를 요구하며 종료 예약 이후에는 거절합니다. 준비 구간에서도 조회할 수 있습니다. 반환값은 원본 도감 SO이므로 간략 화면은 이름·특징·공격 설명만 사용하고, 잠금별 상세·스토리는 Collections로 조회합니다.

이 API는 출현 적 목록을 만들거나 현재 스테이지 포함 여부를 검사하지 않습니다. 표시 대상과 전달·갱신 시점은 KMB/LHJ 연계 후속이며, 실제 구매 허용 조건과 독립적입니다.

## 검사 책임과 오류 처리

| 위치 | 검사 책임 |
| --- | --- |
| 도감 설정 초기화 | 빈 항목·ID 누락/중복·EnemyData 연결 누락/중복·음수 보상 |
| SaveService 로드 | 외부 파일 목록 누락·빈/중복 ID·신규 ID가 해금 목록에 포함되는지 |
| CollectionProgress 복원 | 검사된 기록 복원. 현재 맵에서 빠진 ID도 보존하되 표시에서 제외 |
| 최종 결과 접수 | 전달한 관련 적을 도감에 매핑할 수 있는지 확인하고 대상 보관 |
| CollectionUnlock | 중복 종류 제거·이미 해금한 항목 제외·이번 SO 보상 계산 |
| 도감 저장 함수 | 준비된 후보를 최신 확정 진행에 반영하고 저장 |

설정/파일 검사를 실행 함수마다 반복하지 않습니다. EnemyData 내부 수치 참조·전투 설정의 유효성은 KMB 책임이며 도감 맵에서 재검사하지 않습니다. 잘못된 매핑은 대상과 원인을 드러내는 설정 오류로 보고하고 저장 실패와 구분합니다. 설정 오류를 부분 해금·빈 목록·변경 없음으로 숨기지 않습니다.

처리 가능 여부는 PlayScene의 명령 경계에서 관리하고 도전·종료 조율은 PlaySession이 담당합니다. 하위 도감 함수는 설정 검사를 반복하지 않으며, 성공한 도전의 해금 처리 완료 상태만 유지해 종료 재시도의 중복 지급을 막습니다.

## 초기화

공통 진행 복원·모듈 연결은 [저장 시스템의 초기화](PLAY_FLOW.md#진행-연결과-씬-초기화)를 따릅니다. 도감 조회 객체는 최초 재화 알림 전에 준비하여 알림 수신자가 복원된 해금·신규 상태를 조회할 수 있게 합니다.

PlayScene은 도감 맵 미연결 시 초기화에 실패하며 빈 맵은 허용합니다. 초기화 실패 시 이전 도감 서비스·구독을 사용하지 않습니다. 재활성화는 표시 이벤트 구독을 복구하며 진행 불러오기·최초 지급·도전 개설을 반복하지 않습니다.

## 해금·신규 확인

```text
접수 시 확인한 대상에서 중복 종류·기존 해금 제외
→ SO 보상 합산
→ 최신 저장 후보에 해금·신규·잔액 함께 저장
→ 도감 진행·이번 결과·처리 완료 상태 반영
→ Currency.ApplySavedPermanentBalance
→ 이번 해금 결과 알림·도감 변경 알림
```

저장 실패 시 런타임 해금/신규/재화를 바꾸거나 획득 성공을 알리지 않습니다. 재화 알림에서도 새 도감 상태를 조회할 수 있도록 도감 상태를 먼저 적용합니다. Currency.TryAdd로 보상을 다시 지급하지 않습니다. 저장 계층에서 미해금 여부와 SO 보상을 다시 판정하지 않습니다.

화면을 열 때 조회 객체와 당시 신규 ID를 확보하고 정상 닫기에서 TryMarkCollectionSeen에 전달합니다. 현재 신규인 대상만 저장하고 성공 후 표시를 해제합니다. 확인 저장 실패 시 신규 상태를 유지하며 화면이 열린 뒤 해금된 다른 항목은 해제하지 않습니다. 씬 재초기화 전 화면의 닫기 요청은 거절합니다.

## 종료·재시도·결과 보관

전체 종료 순서와 실패 단계별 재시도는 [공통 플레이 흐름](PLAY_FLOW.md#최종-종료와-완료-통지)을 따릅니다. 미션과 도감은 서로 직접 호출하지 않습니다.

- 접수 시 적 매핑을 확인해 파일 저장 실패 재시도와 설정 오류를 구분합니다. 전달한 대상 목록은 보관하여 외부 변경에 영향받지 않게 합니다.
- 도감은 성공한 처리 단계를 기록해 뒤쪽 정산 실패 후에도 저장/보상 알림을 반복하지 않습니다.
- 패배·포기는 도감 단계를 생략합니다.
- 비활성화만으로 최종 결과·미완료 단계·대상 목록을 지우지 않습니다.
- 종료 정리에서 처리용 대상은 해제하되 이번 도전의 해금/보상 결과는 남깁니다. 원래 도전 번호로 조회하고 다음 도전 시작 성공 시 새 결과로 초기화합니다.
- Victory는 원본 적 목록을 명시해야 합니다. 빈 목록은 정상이며 미제공·미등록 적·빈 참조는 예약 전에 거절합니다. 2인자 명시적 결과 호출은 대상을 전달하지 않으므로 승리에 사용할 수 없습니다.
- 승패와 미지급 스테이지 재화 폐기 정책은 독립적이며 Victory이면 폐기 여부와 관계없이 도감을 평가합니다.

Stage1Controller는 전체 웨이브 구성의 EnemyData를 중복 제거해 전달합니다. 현재 판정에 연결된 Stage1_Normal_Data는 기본형 3마리가 포함된 1웨이브이므로 이 설정의 승리 해금 대상은 기본형입니다. 실제 스폰 참조와의 차이는 [플레이 씬 연결](../LJ_INTEGRATION_GUIDE.md#플레이-씬-연결), 일반 적 4종의 해금은 개별 검증 범위를 따릅니다.

로비 등장 적 조회는 승리 해금과 별개입니다. 실제 구성 제공자를 조회해 도감에 매핑하며 조회로 해금·신규 확인·보상·저장을 변경하지 않습니다. 로비 목록의 이름·이미지 표시 옵션과 실제 제공자 연결은 [로비 계약](LOBBY_SYSTEM.md#최고-점수와-등장-적)을 참조합니다.

## CSV 임포트

- [EnemyCollection.csv](<../../Assets/03. Configs/Collection/EnemyCollection.csv>)는 UTF-8이며 한 행이 적 한 종류입니다. 고정 ID와 신규 SO 이름은 EnemyCollection_0_Basic처럼 넘버링합니다.
- 현재 헤더는 `EnemyId,EnemyAssetPath,Kind,DisplayName,Feature,AttackDescription,RewardAmount,BackgroundStory`입니다. Kind는 Normal/Boss, RewardAmount는 0 이상의 정수입니다.
- 선택 컬럼 BackgroundStory가 없으면 기존 스토리를 보존하고, 있으면 셀 값으로 갱신합니다. 빈 셀은 스토리를 지웁니다. 출현 스테이지는 웨이브 데이터에서 조회합니다.
- `Create > Collection > Data Map`으로 저장한 맵과 기존 출력 폴더를 `Tools > Enemy Collection CSV Importer`에 연결하고 검사·미리보기 후 적용합니다.
- 같은 ID는 기존 SO와 이미지 참조를 유지해 갱신하며 원본 EnemyData 변경은 차단합니다. CSV에 없는 항목·기존 맵 순서를 보존하고 신규 항목을 CSV 순서로 추가합니다.
- 전투 수치와 대표 이미지는 CSV에 넣지 않습니다. 원본 적·씬·저장 진행을 변경하지 않으며 TestScene 맵 연결 상태는 안내만 합니다.
- 적용 직전 입력/에셋 변경을 확인합니다. 저장 실패 시 일부 반영 경로를 표시하며 자동 롤백하지 않습니다.
