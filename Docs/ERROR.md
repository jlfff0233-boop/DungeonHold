# ERROR

## PURPOSE

개발 진행을 실제로 막았고 원인 추적에 시간이 걸린 오류와 해결법을 기록합니다.

반복적인 조작 불편으로 입력 방식이나 흐름을 변경한 경우에는 증상과 개선 이유도 짧게 남길 수 있습니다.

다음 항목은 기록하지 않습니다.

- 단순 경고
- 아직 구현하지 않은 기능
- 일반적인 설계 고민
- 아직 발생하지 않은 잠재적 문제
- 바로 해결되어 추적 가치가 낮은 사소한 실수

## ERROR_LIST

### 2026-11-05 방어 규칙 Everything 선택 후 도전 시작 거절 — 해결

- 원인: Flags 선택창의 Everything(-1)을 그대로 전달해 정의되지 않은 비트 검사에 거절됐습니다.
- 조치: 디버그 선택값을 NoPass/NoDamage로 제한했습니다. 이후 Hard 도전 시작·연속 정산을 사용자 확인했습니다.

### 2026-11-03 상태 VFX 미표시·이동 잔상·만료 후 위치 고정 — 해결

- 원인: 감속 눈송이가 방출하지 않는 부모의 충돌 서브이미터로 등록됐고, 화상은 World 공간을 사용했습니다. 상태 만료에서는 기존 Stop이 추적까지 해제했습니다.
- 조치: 감속 서브이미터 등록 해제·독립 방출, 화상 Local 전환. 상태 만료는 StopEmission으로 방출만 중단하고 잔여 추적을 유지합니다.
- 확인: 사용자 출력·이동·만료 표현 확인. 전체 수명 검증과 API 계약은 [VFX 시스템](Systems/VFX_SYSTEM.md)을 참조합니다.

### 2026-10-28 JSON 필수 목록 누락이 빈 목록으로 복원됨 — 해결

- 증상/원인: Unity JsonUtility가 누락된 최상위 목록을 빈 목록으로 보완해 손상 파일을 정상 기본값으로 받아들였습니다. FromJsonOverwrite 전 null 초기화만으로는 구분되지 않았습니다.
- 조치: SaveJsonReader에서 Newtonsoft로 원문 필수 배열의 존재/타입을 먼저 확인하고 기존 데이터 변환·값 검사로 전달합니다. 정상 빈 배열과 버전 6의 최고 별 목록 보완은 유지합니다.
- 확인: 사용자 단축키 손상 복원 27/27·진행 JSON 20/20 통과. 계약은 [SAVE_SYSTEM](Systems/SAVE_SYSTEM.md#json-읽기) 참조.

### 2026-10-14 검 스킬 치명타 대상의 넉백 거절 — 해결

- 원인: 피해/사망 확정 후 넉백을 요청하면서 기존 생존 검사에 거절됐습니다. 순서만 바꿔도 사망 이벤트와 갱신 검사에서 넉백이 중단되는 구조였습니다.
- 조치: 같은 타격의 실제 피해량/사망 결과를 직접 전달해 치명타 넉백을 허용하고 부활/비활성화에서는 정리합니다. 별도 사망 승인 기록은 추가하지 않았습니다.
- 확인: 독립 로직 검사와 사용자 Unity 로그의 사망 후 넉백 종료 확인. 실제 Enemy 제거/풀 반환 시점은 후속 연동입니다.

실제 오류가 발생하면 아래 형식을 사용합니다.

---

### 오류 제목

#### 증상 / 조건

- 어떤 상황에서 문제가 발생했는지 기록합니다.
- 재현 조건이 확인된 경우 함께 작성합니다.

#### 원인 / 근거

- 확인된 원인을 기록합니다.
- 원인이 확정되지 않았다면 후보라고 명시합니다.
- 추측을 확정 원인처럼 기록하지 않습니다.

#### 조치

- 실제 적용한 변경을 기록합니다.
- 다른 담당자의 영역을 직접 수정하지 않고 협의 또는 별도 TODO로 넘긴 경우 함께 기록합니다.

#### 확인 범위

- 코드 반영만 확인했는지
- 사용자 실행 확인이 있었는지
- Unity 플레이 / 빌드를 직접 확인했는지
- 아직 재검증이 필요한지 구분합니다.

#### 재발 방지

- 동일 유형의 문제가 반복될 가능성이 있을 때만 작성합니다.

---

## ERROR_RULES

- 해결되지 않은 문제를 해결 완료로 기록하지 않습니다.
- 사용자 보고, 정적 코드 확인, Unity 실행 확인을 구분합니다.
- 하나의 증상만으로 원인을 단정하지 않습니다.
- 다른 담당자의 코드에서 원인을 발견해도 현재 작업 범위 밖이면 임의 수정하지 않습니다.
- 미구현 기능은 오류로 기록하지 않고 `TODO.md`에서 관리합니다.
