# 소모품 상점·인벤토리 연결 — 2026-10-24

## 반영 범위

- 새 UI 스크립트 `ConsumableScreenBinder`를 StoreScreen과 InventoryScreen 프리팹에 연결했다.
- 상점 2번 체력 물약·3번 에너지 물약 카드의 이름·아이콘·설명·보유 수량·가격을 실제 ShopData에서 표시한다. 현 판매 가격은 체력 100/에너지 150이며 UI에 고정하지 않는다.
- 두 물약 카드의 기존 강화 미리보기 리스너만 제거하고 구매 요청을 연결한다. 다른 상점 카드의 동작은 유지한다.
- 카드 클릭 한 번으로 `TestScene.TryPurchaseItem`을 요청한다. UI에서 재화나 수량을 직접 변경하지 않는다. 같은 프레임의 중복 요청도 막는다.
- 재화 부족·보유 상한·현재 진행 상태에 따른 구매 불가를 가격 영역과 비활성 버튼으로 표시한다. 저장 실패 등 실제 요청 실패는 별도 상태 문구로 표시한다.
- 상점 오른쪽 위 `소모품 인벤토리` 버튼으로 이동한다. 상점 루트를 활성 상태로 유지하되 CanvasGroup으로 감추고 입력을 차단하여 기존 결과 화면/일시정지 복귀 문맥을 보존한다.
- 인벤토리의 기존 도감·적 목록은 변경하지 않았다. 오른쪽 위 `소모품 보유 목록` 버튼과 별도 소모품 보유 화면을 추가한다.
- 보유 수량이 0인 물약 행은 숨기고, 모두 0이면 빈 목록 안내를 표시한다.
- 인벤토리 사용 버튼은 `GetItemUseState`의 실제 조건을 따른다. 사용 요청은 `TryUseItem`으로만 실행한다. 회복 성공 결과와 실제 회복량을 표시한다. 재사용 대기시간도 실제 조회값으로 표시한다.
- `ItemInventory.OnChanged`와 영구 재화 변경 이벤트로 구매·사용 후 갱신한다. 다시 열거나 초기화 대상이 바뀌면 현재 값을 재조회하고 이전 구독을 해제한다.
- 상점에서 열었을 때 뒤로는 상점으로, 일반 인벤토리에서 열었을 때 뒤로는 기존 도감 화면으로 돌아간다. 상점이 닫히면 방문 중인 소모품 화면도 닫는다.

## 수정 경계

이번 변경은 신규 UI 스크립트·meta와 StoreScreen/InventoryScreen의 루트 컴포넌트 추가, 이 문서에 한정했다. 기존 상점 프리팹의 수정은 보존했다. 구매·사용·재화·저장·입력 등 다른 담당자의 스크립트와 데이터, Canvas_Screens, 기존 UI 이미지 작업은 수정하지 않았다.

## 검증

- 신규 UI 스크립트만 기존 프로젝트 어셈블리를 참조하여 별도 임시 DLL로 컴파일한다. 전체 프로젝트 빌드나 Unity 실행은 하지 않는다.
- 두 화면의 루트 컴포넌트·ShopData·폰트 GUID, 두 물약 카드 이름과 로컬 ID 중복을 정적으로 점검한다.

Unity에서 남은 실행 확인:

1. 입장 전 상점에서 체력/에너지 물약 구매. 판매 데이터 가격만큼 차감되고 수량이 1개 증가하는지 확인.
2. 재화 부족·보유 상한·구매 불가 진행 상태에서 미차감과 안내 확인.
3. 상점 → 소모품 인벤토리 → 뒤로. 재화·수량·기존 상점 카드 상태 및 결과/로비 복귀 문맥 확인.
4. 일반 인벤토리 → 소모품 보유 목록 → 뒤로. 기존 도감 화면 유지와 빈 목록 표시 확인.
5. 도전 중 피해/에너지 소비 후 물약 사용 또는 기존 퀵슬롯 사용. 수량 감소와 재사용 대기, 회복 불가 상태의 비활성 표시 확인.
6. 화면 재열기·도전 종료·재시도 후 이전 수량 잔존이나 중복 구매/사용이 없는지 확인.
