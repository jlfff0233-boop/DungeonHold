# 공용 퀵슬롯 6~0 HUD 연결

2026-10-25

## 변경 범위

- `SupportQuickSlotHudBinder`와 해당 메타 파일 추가, `Canvas_HUD.prefab`에 표시용 컴포넌트 추가.
- 기존 입력·고용·아이템 처리 및 설치물 1~5번은 변경하지 않음.
- 다른 작업자의 이미지 및 임포트 설정은 변경하지 않고 기존 텍스처를 참조함.

## 표시 계약

| 키 | UI-MapTest의 실제 실행 대상 | 표시 |
| --- | --- | --- |
| 6 | 검사 | 무기 타입 아이콘, 신규/재고용 비용, 가능 여부 |
| 7 | 궁수 | 무기 타입 아이콘, 신규/재고용 비용, 가능 여부 |
| 8 | 마법사 | 무기 타입 아이콘, 신규/재고용 비용, 가능 여부 |
| 9 | 등록된 체력 물약 | 아이콘, 보유 수량, 사용 상태, 남은 쿨타임 |
| 0 | 등록된 에너지 물약 | 아이콘, 보유 수량, 사용 상태, 남은 쿨타임 |

기존 HUD는 이름이 WeaponSlots인 칸도 설치물 1번이며 InstallationSlots (4)~(8)이 6~0번이다. 이 기존 다섯 칸에 연결하며 런타임에 슬롯을 복제하지 않는다. 앞서 무기 칸을 제외하고 인덱스를 계산해 한 칸 밀렸던 연결을 수정했다. 숫자키 실행 경로는 유지한다. 동료·물약 이름은 숨기고 수량 없음 문구는 표시하지 않는다. 슬롯은 수동 표시만 수행한다.

동료 비용은 실제 고용 데이터에서 조회한다. 재고용 가능한 기록이 있으면 재고용 비용을 표시한다. 같은 타입이 대기 중이어도 정원이 남으면 기존 실행 규칙에 맞춰 신규 고용 비용을 표시한다. 정원이 찼으면 인원 제한 또는 해당 동료의 사망 처리/실제 재고용 대기 시간을 표시한다. 재화 부족도 구분한다.

물약 상태는 `GetItemUseState` 및 실제 인벤토리에서 조회한다. 회복 아이템 사용 조건 불충족 시 영웅이 행동 가능하면 회복 불필요, 그렇지 않으면 사용 불가로 표시한다. 수량 및 재화/고용 이벤트와 매 프레임 조회로 변경과 타이머를 반영한다.

입력 컴포넌트가 비활성화되면 입력 차단을 표시한다. 키 구독, 클릭 실행, 구매/고용/아이템 사용 호출은 추가하지 않는다. HUD 비활성화 시 표시와 구독을 정리하고 재표시 시 현재 서비스와 값에 다시 연결한다.

## 설정 동기화

도메인 코드에 공개 접근자를 추가하지 않기 위해 에디터에서는 SerializedObject로 씬의 퀵슬롯 5~9 인덱스, 입력 참조, 고용 맵/정원을 읽는다. 원본 객체에는 쓰지 않는다. 빌드에서는 HUD 프리팹에 저장한 현재 설정의 사본을 사용한다. 씬의 퀵슬롯 배치·정원·데이터를 바꿀 때에는 HUD의 저장 설정도 함께 갱신해야 한다. 런타임에 퀵슬롯 구성을 교체하는 기능은 이 연결 범위에 포함하지 않는다.

## 검증

- 기존 Unity 어셈블리를 참조한 신규 스크립트 단독 컴파일: 런타임 및 UNITY_EDITOR 모두 통과.
- 씬 퀵슬롯 인덱스 5~9의 데이터 GUID와 HUD 저장 참조 일치 확인.
- 신규 코드에 키 입력 구독이나 실행 함수 호출이 없는 것 확인.
- UI-MapTest의 일시정지 입력 차단 목록에 실제 InputHandler가 포함된 것 확인.
- `git diff --check` 통과.
- Unity Play는 수행하지 않음. 실제 숫자키 6~0 실행, 메뉴 차단, 재고용 대기/정원, 물약 사용 후 수량/쿨타임, 재시도 및 0번 슬롯 화면 배치 확인은 남아 있음.
