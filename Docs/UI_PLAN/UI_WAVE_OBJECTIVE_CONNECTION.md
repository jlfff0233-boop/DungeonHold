# 웨이브·방어 목표·별점 UI 연결 — 2026-10-25

## 반영

- 기존 `Presentation/UI/WaveHudBinder.cs`를 보완했다. 기존 필드와 .meta GUID는 유지했다.
- UI-MapTest 씬의 기존 WaveHudBinder 컴포넌트에 참조 두 줄만 추가했다. WaveController와 Stage1Controller가 실제 사용 중인 동일한 UI-TemporaryStage 에셋 및 대응 Stage1Controller를 연결했다.
- 총 웨이브 수를 임의로 고정하지 않고 Stage1Data.WaveCount에서 조회하여 현재/전체로 표시한다.
- 준비 시간·전투 중·웨이브 종료·스테이지 성공/실패·입장 전 상태를 구분한다. 웨이브 완료만으로 승리로 표시하지 않는다.
- 통과 수/실패 한도를 표시하고 실제 한도의 80% 이상이면 경고색, 한도 도달 시 실패색으로 표시한다. 현재 출현 적은 ActiveEnemyCount이며 스폰 예정 적을 포함한 전체 남은 적으로 설명하지 않는다.
- 실제 2성/3성 통과 조건과 현재 통과 수로 유지 가능한 별점을 표시한다. 한도 도달 시 유지 가능 0성이다. 조건은 클리어했을 때의 평가 기준임을 표시한다.
- 최종 별점과 성공/실패는 Stage1Controller의 확정값만 사용한다.
- 별점 조건 텍스트는 기존 목표 영역 아래에 실행 중 추가하며, 기존 UI 참조나 레이아웃 에셋을 교체하지 않는다.
- 웨이브 재시도/대상 교체/비활성화 시 이전 문자열·경고색을 지우고, 다음 갱신 또는 재표시 때 현재 값을 조회한다. 도전 종료 후 입장 전 상태에서는 이전 통과 수와 출현 적 수를 0으로 표시한다.

## 보존 범위

다른 담당자의 WaveController/Stage1Controller/Stage1Data/TestScene과 설정 에셋은 수정하지 않았다. UI-MapTest의 변경은 기존 UI 컴포넌트의 설정 및 판정 컨트롤러 참조 2개뿐이며, 게임 오브젝트나 게임 컴포넌트는 변경하지 않았다. 기존 다른 UI 작업도 보존했다.

Temporary UI Test/UI-KMBMapTest 1 씬은 과거 방식의 웨이브 직렬화 값만 있고 현재 Stage1Data 참조가 없어 변경하지 않았다. 설정이 없는 UI에서는 한도/별점 미연결로 표시하며 임시 목표값을 넣지 않는다.

- WaveHudBinder 단독 컴파일: 기존 프로젝트·Unity 어셈블리 참조, 오류 없음. 전체 프로젝트 빌드는 미수행.
- UI-MapTest에서 UI가 참조한 WaveController의 Stage1Data와 판정 컨트롤러의 Stage1Data가 같은 GUID인지 정적으로 확인했다.
- 씬 변경이 UI 컴포넌트의 두 참조 추가로만 구성되었는지 diff 확인했다.
- 별점 분기: 통과 수가 3성 기준 이하이면 3성, 2성 기준 이하이면 2성, 실패 한도 미만이면 1성, 한도 이상이면 0성이다. 최종 판정 로직은 변경하지 않았다.
- Unity 실행·실제 경계값·텍스트 배치 검증은 미수행.
