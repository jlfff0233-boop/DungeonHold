# UI 화면 제작 우선 — 1주차 상세 계획 (7일·56시간)

수정: 2026-10-10  
기준: [전체 6주 계획](UI_WORK_PLAN.md#7-ui-화면-제작-우선-일정), [참고 이미지 목록](UI_REFERENCE_CATALOG.md).

1주차 목표는 **기존 공통 부품 보완 → 플레이 진입 화면 제작 → 기본 HUD와 안내 표시 제작 → 표시 검수**다. 하루 약 8시간씩 7일, 총 56시간을 배분한다. 이미 진행한 시간도 총 6주에 포함하며 새로 1주를 추가하는 일정이 아니다. 시간은 학습·배치·확인·수정·저장을 포함한 작업 예산이고 실측 견적이 아니다.

이 문서의 1~7일차가 현재 날짜별 계획이다. 이전의 공통 부품만 7일에 나눈 계획을 대체한다. 전체 계획 11절은 현재 1일차 수동 안내이며, 13·14·15·16절의 과거 일차 제목은 부품별 Inspector 참고로 유지한다. 이 참고 제목을 현재 작업 날짜로 사용하지 않는다. 이미 완료한 과제를 반복하지 않고 다음 미완료 작업부터 진행한다.

전체 UI 화면·페이지·필요 상태의 외형을 완성한 뒤 버튼/데이터를 연결한다. **FX도 전체 UI 화면 제작 완료 후 시작한다.** 연결·복귀·입력 규칙은 연결 단계에서 다시 안내한다. 이번 주에는 배치·문구·이미지·버튼 외형과 수동 표시 상태를 제작한다. On Click·새 Navigation·화면 전환·게임 데이터·저장/네트워크 함수, Tween/파티클 제작을 과제로 넣지 않는다. 기존 연결은 유지한다.

이미 저장된 Canvas_Popup·PauseMenuRoot·HelpPromptRoot·ConfirmDialogRoot·GuideOverlayRoot, Canvas_HUD·Canvas_Health를 재사용한다. 파일 존재가 실제 화면 확인 완료를 뜻하지는 않는다. 예시와 이름/폴더가 다르다는 이유로 이동·삭제·재생성하지 않는다. 없는 부품만 만든다.

작업이 일찍 끝나면 다음 항목으로 넘어간다. 예산을 넘으면 완료/미완료를 기록하고 다음 작업 시간을 재배분한다. 기능·화면을 완료 목록에서 조용히 빼거나 6주 기한을 임의로 늘리지 않는다. 각 날의 마지막 확인 시간에 작은 수정도 처리하되, 큰 수정은 남은 시간에서 다시 계산한다.

## 1일차 — 기존 공통 팝업과 한글 보완

참고: [Pause R44](UI_References/R44_PauseMenu.png), [질문 R42](UI_References/R42_BasicHelpPrompt.png), [재시도 R45](UI_References/R45_RetryConfirm.png). **현재 1일차의 단계별 Inspector 안내는 [전체 계획 11절](UI_WORK_PLAN.md#11-1일차-수동-작업-안내)을 따른다.** 13·14·15절은 부품별 세부 참고다.

| 시간 | 할 일 |
| --- | --- |
| 1시간 | 기존 Canvas·PopupRoot·암막·프리팹 구성 확인 |
| 2시간 | 한글 폰트와 공통 버튼 외형 기준 적용/보완 |
| 2시간 | 기존 Pause 메뉴와 도움말 질문창 보완 |
| 2시간 | 확인창과 질문/확인 문구 변형 표시 |
| 1시간 | 두 해상도 표시 확인·작은 수정·저장 |

구체적인 작업:

1. View의 Canvas_HUD·Canvas_Health·EventSystem·Canvas_Popup과 저장된 공통 프리팹을 확인한다. 기존 값을 먼저 보고 없는 부분만 보완한다.
2. Canvas_Popup은 기존 Overlay·1920×1080·Match 0·Sort Order 100을 기준으로 이어간다. PopupRoot와 암막은 전체 Stretch, 암막은 검정 Alpha 약 0.55를 시작값으로 확인한다.
3. 한글 TMP Font Asset을 기존 Label에 적용한다. 제목·설명·버튼 글자의 크기/색/정렬을 통일하고 긴 한글 문구를 넣어 본다.
4. Pause의 돌아가기·다시 시도·옵션·도움말·나가기 5개를 보완한다. 기존 Root 480×400·버튼 480×64·간격 8을 확인하고 화면에서 필요한 부분만 조정한다.
5. HelpPromptRoot에 기초·인벤토리·마법책 질문 문구 3종을 차례로 표시한다. 질문·설명·예/아니요 배치는 하나를 재사용한다.
6. ConfirmDialogRoot에 재시도·캠페인 복귀·전체 환불의 제목/설명과 확인/취소 또는 예/아니요 문구를 차례로 표시한다. 문구별 프리팹을 따로 복제하지 않는다.
7. 1920×1080·1280×720에서 잘림/겹침을 확인하고 각 Root를 수동으로 끈 뒤 함께 숨는지 확인한다. 프리팹과 씬을 저장한다.

완료 기준: 한글이 읽히고 팝업 3종의 제목/설명/버튼 외형이 일관되며 긴 문구도 들어간다. 화면 표시만 완료로 기록한다.

## 2일차 — 가이드·카드·슬롯·키 안내

참고: [기초 가이드 R41](UI_References/R41_BasicGuide.png), [카드 R35](UI_References/R35_CampaignModes.png), [장비 바 R43](UI_References/R43_PreparationHud.png). **현재 2일차의 단계별 Inspector 안내는 [전체 계획 17절](UI_WORK_PLAN.md#17-2일차-수동-작업-안내--가이드카드슬롯키-안내)을 따른다.** 16절은 가이드 부품별 추가 참고다.

2026-10-10 세로 카드의 Image·앵커·Pivot·위치·상태별 활성 체크는 [보충 18절](UI_WORK_PLAN.md#18-현재-저장-파일-기준-보충--세로-카드-배치)을 참고한다. 이후 SelectionCardVertical.prefab 저장이 확인되었으며, 가로 복사본의 상세 입력은 [SelectionCardWide 안내 19절](UI_WORK_PLAN.md#19-selectioncardwide-수동-설정-안내)을 따른다. 기존 UIPatsPreviewRoot와 카드 계층을 재사용하고 이미 수정된 가이드 회전·크기는 유지한다.

| 시간 | 할 일 |
| --- | --- |
| 2시간 | 기존 GuideOverlayRoot 보완 |
| 3시간 | 선택 카드와 일반/선택/잠금/비용 부족 외형 |
| 2시간 | EquipmentSlot·KeyHint 공통 부품 |
| 1시간 | 표시 확인·작은 수정·프리팹 저장 |

구체적인 작업:

1. GuideOverlayRoot의 Highlight·Arrow·Callout·NextContinueButton·ProgressText를 점검한다. Callout 제목/설명과 진행 숫자가 없다면 보완한다.
2. 같은 가이드에서 다음 + 1/3, 마지막 계속 + 진행 숫자 숨김을 Inspector로 바꿔 표시한다. 첫 대상은 기존 장비 바다. 자동 진행은 연결하지 않는다.
3. 선택 카드에 이미지·이름·설명/비용 영역·선택 테두리·잠금 아이콘·잠금 이유를 배치한다. 일반/선택/잠금/비용 부족 4개 상태를 수동 표시로 확인한다.
4. 세로 영웅 카드와 가로 모드 카드처럼 비율이 다른 경우 같은 스타일을 사용하면서 화면별 배치를 조정한다. 모든 카드를 한 크기에 억지로 맞추지 않는다.
5. EquipmentSlot에 아이콘·비용·선택 표시·잠금·번호/키 이름·사용 가능/부족 표시 영역을 만든다. 3개 샘플을 놓고 긴 가격/이름이 겹치는지 본다. 샘플 3개는 최종 슬롯 수를 확정하는 뜻이 아니다.
6. KeyHint에 키 아이콘/이름과 행동 설명을 배치한다. 짧은 설명과 두 줄 설명을 넣어 본다. 확정되지 않은 키는 임시 표시로 기록한다.
7. 기존 프리팹은 덮어쓰기 전에 변경 범위를 확인하고 저장한다. 없는 공통 부품만 새 프리팹으로 저장한다.

완료 기준: 가이드·카드·슬롯·키 안내가 다음 화면 제작에 재사용 가능하고, 긴 이름/비용/잠금 이유가 겹치지 않는다.

## 3일차 — 타이틀·캠페인/모드 선택

참고: [타이틀 R01](UI_References/R01_Title.png), [캠페인 R02](UI_References/R02_Campaign.png), [모드 R35](UI_References/R35_CampaignModes.png).

| 시간 | 할 일 |
| --- | --- |
| 2시간 | S01 타이틀 화면 |
| 4시간 | S02 캠페인/모드 카드 배치 |
| 1시간 | 선택·잠금·잠금 이유와 버튼 표시 상태 |
| 1시간 | 표시 확인·작은 수정·저장 |

구체적인 작업:

1. 전체 화면 Root에 프로젝트 로고·기존 배경과 플레이/옵션/게임 종료 버튼을 배치한다. 정적 이미지가 없으면 표시 영역과 임시 이미지로 크기를 잡는다.
2. 캠페인/모드 화면에 제목·뒤로·카드 목록·게임 찾기·재화 영역을 배치한다. 공통 버튼과 카드 스타일을 재사용한다.
3. R35의 위쪽 세로 카드/아래쪽 가로 카드 구성을 참고한다. 메인/추가 캠페인·스크램블·무한·주간 모드의 표시 영역을 만들되 실제 항목 수/이름은 우리 게임 데이터 기준으로 교체할 목록을 기록한다.
4. 일반·선택·잠금 카드와 잠금 이유를 수동으로 표시한다. 한글 이름이 길어도 선택 테두리/잠금 아이콘과 겹치지 않게 조정한다.
5. 게임 찾기·뒤로·재화 표시가 빠지지 않았는지 확인한다. 실제 클릭·해금·매칭 동작은 연결하지 않는다.
6. 배경 아트가 없는 상태에서도 제목·카드·버튼이 읽히도록 배치하고 두 해상도에서 확인/저장한다.

완료 기준: S01·S02의 화면 구성과 필요한 선택/잠금 상태가 준비된다. 제목·카드·재화·버튼이 화면 안에 들어간다.

## 4일차 — 난이도/플레이 방식·영웅 선택

참고: [난이도/플레이 방식 R36](UI_References/R36_DifficultyPlayerMode.png), [영웅 R40](UI_References/R40_HeroSelect.png).

| 시간 | 할 일 |
| --- | --- |
| 3시간 | S03 난이도와 플레이 방식 화면 |
| 3시간 | S04 영웅 선택 화면 |
| 1시간 | 선택·잠금·긴 설명·비활성 외형 |
| 1시간 | 표시 확인·작은 수정·저장 |

구체적인 작업:

1. 난이도 제목/변경 가능 안내·난이도 카드 3개·카드별 설명을 배치한다. 선택 테두리와 잠금 외형을 준비한다.
2. 플레이 방식에 솔로/친구 초대/게임 호스팅/게임 찾기 4개 표시와 아이콘 영역을 만든다. 확인/취소 버튼을 배치한다.
3. 영웅 카드에 초상·이름·소개·주 무기·특수 능력과 선택 표시를 넣는다. 영웅 수/소개는 우리 게임 기준으로 교체할 항목을 기록한다.
4. 선택한 영웅과 잠긴 영웅의 외형/해금 설명을 수동으로 표시한다. 설명은 내용이 없는 상태와 긴 내용으로도 확인한다.
5. 일반·선택·잠금, 확인 버튼의 일반/비활성 외형이 구분되는지 본다. 데이터 선택이나 캐릭터 변경 기능은 연결하지 않는다.
6. 같은 공통 카드 스타일이 적용되었는지, 설명이 아래 버튼과 겹치지 않는지 확인하고 저장한다.

완료 기준: 난이도 3개·플레이 방식 4개·영웅 정보와 선택/잠금 표시 영역이 준비된다. 실제 난이도/플레이어/영웅 설정 완료와 구분한다.

2. Preview에는 선택 미션 이미지·이름·최고 점수·평가 아이콘을 넣는다. 기존 이미지/모델 캡처가 없으면 자리표시자를 쓴다. 포털 파티클·왜곡·새 3D 연출은 제작하지 않는다.
3. 오른쪽에 캠페인/모드·난이도·솔로/협동 요약을 배치하고 뒤로·플레이·취소·마법책 진입·페이지 화살표/점을 준비한다.
4. 동일한 로비 Root에서 솔로 선택, 협동의 플레이어 대기 문구/참여자 영역, 플레이 버튼의 일반/비활성 외형을 수동으로 바꾸어 확인한다. 서버 대기 로직은 만들지 않는다.
5. 친구 순위 페이지에는 제목·이름/기록 행·선택 행·전체 순위표 진입·빈 기록 안내를 배치한다. 샘플 행을 넣되 실기록으로 표시하지 않는다. 전체 순위표 본문/조회 화면 S15는 2주차에 제작한다.
6. 미션 기록은 임시 값임을 기록하고 기록 없음 상태도 확인한다. 사진 속 사용자 이름/점수/캐릭터를 최종 프로젝트 데이터로 확정하지 않는다.
7. 미션 이름이 길거나 친구 기록이 없는 경우에도 Preview·요약·버튼이 겹치지 않게 조정하고 저장한다.

완료 기준: S13의 솔로/협동 대기/친구 순위 페이지 외형과 미션 선택/잠금/기록 없음 상태를 수동으로 표시할 수 있다. 실제 미션 이동·순위 조회·협동 기능은 완료로 기록하지 않는다.

## 6일차 — 기본 HUD·장비 바·준비/판매 안내

HUD 배치는 2026-10-12 사용자 지정 [인게임 예시안](UI_References/HUD_Wireframe_2026-10-12.png)을 우선 기준으로 따른다. 좌상단 플레이어·동료 HP/에너지, 상단 중앙 남은 적과 중요 알림, 우상단 웨이브·제한 시간·미니맵, 우측 중간 연속 처치·코인 획득 알림, 좌하단 상점 코인, 하단 중앙 숫자키 아이템 바, 우하단 스킬 영역을 배치한다. 아래 기존 게임 이미지는 상태와 시각 스타일의 보조 참고다. 기존 제작 순서와 시간 예산은 유지하고 버튼/데이터 연결과 FX는 전체 UI 외형 제작 후 진행한다.

참고: [준비 HUD R43](UI_References/R43_PreparationHud.png), [판매 안내 R54](UI_References/R54_TrapSellPrompt.png), [기존 HUD R08](UI_References/R08_PreparationHud.png).

| 시간 | 할 일 |
| --- | --- |
| 2시간 | 기존 HP·에너지·초상 영역 보완 |
| 2시간 | 점수·재화·목표·남은 적·웨이브·시간 영역 |
| 2시간 | 장비/설치 바와 선택·잠금·사용 가능/부족 표시 |
| 1시간 | 준비/판매 KeyHint 배치 |
| 1시간 | 표시 확인·작은 수정·저장 |

구체적인 작업:

1. 기존 Canvas_HUD·Canvas_Health의 필요한 표시 영역을 재사용한다. 체력·에너지·초상 영역의 한글/숫자/색상과 0/일부/가득 찬 표시를 수동으로 점검한다.
2. H01에 점수·전투/영구 재화·목표 점수·남은 적·웨이브·시간을 배치한다. 두 재화가 같은 의미로 보이지 않도록 아이콘/라벨을 구분한다. 실제 값이 없는 시안은 샘플 값으로 기록한다.
3. H02 장비/설치 바는 2일차 슬롯을 재사용한다. 아이콘·비용·선택·잠금·번호/키·사용 가능/부족, 스킬/궁극기 준비/대기 표시 영역을 배치한다. 실제 슬롯 수와 사용 조건은 확정 데이터로 후속 연결한다.
4. H03 준비 단계의 방어 선택/웨이브 시작 안내와 판매 대상 안내를 같은 KeyHint 스타일로 만든다. 판매 안내는 고정 테스트 위치에 배치한다. 대상 추적은 연결 단계로 둔다.
5. 키가 확정되지 않았다면 참고의 B/G/E는 임시 표기로 기록한다. 실제 바인딩이나 입력 규칙을 구현한 것으로 취급하지 않는다.
6. 다음 주 미니맵 H10과 스테이지명 H11을 넣을 영역을 미리 확보한다. 조준/월드·보스 HP·콤보·알림도 2주차 제작 대상으로 남겨 둔다.
7. 긴 숫자/0/빈 아이콘으로도 확인한다. 팝업/가이드와 겹치는 부분을 조정하고 저장한다.

완료 기준: H01·H02·H03의 필수 표시 영역과 상태가 준비된다. 실제 HP/재화 변화·키 변경·판매/설치 판정은 연결하지 않는다.

## 7일차 — 웨이브·설치 안내·기초 가이드·전체 검수

참고: [웨이브 R53](UI_References/R53_WaveStart.png), [설치 불가 R22](UI_References/R22_PlacementInvalid.png), [기초 안내 R41](UI_References/R41_BasicGuide.png).

| 시간 | 할 일 |

| 1.5시간 | H04 웨이브 표시 3종 |
| 1.5시간 | H08 설치 가능/불가 UI 표시 |
| 1시간 | HUD 위 기초 가이드 배치 마감 |

| 1시간 | 저장·표시 확인 기록·2주차 미완료 목록 정리 |

구체적인 작업:

1. H04에 카운트다운 숫자, 시작!, 다음 웨이브 문구를 배치한다. Inspector 문구/활성 상태 변경으로 각 시안을 본다. 실제 타이머·웨이브 이벤트·애니메이션은 연결하지 않는다.
2. H08에는 설치 가능/불가의 색상·금지 아이콘·사유 문구와 회전/확정/취소 안내를 만든다. 고정 테스트 위치에서 UI만 확인하며 설치 판정·추적·고스트 메시/재질·파티클 제작은 후속 단계로 둔다.
3. 기초 안내 1단계에서 목표·재화·장비 바 3지점의 강조/화살표/Callout을 준비하고 계속 문구를 표시한다. 같은 화면에 함께 배치된 설명과 HUD가 겹치지 않게 조정한다. 인벤토리/마법책/강화 가이드의 모든 단계는 해당 화면을 만드는 2주차 과제다.
4. 1920×1080·1280×720에서 팝업, S01~S04·S13, H01~H04·H08을 차례로 수동 표시한다. 각 화면의 일반/선택/잠금/부족/대기/빈 기록 등 해당 상태를 확인한다.
5. 긴 한글·큰 숫자·없는 이미지·잠금 이유를 넣어 잘림/겹침을 찾는다. Root를 껐을 때 함께 숨는지, 가이드가 중요한 HUD를 가리지 않는지 확인한다.
6. 프리팹과 씬을 저장하고 각 화면의 확인 결과/임시 아트/미완료 상태를 기록한다. 클릭 동작·게임 기능·FX가 완료되었다고 표시하지 않는다.

완료 기준: 1주차 목표 화면과 상태의 배치/수동 표시/저장 확인 기록이 있다. 큰 누락이나 수정은 남은 작업으로 남긴다. 이날 시간에는 별도 큰 수정 여유가 없으므로 미완료를 숨기지 않는다.

## 1주차 결과물 체크

아래 항목은 제작 목표다. 계획 작성만으로 완료된 것이 아니며 사용자가 직접 표시를 확인한 뒤 체크한다.

- [ ] 기존 한글·버튼 스타일·암막과 Pause/HelpPrompt/ConfirmDialog 보완.
- [ ] GuideOverlay·선택 카드·EquipmentSlot·KeyHint 공통 부품 준비.
- [ ] S01 타이틀, S02 캠페인/모드, S03 난이도/플레이 방식, S04 영웅 선택 외형.
- [ ] S13 솔로/협동 대기/친구 순위 페이지 외형.
- [ ] H01 기본 HUD, H02 장비 바, H03 준비/판매, H04 웨이브, H08 설치 안내의 UI 외형.
- [ ] 목표·재화·장비를 설명하는 기초 가이드 1단계.
- [ ] 각 화면의 필요한 선택·잠금·부족·대기·기록 없음 등 수동 상태 확인.
- [ ] 두 해상도·긴 문구·큰 숫자·Root 숨김·저장 확인.
- [ ] 아직 없는 이미지/이름/기록과 미완료 작업 목록 기록.

## 2주차로 이어가기

2주차는 전체 계획 7절에 따라 인벤토리·마법책·강화·결과/통계·옵션/설정·도움말 책·세션/초대/전체 순위표·계정/저장 응답·동료/도감/탐험 미션, 나머지 HUD 및 전체 가이드 단계를 제작한다. 1주차 미완료 작업이 있으면 남은 112시간 UI 예산 안에서 먼저 처리한다.

전체 UI가 완성되기 전에는 버튼 연결과 FX를 시작하지 않는다. 2주차 말에 전체 UI의 완료 여부와 남은 연결/FX 예산을 재점검한다. 현재 계획은 UI 2주 마감이 빠듯하다는 전제를 유지하며 6주 완료를 보장하지 않는다.
