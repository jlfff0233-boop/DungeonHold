# 남은 UI 연결 계획 — 2026-10-19

## 작업 순서 변경 — 2026-10-20 사용자 확정

**HUD 통합은 UI 연결 작업 중 가장 마지막에 진행한다.** 기존 테스트 씬에서 개별 HUD 연결·검증은 진행하되, 실제 플레이 씬에 플레이어·웨이브·설치 HUD를 모으고 공통 초기화·참조·알림 우선순위를 맞추는 통합 작업은 나머지 UI 데이터·버튼·화면 전환 연결 이후로 미룬다. 아래 순서가 기존 연결 계획의 HUD 선행 통합 순서를 대체한다. 튜토리얼·도움말 최종 이미지/화살표와 최종 리소스·FX의 후반 작업 방침은 유지한다.

## 확인 범위

현재 저장된 C#·씬·프리팹 및 기존 UI_CONNECTION_PLAN을 정적으로 확인했다. Unity 실행·Play 검증은 하지 않았다. 스크립트 GUID 참조는 컴포넌트가 저장되어 있다는 근거이며, 모든 Inspector 참조와 실제 동작의 완료를 뜻하지 않는다. 현재 git status는 깨끗하고 Docs 내 충돌 마커는 발견되지 않았다.

## 기존 계획에서 달라진 현재 상태

- UI-PlayerTest.unity: PlayerHudView/PlayerHudBinder, CurrencyHudBinder, PlayerSkillHudBinder, PlayerLifeHudBinder, TargetHealthHudBinder/WorldHealthView 참조가 있다.
- UI-KMBMapTest 1.unity: WaveHudBinder, PreparationHudBinder, PlacementHudBinder, WaveNoticeHudBinder, WaveSummaryHudBinder 참조가 있다.
- Canvas_TargetHealth.prefab: TargetHealthHudBinder/WorldHealthView 참조가 있다. 실제 스폰 적·동료에 적용되는지는 별도 확인한다.
- View.unity에서 위 스크립트의 직접 GUID 참조는 검색되지 않았다. 중첩 프리팹과 실행 진입 경로를 확인한 뒤 통합 대상을 확정한다.
- StageHudView는 저장된 씬/프리팹 참조가 검색되지 않았다. 기존 Binder가 직접 TMP를 갱신하므로 반드시 추가할 필요는 없다.
- Hero에 UltimateCaster/CanUseUltimate, StageRewardController에 OnComboChanged/OnRewardPaid/GetComboRemainingTime이 있다. 궁극기·콤보를 API 미확보로 보류했던 기존 계획을 갱신한다.

HUD 통합 후 최종 이미지/화살표·리소스·FX 및 최종 미술 검수를 진행한다. API 미제공 항목은 미완료/보류로 명시하고 완료로 처리하지 않는다.

## 바로 처리할 연결 위험

1. PlayerLifeBinder.cs의 클래스명은 PlayerLifeHudBinder다. Unity에서 정상 컴포넌트로 인식되는지 확인하고 파일/클래스명 정합성을 정리한다. .meta GUID를 보존한다.
2. PlayerSkillHudBinder는 Hero.CanUseSkill을 사용한다. UltimateCaster만 지정해 재사용하면 궁극기 사용 가능 판정이 틀릴 수 있다. 일반/궁극기 구분을 명시한다.
3. PlacementHudBinder는 HasCell/IsAreaAvailable을 바탕으로 일반 안내만 표시한다. 거리·준비 종료·비용·겹침 등 실제 최종 설치 거절 사유를 모두 설명하는 연결은 아직 아니다. 키 안내도 실제 InputHandler와 대조한다.
4. WaveSummaryHudBinder는 OnAllWavesCompleted로 처치/통과 요약을 연다. 스테이지 승리 판정이나 보상 확정 결과 화면으로 간주하지 않는다. _hudRoot를 숨길 때 Binder 자신의 부모까지 비활성화되어 OnDisable→Close가 발생하지 않는 계층인지 확인한다.
5. 웨이브/부활/설치 알림이 같은 Root/Text를 공유하면 덮어쓸 수 있다. 참조를 확인하고 표시 우선순위를 정한다.
6. 일부 소스의 한글은 터미널 출력에서 깨져 보인다. 원본 인코딩과 Unity 실제 표시를 확인한 후 필요한 경우에만 수정한다.

## 권장 작업 배분

- 1차 1~2일: 테스트 씬별 참조·컴포넌트 문제 확인, 기본 HUD 개별 연결과 실행 검증. HUD 통합은 보류.
- 2차 1~2일: 궁극기·무기·콤보/보상, 적·동료 생성/제거 연결.
- 3차 1~2일: 설치 상세 표시와 메뉴/입력/복귀.
- 4차 1~2일: 결과/재시도 개별 연결과 검증.
- 이후: 인벤토리·마법책·강화·해금·고용·미니맵 및 튜토리얼·도움말의 남은 UI 연결을 진행한다.
- UI 연결 최종 단계: 실제 플레이 씬에 HUD 통합 후 메뉴·결과·재시도까지 전체 흐름 회귀 확인. 통합 소요시간은 앞선 연결 상태와 API 준비 상황을 보고 재산정한다.

위 4~8일은 기존 코드 재사용과 필요한 게임 API 제공을 전제로 한 예상치다. 인벤토리/강화/미니맵의 신규 도메인 구현과 후반 FX는 포함하지 않는다. 각 단계는 코드 존재 → Inspector 참조 → 실제 Play 확인을 구분해 기록한다.

## 최소 실행 확인 시나리오

- 시작 직후 → 피격/회복 → 스킬/궁극기 소비·쿨타임 → 사망/부활/최종 소진.
- 준비 자동 종료/조기 시작 연타 → 적 생성·처치·통과 → 다음 웨이브·전체 종료.
- 콤보 갱신/만료·지급 재시도 → 보상 알림 중복 확인.
- 설치 가능/불가·회전·비용 부족·철거 → 준비 종료 직전 입력.
- Pause/복귀·HUD OFF/ON·결과 재열기·재시도·씬 재진입.

게임 로직과 공용 API는 임의로 수정하지 않는다. 연결에 부족한 계약은 담당자 확인 사항으로 남긴다.
