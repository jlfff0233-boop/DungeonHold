# UI·파티클·연출 작업 계획 — 추가 45장 반영

2026-10-20 사용자 확정: **HUD 통합은 UI 연결 작업 중 가장 마지막에 진행한다.** 테스트 씬별 개별 연결·검증을 먼저 진행하고, 나머지 UI 데이터·버튼·화면 전환 연결 이후 실제 플레이 씬에 HUD를 통합한다. 현재 연결 순서는 [남은 UI 연결 계획](UI_REMAINING_CONNECTION_PLAN_2026-10-19.md)을 따른다.

2026-10-12 현재 기준: 원래 제작 계획과 순서를 유지한다. **HUD는 예외적으로 사용자가 제공한 [인게임 예시안](UI_References/HUD_Wireframe_2026-10-12.png)의 정보 배치를 우선 기준으로 따른다.** 나머지 새 예시안은 참고 자료로 사용하며 로비/마법책/강화/결과의 와이어프레임 개편안과 별도 6화면 우선 일정은 적용하지 않는다. 저장 파일 검수와 바로 다음 작업은 [10월 12일 검수](UI_REVIEW_2026-10-12.md)를 참고한다.

작성일: 2026-10-09  
전체 범위·제작 순서·FX 시작 조건 재편: 2026-10-10  
총 작업기간: 기존 진행분을 포함한 6주. 작업 가능 시간: 하루 약 8시간 × 주 7일, 주 56시간·총 최대 336시간.  
기준: 기존 23장 + 새 45장 = 참고 이미지 68개. [전체 이미지 목록](UI_REFERENCE_CATALOG.md).  
이번 변경: 계획·참고 자료만 갱신. 사용자가 만든 씬·프리팹과 게임 코드는 수정하지 않았다.

**새 자료의 UI를 모두 제작 목록에 포함한다.** 기존 문서에서 멀티플레이·영웅·미니맵·분기 강화·전체 환불을 제외/후보로 표시했던 방향을 바꾼다. 같은 화면의 선택 상태·안내 단계는 공통 화면과 데이터로 만들며, 사진 45장을 독립 화면 45개로 복제하지 않는다.

LHJ는 UI와 공격을 포함한 게임 전체 파티클/VFX·연출을 담당한다. 사용자 확정 순서는 **전체 UI 화면 제작 완료 → 모든 버튼·화면 전환 연결 → 연결 검증**이다. **FX도 전체 UI 화면 제작 완료 후 시작**한다. 기존 2주차 FX 시작 계획을 대체하며, 화면 제작 기간에는 FX를 병행하지 않는다. 이 일정에서는 UI 제작 완료 뒤 버튼 연결과 FX 제작에 작업 시간을 나누어 배치한다. 연결·복귀·입력 규칙은 연결 단계에서 다시 안내한다. 제작 기간의 FX 과제와 연결 규칙표 작성은 보류한다. 사진의 게임 로고·인물·수치·콘텐츠 개수는 우리 리소스와 데이터로 교체한다. 정지 사진만으로 애니메이션·효과 시간·화면 전환 순서를 확정하지 않는다.

새 요청은 UI 제작 범위를 넓힌다. 기존 게임 규격과 달라진 기능은 **화면 제작에 포함하고 실제 로직 확장 계약을 별도로 기록**한다. 이 계획 작성으로 PROJECT_CONTEXT의 게임 규칙이나 다른 팀원의 코드가 자동 변경된 것은 아니다.

2026-10-10 저장 파일에서 확인한 기반:

- Canvas_HUD·Canvas_Health, PlayerHudView·StageHudView·WorldHealthView 표시 스크립트가 있다. 스크립트 존재와 실제 Inspector 데이터 연결 완료는 구분한다.
- View에는 기존 Canvas 인스턴스·EventSystem·Canvas_Popup 기반이 있다. 팝업은 1920×1080, Match 0, Sort Order 100을 기준으로 이어간다.
- 사용자가 만든 Canvas_Popup.prefab과 **PauseMenuRoot.prefab의 메뉴 5개**를 확인했다. 위/아래 Explicit 탐색 참조도 저장되어 있다. 이 기반을 다시 만드는 일정으로 돌리지 않는다.
- HelpPromptRoot.prefab의 질문·설명·예/아니요 구성 파일도 확인했다. 현재 경로를 유지하고 없는 요소만 보완한다. 저장 파일 존재를 실제 표시 확인 완료로 기록하지 않는다.
- 저장된 메뉴 TMP는 LiberationSans SDF, 버튼 상태 색은 기본 흰색/회색이다. 한글 폰트·금색 상태색·참조 및 화면 표시를 다음 점검 대상으로 둔다. 실제 한글 렌더링·키 탐색·게임 재개는 아직 실행 확인하지 않았다.
- URP·Particle System·DOTween이 있다. 가져온 Fire_Particle 리소스와 게임용 FX 연결 완료는 구분한다. 별도 VFX Graph 도입을 작업 시작 조건으로 만들지 않는다.

11·13·14·15·16절은 공통 부품별 Inspector 참고로 유지한다. 해당 절 제목의 기존 “1~5일차”는 초기 부품 제작 안내의 이름이며, 현재 날짜별 일정은 [1주차 56시간 상세 계획](UI_WEEK1_DAILY_PLAN.md)을 따른다. 폰트·이미지·Button Target Graphic은 외형 제작에 포함하지만 On Click·새 Navigation·화면 전환·데이터 연결은 전체 화면 제작 후 진행한다. 기존 연결은 유지한다. 이미 만들어진 오브젝트는 해당 단계의 값을 점검하고 다음 작업으로 이동한다. 현재 프리팹 이름/폴더가 예시와 다르다는 이유만으로 이동·삭제·재생성을 요구하지 않는다.

4. GuideOverlay의 대상 Anchor·화살표·Callout·진행도와 페이지 데이터.
5. 상세 정보·장비 슬롯·순위/세션 행·보상 카드·평가 아이콘.

공통 카드 상태: 일반/강조/선택/잠금/구매 가능/재화 부족/처리 중/소유/최대 강화. 카드가 참조하는 아이템·영웅·미션 ID를 유지하고 슬롯 위치나 표시 이름을 식별자로 쓰지 않는다. 목록/선택/스크롤은 하위 화면에서 복귀할 때 보존한다.

## 4. 기존 게임 규격과 확장 기능의 연결 — 후속 연결 단계 참고

모든 행의 **UI 제작은 포함**한다. 아래 차이는 실동작을 위한 데이터/기능 확장 요구다. UI 샘플 값은 테스트 표시임을 기록하고 실제 기능 완료로 처리하지 않는다.

| UI 기능 | 기존 규격과 필요한 연결 |
| --- | --- |
| 캠페인·추가/무한/주간/스크램블 | 모드 ID·잠금·미션 목록·보상/초기화 정책 필요. 카드 7개가 우리 맵 7개를 뜻하지 않음 |
| 협동·초대·호스팅·세션 찾기 | 기존 싱글 우선 기획에 네트워크 담당/서비스 없음. 새 소유자·세션/초대/권한/연결 계약 필요 |
| 친구/전체 순위·외부 계정 | 조회/인증 제공 방식·실패/취소·연결 해제 계약 필요. 실제 기록 없는 값을 0으로 꾸미지 않음 |
| 영웅·영웅 책 | 영웅 ID·선택/해금·능력 데이터 필요. 무기 선택과 영웅 선택을 구분 |
| 장신구·장비 바 재배치·무기 전환 안내 | 선택/장착/슬롯 잠금과 게임 단계별 허용 필요. 기존 “전투 중 무기 1개 고정”과 전환 안내의 차이는 게임 담당이 결정 |
| 레벨/고유/특별 강화·마일스톤 | 기존 선형 3단계보다 확장된 데이터 필요. 선택 분기·구매 조건·진행 저장·능력 적용 계약 |
| 전체 강화 환불 | 초기화 대상·돌려줄 금액·저장 반영을 성장 담당이 처리. 설치물 70% 철거 환불과 별도 |
| 미니맵·적 약점/저항·바리케이드 | 지도/좌표/문·적/목표 데이터, 실제 약점 규칙, 경로 변화 기능 필요 |
| 상태 효과 12종 | 기존 화상/감속/기절 3종 + 새 9종의 표시/FX 포함. 적용·면역·행동 규칙은 공통 전투 계약 확장 |
| 소리/그래픽/키/언어/게임플레이 설정 | 현재/기본/지원 값·적용 결과·저장·복원 필요. 그래픽/VFX 품질은 실제 URP·대상 플랫폼이 지원하는 값으로 제공 |
| 결과 통계·추가 보상 | 확정 결과 스냅샷·측정 항목·신기록/보너스 결과 필요. UI가 피해/보상/점수를 재판정하지 않음 |

현재 유지되는 설치/전투 규격은 실연동 시 적용한다. 참고 사진에 벽/천장 설치나 다른 슬롯 수가 있어도 시안 제작만으로 바닥 설치·준비 시간 제한이 변경되지는 않는다. 평가는 참고의 해골 5칸과 우리 별 규칙을 같은 반복 아이콘 부품의 개수/데이터로 처리한다.

입력 사진의 E/B/G/M, 키보드/패드 아이콘은 값이 아니라 표시 예시다. 도움말·HUD·단축키·키 재매핑이 동일한 실제 바인딩 데이터를 사용하게 한다. 입력 장치 지원 범위도 입력 담당 계약과 연결한다.

조작 도움말의 전쟁 기계·팀 통신·스트림 연결 항목도 페이지 제작 목록에 둔다. 실제 행동/서비스의 지원 규격과 연결하며 별도 기능 본문 화면이 사진에 제공된 것으로 기록하지 않는다. 이동 능력·보조 무기 안내 역시 영웅/무기별 실제 능력과 입력으로 표시한다.

남은 게임 결정: 재화 2종의 실제 구분, 스테이지3 목표/실패, 장비 슬롯과 단계별 변경 허용, 조기/자동 웨이브, 콤보 시간. 추가 기능은 모드/네트워크/랭킹/계정·영웅·분기 강화/환불·새 상태 효과의 규격과 제공 일정이 필요하다. 나가기 UI 목적지는 새 자료 기준 **캠페인/미션 선택 계열로 복귀**하는 것으로 계획하고, 타이틀의 앱 종료와 구분한다.

## 5. 화면 흐름·취소·설정 상태 — 전체 UI 제작 후 다시 안내

이 절은 이전 연결 설계 제안의 보관 자료이며 현재 제작 과제가 아니다. 화면 제작 중 호출/복귀표나 입력 규칙을 작성·연결하지 않는다. 전체 UI 제작 완료 후 실제 화면과 담당 API에 맞춰 검토하고 다시 안내한다. 화면 순서는 구현 제안이며 사진 첨부 순서만으로 실제 게임 진행을 확정하지 않는다.

솔로: 타이틀 → 캠페인/모드 → 난이도·솔로 → 영웅/장비 준비 → 미션 선택/포털 → 스테이지 준비 → 웨이브/전투 → 결과 → 다음 미션 또는 캠페인. 인벤토리·마법책은 준비/미션/결과의 진입 지점에서 호출 화면으로 돌아온다.

협동: 게임 찾기 → 필터/행 선택 → 참가 요청 → 응답 성공 후 같은 미션 로비. 호스팅/초대는 생성·친구 선택/초대 결과를 받아 대기 로비에 진입한다. 참가 후 미션·난이도는 세션 응답값을 표시한다. 호스트/참가자의 변경/시작 권한과 대기/연결 해제 상태를 구분한다.

| 현재 행동 | 다음 상태·복귀 |
| --- | --- |
| Pause → 돌아가기 | 메뉴 닫고 게임/입력 재개 요청 |
| Pause → 다시 시도 | 재시도 확인창. 취소/Esc는 Pause·정지 유지, 확인은 같은 미션/난이도 재시작 요청 |
| Pause → 나가기 | 캠페인 복귀 확인창. 취소/Esc는 Pause, 확인은 복귀 결과 후 화면 이동 |
| Pause → 옵션/도움말 → 뒤로 | Pause·정지 유지. 타이틀에서 열면 타이틀로 복귀 |
| 도움말 질문 → 예/아니요 | 예는 해당 안내, 아니요는 호출 화면. 마법책 질문도 동일 |
| 가이드 → 다음/계속/닫기 | 단계 갱신/종료 후 호출 화면·선택 보존. Pause 도움말에서 다시 조회 가능 |
| 인벤토리 → 적/장비 선택 | 좌측 상세만 변경. 장착·재배치는 허용 상태와 결과를 받음 |
| 책 → 강화 상세 → 뒤로 | 카테고리·선택·스크롤 보존 |
| 책 → 전체 환불 확인 | 아니요는 목록 유지, 예는 처리 중 → 결과 성공 후 잔액/강화/카드 함께 갱신 |
| 결과 → 통계 → 닫기 | 같은 결과 요약으로 복귀. 보상 재지급 없음 |
| 결과 → 업그레이드/책 | 결과 기록을 보존해 책/상세로 진입, 뒤로는 결과 |
| 결과 → 계속/캠페인/재시도 | 실제 다음 미션/복귀/재시작 가능 결과에 따라 진행 |
| 세션 찾기 → 취소 | 검색을 열었던 화면으로 복귀. 참가 요청 중 취소는 해당 요청 결과와 함께 처리 |
| 로비 → 순위 페이지/전체 순위 → 뒤로 | 선택 미션·대기 상태 유지, 원래 로비/페이지로 복귀 |
| 로비 → 취소/연결 끊김 | 참가자 이탈/호스트 해산·오류 응답에 따라 진입 화면 복귀 |

설정은 **진입 시 현재 값 보관 → 임시 값 편집 → 수락 시 적용/저장**한다. 취소는 진입 전 값으로 복원한다. 초기화는 해당 페이지의 임시 값을 기본값으로 바꾸고 수락을 기다린다. 소리 미리듣기를 실제로 적용하면 취소 때 믹서 값도 복원한다. 그래픽 사진에는 초기화 버튼이 없으므로 Footer 버튼을 선택적으로 표시한다. 적용 실패 시 실패 사유와 편집 값을 유지한다.

키 재매핑: 행 선택 → 입력 대기 → 새 키 수신 → 중복/예약키 검사 → 표시 갱신 → 수락. 대기 중 Esc는 키 캡처 취소에 소비한다. 같은 입력이 메뉴 닫기/공격으로 전달되지 않게 한다. 바인딩 적용 후 도움말/키 안내도 갱신한다. 창 모드 변경 후 이전 설정 복귀 확인은 필요 시 추가할 UX 제안이며 사진에서 확인된 동작은 아니다.

공통 화면 제어:

- 입력 소유는 최상위 화면 하나. 호출 화면·선택·페이지·정지 요청을 보존한다.
- 하위 화면 닫기가 게임 재개로 이어지지 않게 한다. 직접 열린 질문/가이드는 자신이 요청한 차단만 해제한다.
- 협동 메뉴가 전체 게임 정지인지 로컬 입력 차단인지 계약으로 받는다. UI가 임의로 Time.timeScale을 바꾸지 않는다.
- HelpPrompt의 도움 여부와 ConfirmDialog의 실행 승인은 문구/기능을 구분한다. 진행 소실/환불 창의 기본 선택은 취소/아니요를 제안한다.
- 중복 열기·Submit 연타·늦게 도착한 이전 요청 결과·아래 UI/전투로 입력 전달을 막는다. 실행 요청은 처리 중 비활성, 성공/실패 후 갱신한다.
- 씬 종료/재시작에서 이벤트 구독·요청·선택·Tween·지속 FX를 정리한다.

## 6. 제작 단계와 담당 계약

현재 UI 목표는 전체 화면의 A 단계와 표시 상태 시안이다. 실제 선택·페이지 전환·버튼·저장·요청/응답 연결은 전체 화면 제작 완료 후 B/C 단계로 진행한다. 아래 계약은 후속 참고 목록이며 화면 제작 중 과제가 아니다. FX A~D도 전체 UI 화면 제작 완료 후 진행한다.

| 단계 | UI | FX | 완료 표시 |
| --- | --- | --- | --- |
| A | 배치·폰트·리소스·임시 데이터 | 형태·색·크기·재질·단발/지속 샘플 | 시안/샘플 |
| B | 선택·잠금·페이지·취소/복귀·오류 상태 | 재생·추적·갱신·종료·재사용 | 임시 데이터/수동 재생 상태 확인 |
| C | 실조회·요청/응답·저장·게임/서비스 이벤트 | 실제 공격/피격/상태/설치/웨이브 결과 연결 | 실제 기능 연동 |
| D | 전환·가독성·입력·회귀·성능 | 타이밍·사운드·정지·잔상·동시 발동 | 최종 검증 |

| 제공/합의 담당 | 필요한 데이터·결과 | UI가 보내는 요청 |
| --- | --- | --- |
| LJ | HP/에너지·무기/스킬·영웅/장비·재화·콤보·성장/마일스톤·저장 | 선택/장착/사용·구매/강화/환불·설정 적용/저장 |
| KMB | 모드/미션/난이도·목표/웨이브·설치 판정·적/보스·승패·지도/문/포털 | 미션 선택·시작·설치/회전/판매·재시작/복귀 |
| LJ/KMB + LHJ | 정지/커서/입력 정책·피격 위치/방향·적중/상태 시작/종료·결과 보상/통계 | 표시용 구독·사용자 행동 전달 |
| 신규 서비스 담당 결정 필요 | 세션/초대/연결·권한·친구/전체 순위·계정 상태·온라인 모드 | 검색/참가/초대/생성/이탈·순위 조회·계정 연결 |
| 설정/입력/사운드 담당 합의 | 현재/기본/지원 설정·바인딩·적용/복원·저장 결과 | 임시 값 적용/취소·키 재매핑 |

이는 필요한 계약 목록이며 이미 존재하는 API 이름이 아니다. 초기 조회 + 변경 이벤트 + 요청 응답 + 구독 해제를 준비한다. 새 서비스 담당은 기존 담당표에 없어 임의로 LJ/KMB의 확정 책임으로 배정하지 않는다.

세부 계약:

- 모드/미션/영웅/장비: ID·이름·이미지·설명·소유/잠금 이유·선택 가능, 미션 기록/평가·프리뷰.
- 세션: 필터·4열 표시 데이터·참가 가능, 멤버/호스트 권한·시작 가능·대기/연결 해제. 인원/핑은 내부 판정 데이터가 필요할 수 있지만 사진에 없는 열을 자동 추가하지 않는다.
- 인벤토리: 목록/적 정보·카테고리/정렬·장비 배치·잠긴 슬롯·단계별 장착 허용·변경 결과.
- 강화: 현재/다음 단계·레벨/고유/특별 선택지·가격·구매/선택/마일스톤/최대/잠금. 환불 금액/대상/실행 결과는 성장 담당이 계산하고 저장한다.
- 결과: 요약/통계가 동일한 확정 스냅샷을 사용. 점수·평가·보상·해금·다음 미션·신기록, 콤보 수·최대 콤보·최대 연속 처치·전체/무기/헤드샷/함정 처치·배치/판매 수·함정/전체 피해·남은 목표·완료 시간·보너스 조건. 헤드샷 등 새 측정 항목도 실제 기록 제공 계약으로 연결한다.
- 제공되지 않은 통계/순위 값은 “기록 없음/미지원” 등으로 구분하며 임의의 0을 실기록처럼 표시하지 않는다.

현재 공격과 UI 클릭은 일부 같은 입력을 사용한다. 암막/CanvasGroup의 Raycast 차단만으로 게임 공격·카메라·설치·키 탐색이 차단되는 것은 아니므로 입력 담당의 차단/복원 계약이 필요하다.

FX 계약은 발생 ID·위치/방향·대상·종류·강도·수명·재적용/해제·면역 결과를 포함한다. 공격 발동과 유효 적중을 구분하고 빗나간 공격에 적중 표현을 재생하지 않는다. 피해/상태 판정은 LJ/KMB, 표현은 LHJ다.

## 7. UI 화면 제작 우선 일정

총 기간은 **6주**이며 이미 진행한 1주차도 포함한다. 하루 약 8시간·주 7일을 기준으로 주 56시간, 전체 최대 336시간을 배분한다. 이전의 UI 제작 5주 뒤 연결/FX를 추가하는 일정은 이 총 기간에 맞지 않아 아래 목표안으로 대체한다. **UI 제작 5주 뒤 남은 1주에 모든 연결·전체 FX·검수를 끝낸다고 계획하지 않는다.**

전체 화면·페이지·표시 상태를 먼저 제작한다. **버튼 연결과 FX 제작은 모두 전체 UI 화면 제작 완료 뒤 시작**한다. UI는 1~2주차 완료를 목표로 하고, 이후 3~5주차의 시간을 연결과 FX에 나누어 쓴다. 화면 제작 중 FX 목록/계약 메모·샘플 제작·보완·미리보기·연동을 별도 과제로 넣지 않는다. 연결 규칙은 연결 단계가 시작될 때 다시 안내한다.

| 프로젝트 주차 | 시간 예산 | 작업 범위 | 주말 목표 |
| --- | --- | --- | --- |

합계는 **UI 제작 112시간 + 버튼/데이터 연결 64시간 + FX 제작/연동 104시간 + 통합 검수 40시간 + 수정 여유 16시간 = 336시간**이다. 이는 실측 소요시간이 아니라 가용시간 배분안이다. 기존 진행 시간도 예산에서 차감하며 새로 6주를 추가하는 뜻이 아니다. 한 사람이 같은 주 안에서 연결과 FX의 시간을 나누어 작업한다.

UI를 2주에 마감하는 목표와 5주차 FX 범위는 빠듯하다. 기존 프리팹·아트·리소스, 공통 카드/설정 행/가이드와 FX의 색·크기·속도 변형을 재사용한다. 모든 효과를 각각 새 고품질 아트로 제작한다고 가정하지 않는다. 스킬·보스 등 복합 표현은 4주차에 공통 틀을 만들고 5주차에 마감한다. 연결 예산에는 다른 담당의 네트워크/랭킹/계정 로직 신규 개발을 포함하지 않는다. 제공되지 않은 API는 대기로 기록하며 실제 기능 연결 완료로 표시하지 않는다.

매주 말 완료한 화면/상태·버튼/데이터 흐름·효과를 기준으로 남은 시간을 재산정한다. **2주차 말에 전체 UI 제작이 미완료라면 연결과 FX를 먼저 시작하지 않고, 남은 6주 예산 안에서 완료 가능성을 다시 계산한다.** 범위나 기한을 임의로 바꾸지 않는다. 별도 여유는 6주차 수정 16시간뿐이므로 현재 범위의 6주 완료를 보장하지 않는다.

UI 피드백 FX는 해당 버튼/요청 결과 연결 후, 전투 FX는 실제 발동/적중/상태 자료가 확보된 항목부터 연결한다.

화면 제작 완료 체크는 S01~S23, H01~H11, 각 가이드 단계와 책 페이지, 추가 동료/도감/탐험 미션·온라인 응답 표시에 적용한다. 자료가 없는 이름/이미지/기록은 임시 표시로 배치를 준비하고 교체할 항목을 기록한다. 사진 수와 프리팹 수를 완료율로 사용하지 않는다.

전체 UI 제작 완료 조건:

- 모든 제작 대상에 배치·문구·이미지 영역·필요한 버튼 외형이 있다.
- 선택·잠금·부족·소유·최대·대기·빈 목록·실패 등 필요한 상태를 수동으로 표시할 수 있다.
- 책/도움말/가이드의 모든 페이지와 단계가 배치되어 있다.
- FX를 쓰는 도움말 이미지/영상 영역은 기존 정적 이미지 또는 자리표시자로 배치하고 교체 대상을 기록했다. 최종 FX 영상 준비는 UI 화면 배치 완료의 선행 조건으로 두지 않는다.
- 정한 해상도에서 한글·잘림·겹침을 확인하고 프리팹·씬을 저장했다.
- 남은 UI 제작 항목이 없거나 사용자가 범위를 명시적으로 조정했다. 버튼 미연결 자체는 화면 제작 미완료로 세지 않는다.

연결 단계의 동작·취소·복귀·입력 규칙은 그때 다시 안내한다. **전체 UI 화면 제작 완료가 버튼 연결과 FX 착수의 공통 시작 조건**이다. 날짜가 3주차가 되었다는 이유만으로 먼저 시작하지 않는다. 이미 만든 FX 샘플은 보관하고 이후 재사용한다.

기존 ROADMAP의 6주 팀 기한은 유지한다. 이 문서는 LHJ 작업 시간 배분안이며 공유 ROADMAP을 수정하지 않는다. 완료 예상이 기한을 넘으면 남은 항목·필요 시간·외부 의존성을 즉시 기록해 기한 내 완료가 어려운 부분을 드러낸다. 네트워크/랭킹/계정 등 실제 기능 제공이 늦는 항목도 UI 외형 제작과 실제 연결을 구분한다.

- 암막으로 초기 제작, Blur는 렌더링/성능 확인 후. 책/검/캐릭터는 정적 아트와 3D Preview를 활용하고 입자로 모두 재제작하지 않는다.
- 메뉴의 선택색과 카드의 잠금/소유/처리 중 표시는 Tween 없이 먼저 완성.
- 전체 화면/부품 프리팹은 필요한 실제 공통 부분만 공유. 개별 버튼 프리팹에 주변 버튼 Navigation 참조를 저장하지 않는다.
- 미션 포털·대표 장비·적/영웅 이미지는 기존 정적 이미지나 3D 모델 캡처로 준비한다. 아직 없는 아트/FX 영상은 자리표시자로 배치한다. 공격/상태 도움말의 최종 FX 미리보기 제작·교체는 UI 제작 완료 후 진행하고 실제 표현과 설명을 맞춘다.

## 10. 단계별 완료 기준·자료·검증

현재 화면 제작과 후속 연결·FX 검증을 구분한다. 이 계획 갱신에서 Unity 실행/빌드, 씬/프리팹 또는 게임 코드 수정은 수행하지 않았다.

현재 UI 화면 제작 확인:

- 화면·페이지·가이드 단계·표시 상태가 제작 목록에 대응한다.
- 한글 폰트·제목·설명·이미지·버튼·슬롯·카드·스크롤 영역이 배치되어 있다.
- 일반/선택/잠금/부족/소유/최대/대기/빈 목록/실패 상태를 수동 표시로 확인한다.
- 1920×1080·1280×720, 여유가 있으면 2560×1440에서 긴 문구·큰 숫자·잘림·겹침을 점검한다.
- 화면 Root 숨김과 프리팹·씬 저장 상태를 확인한다.
- UI 연결 규칙표, 실제 On Click/Navigation/입력·게임 정지·구매/환불/저장 검증은 이 단계의 완료 조건에서 제외한다.

후속 연결 확인은 전체 UI 제작 완료 뒤 다시 안내한다. FX 샘플·실연동·정지/종료·동시 발동 검증도 전체 UI 제작 완료 후 7절의 후속 일정과 12절을 따른다.

필요 리소스: 한글 폰트·로고/배경·카드 프레임·선택/잠금/금지·키 Glyph·가이드 화살표·지도/범례·아이콘·장비/적/영웅/미션 이미지·책/검/포털. FX 단계에는 UI/전투 사운드·파티클 텍스처/URP 머티리얼·Trail/메시를 준비한다. 프로젝트 자료가 없으면 이미지 자리표시자로 배치를 준비하고 교체 대상을 기록한다.

후속 자료는 R68부터 추가해 [참고 목록](UI_REFERENCE_CATALOG.md)에 연결한다. 실제 완료는 TODO/DONE과 구분하며 이 문서는 LHJ UI/FX의 제작 범위와 순서 원본으로 유지한다.

### 11-3. 기존 PopupRoot와 암막 점검

1. Hierarchy의 PopupRoot를 선택한다. Rect Transform의 Anchors Min (0,0), Max (1,1), Pivot (0.5,0.5), Left/Right/Top/Bottom 모두 0을 확인한다. Rotation은 0, Scale은 (1,1,1)이다.
2. 기존 Canvas Group은 Alpha 1, Interactable 켜기, Blocks Raycasts 켜기, Ignore Parent Groups 끄기를 확인한다.
3. DimmedBackground를 선택한다. Rect Transform은 같은 전체 Stretch·네 오프셋 0이다.
4. Image Color는 검정, Alpha 약 0.55(0~255로 표시되면 140), Raycast Target 켜기다.
5. 현재 PopupRoot 아래에는 DimmedBackground와 ConfirmDialogRoot가 있고, DimmedBackground 아래에는 PauseMenuRoot·HelpPromptRoot가 있다. 이 부모 관계를 바꾸지 않는다. 한 팝업씩 켜서 글자가 암막보다 앞에 표시되는지 Game 뷰에서 확인한다.

Rect Transform 왼쪽의 작은 Anchor Presets 사각형에서 가로·세로 모두 Stretch인 칸을 선택해도 된다. 숫자가 헷갈리면 Anchors Min/Max를 직접 입력한다. 전체 Stretch에서는 Pos X/Y·Width/Height 대신 Left/Right/Top/Bottom이 표시되는 것이 정상이다.

오늘 암막은 화면을 어둡게 하는 표현이다. 참고 화면의 배경 Blur는 후속 폴리싱 항목이다. CanvasGroup과 암막의 Raycast는 실제 플레이어 공격·설치 입력이나 뒤 UI의 키보드 선택을 정지시키는 기능과 별도다.

### 11-4. 한글 TMP 폰트 준비

1. 한글을 지원하는 TTF/OTF를 준비한다. 팀 지정 폰트가 없으면 [Google Fonts의 Noto Sans KR](https://fonts.google.com/specimen/Noto+Sans+KR)을 시작용으로 사용할 수 있다. 다운로드한 압축 파일을 풀고 TTF/OTF 파일을 Assets/09. Fonts로 드래그한다.
2. Project에서 가져온 폰트 원본을 선택한 뒤 우클릭 → Create → TextMeshPro → Font Asset → SDF를 누른다.
3. 생성된 TMP Font Asset을 선택한다. Generation Settings에서 Source Font File이 한글 원본인지, Atlas Population Mode가 Dynamic인지 확인한다. Atlas는 기본 1024×1024로 시작하고 Multi Atlas Textures를 켠다. 원본 폰트도 프로젝트에 유지한다.
4. Project의 Assets/04. Prefabs/PauseMenuRoot.prefab을 더블클릭해 Prefab Mode를 연다. 각 버튼 아래 Label을 선택하고 TextMeshPro - Text (UI)의 Font Asset 슬롯에 생성한 SDF를 드래그한다. 5개 Label 모두 적용한다.
5. 돌아가기 / 다시 시도 / 옵션 / 도움말 / 나가기가 네모로 나오지 않는지 확인하고 Ctrl+S로 프리팹을 저장한다. Prefab Mode 상단 뒤로 가기로 View 씬에 돌아온다.
6. 공통 템플릿에도 반영하려면 Canvas_Popup.prefab을 Prefab Mode로 열어 MenuTextButton/Label의 Font Asset을 같은 SDF로 교체하고 저장한다. 이 템플릿을 View 씬에 새로 배치하지는 않는다.

Font Asset 슬롯에는 TTF/OTF 원본이 아닌 생성된 TMP Font Asset을 넣는다. 생성이 실패하면 원본 Font Import Settings의 Include Font Data와 Dynamic 설정을 확인한다. Dynamic으로 바꿔도 원본에 없는 한글 글리프가 추가되지는 않는다.

### 11-5. 기존 버튼으로 공통 기준 정리

PauseMenuRoot.prefab의 ResumeButton을 기준으로 아래 값을 점검한다. 해당 프리팹의 위치는 Vertical Layout Group이 제어하므로 버튼 Pos Y를 각각 0으로 리셋하지 않는다.

1. 버튼의 Width 480, Height 64, Scale (1,1,1)을 확인한다.
2. 버튼 Image 컴포넌트는 활성 상태, Color Alpha 0, Raycast Target 켜기다. 투명한 사각형이 클릭 영역이다.
3. 자식 Label의 Rect Transform은 전체 Stretch, Left/Right/Top/Bottom 0이다.
4. Label의 TMP 값은 Text 돌아가기, 한글 Font Asset, Font Size 48, Auto Size 끄기, Alignment 가로 Center/세로 Middle, Vertex Color 흰색/Alpha 1이다.
5. TMP 하단 Extra Settings를 펼쳐 Raycast Target을 끈다.
6. 부모 ResumeButton의 Button → Transition은 Color Tint, Target Graphic은 **ResumeButton 안의 Label**이다. Color Multiplier 1, Fade Duration 0.1, Interactable 켜기를 확인한다.
7. 현재 저장된 Navigation은 Explicit이며 위/아래 참조가 연결되어 있다. 그대로 유지한다. 오늘은 On Click()에 게임 로직을 추가하지 않는다.
8. 아래 상태 색상을 ResumeButton에 입력해 기준을 정리하고 Pause의 다른 4개 버튼에도 색상 필드만 적용한다. Button 컴포넌트 전체 복사/붙여넣기로 각 버튼의 Label/Navigation 참조를 덮어쓰지 않는다. 질문/확인 버튼은 아래 11-6의 연한 회색 Normal을 사용한다. 실제 탐색/최초 선택 확인은 전체 UI 화면 제작 후 연결 단계에서 진행한다. Canvas_Popup.prefab의 MenuTextButton에도 같은 스타일을 저장해 재사용할 수 있다.

색상은 스크린샷 분위기에 맞춘 임시 시작값이며 이후 조정한다. Button의 각 색상 Alpha는 모두 1이다.

| 상태 | 시작 색상 |

| Normal | #9B7C24 |
| Highlighted | #FFD84A |

### 11-6. Pause·질문·확인창과 문구 변형

아래 Rect Transform 수치는 기존 저장값과 화면 제작 시작 기준이다. 이미 맞는 값은 유지한다. 다른 배치로 화면 표시가 맞게 완료되었다면 같은 숫자로 강제 재배치하지 않는다.

**PauseMenuRoot — 기존 메뉴 5개**

1. PauseMenuRoot.prefab을 연다. Root 중앙 Anchor/Pivot (0.5,0.5), Pos (0,0), Width 480 / Height 400을 확인한다.
2. 기존 Vertical Layout Group은 Spacing 8, Child Alignment Middle Center, Padding 0이다. Control Child Size·Use Child Scale·Child Force Expand의 Width/Height는 꺼져 있다. 맞으면 유지한다.
3. 자식 순서와 문구가 돌아가기 → 다시 시도 → 옵션 → 도움말 → 나가기인지 확인한다. 버튼 각각 480×64, Label 크기 48과 11-5의 스타일을 적용한다. 버튼 위치는 Layout Group이 배치하므로 Pos Y를 개별 조절하지 않는다.
4. Ctrl+S로 프리팹을 저장한다. 세부 구조와 검사표는 13절을 부품별 참고로 사용한다.

**HelpPromptRoot — 질문창 1개에 문구 3종**

1. 기존 HelpPromptRoot.prefab을 연다. QuestionText·DescriptionText·AnswerRow·YesButton/Label·NoButton/Label을 재사용한다.
2. QuestionText와 DescriptionText의 TMP Alignment를 가로 Center / 세로 Middle로 바꾼다. Font Asset은 한글 SDF, Vertex Color는 흰색/Alpha 1, Auto Size 끄기, Text Wrapping Mode Normal, Raycast Target 끄기로 맞춘다.
3. 현재 Root 1600×440, QuestionText 1600×140 / Pos Y 120 / Font Size 52, DescriptionText 1400×100 / Pos Y -20 / Font Size 30을 시작값으로 확인한다. Root와 두 텍스트는 중앙 Anchor/Pivot을 사용한다.
4. AnswerRow는 440×72 / Pos Y -150이다. 기존 Horizontal Layout Group의 Child Alignment를 Middle Center로, Spacing 40, Padding 0, Control Child Size·Use Child Scale·Child Force Expand의 Width/Height와 Reverse Arrangement를 모두 끄기로 맞춘다.
5. 버튼 각각 200×72, Label Font Size 40·Center/Middle·흰색/Alpha 1을 적용한다. 기존 어두운 예/아니요 Label은 흰색으로 보완한다. 부모 Button의 Target Graphic은 각자 내부 Label 참조를 유지한다.
6. 질문/확인 버튼의 색상은 Normal #D9D9D9, Highlighted/Selected #FFD84A, Pressed #E6A02A, Disabled #777777을 시작값으로 준비한다. Alpha는 모두 1이다. 실제 입력 반응은 연결 단계 검증이다.
7. QuestionText에 기초 → 인벤토리 → 마법책 질문을 차례로 넣는다. 설명은 언제든지 일시 정지 메뉴에서 도움말 화면에 다시 방문할 수 있다는 참고 문구로 2줄 표시를 확인한다. 정확한 문구 표는 14-4를 참고한다.
8. 문구마다 잘림/겹침을 기록하고 기본 문구를 기초 질문으로 되돌린 뒤 저장한다. 문구별 프리팹이나 실제 선택/전환 함수를 만들지 않는다.

**ConfirmDialogRoot — 기존 확인창에 문구 3종**

1. 이미 있는 ConfirmDialogRoot.prefab을 연다. HelpPromptRoot를 새로 복제하지 않는다. TitleText·DescriptionText·AnswerRow·ConfirmButton/Label·CancelButton/Label을 재사용한다.
2. 한글 Font Asset을 모든 TMP에 적용한다. TitleText/DescriptionText는 Center/Middle, 흰색/Alpha 1, Auto Size 끄기, Text Wrapping Mode Normal, Raycast Target 끄기로 확인한다.
3. 현재 Root 1600×640, TitleText 1600×140 / Pos Y 200 / Font Size 64, DescriptionText 1400×220 / Pos Y -10 / Font Size 32, AnswerRow 440×72 / Pos Y -210을 시작값으로 확인한다. Root/제목/설명/Row의 Anchor와 Pivot은 중앙이다.
4. AnswerRow의 Middle Center·Spacing 40·Force Expand 끄기는 이미 저장되어 있다. 버튼 각각 200×72, Label Font Size 40과 질문창과 같은 버튼 스타일을 확인한다. 맞으면 유지한다.
5. 재시도(확인/취소) → 캠페인 복귀(확인/취소) → 전체 환불(예/아니요)의 제목/설명/버튼 문구를 같은 화면에 차례로 넣는다. 정확한 참고 문구는 15-5를 사용한다. 긴 환불 설명부터 4줄이 들어가는지 확인한다.
6. 문구는 참고용 표시 시안이다. 우리 게임의 재화 명칭과 실제 경고 정책은 후속 연결 단계에서 확정한다. 글자가 넘치면 설명 Height와 버튼 간격을 함께 조정한다.
7. 기본 문구를 재시도, 버튼을 확인/취소로 되돌리고 저장한다. 함수·새 Navigation·환불/재시작 로직은 연결하지 않는다.

## 13. 2일차 수동 작업 안내 — Pause 메뉴 외형 마감

목표는 **기존 Pause 메뉴 5개의 배치·폰트·색상·간격 마감 → 표시 확인 → 저장**이다. 1일차의 한글 TMP Font Asset과 공통 버튼 외형 기준을 사용한다. FX·버튼 탐색·후속 동작표는 2일차 과제에서 제외한다.

2026-10-10 저장 파일에서 PauseMenuRoot.prefab의 중앙 배치·자동 세로 배치·버튼 크기·자기 Label 참조·Explicit 탐색은 이미 맞게 저장되어 있다. 값이 맞으면 그대로 유지한다. 저장본의 폰트는 LiberationSans SDF, 상태 색은 기본 흰색/회색이므로 1일차에서 반영한 값과 함께 확인한다. 이 안내는 수동 작업 순서이며 씬·프리팹 직접 수정이나 실행 완료 기록이 아니다.

FX는 전체 UI 화면 제작 완료 후 첫 무기 자료와 발생 정보를 확인한 뒤 시작한다. 2일차에 공격 샘플을 만들거나 기존 샘플 보완을 요구하지 않는다.

### 13-1. 기존 기반을 켜고 확인

1. View 씬을 연다. Hierarchy에서 Canvas_Popup → PopupRoot를 펼치고 PopupRoot의 활성 체크를 켠다.
2. 현재 DimmedBackground와 PauseMenuRoot/버튼을 사용한다. EventSystem과 Canvas를 중복 생성하지 않는다.
3. PopupRoot CanvasGroup은 Alpha 1, Interactable/Blocks Raycasts 켜기, Ignore Parent Groups 끄기다. DimmedBackground는 첫 자식, 전체 Stretch, 검정 Alpha 0.55다.
4. Project의 Assets/04. Prefabs/PauseMenuRoot.prefab을 더블클릭해 Prefab Mode를 연다. 13-2~13-6의 메뉴 수정은 여기서 진행하고 Ctrl+S로 저장한다.
5. 1일차에 만든 한글 TMP Font Asset이 5개 Label에 연결되어 있는지 확인한다. 아직 준비하지 않았다면 11-4부터 진행한다.

View의 Canvas_Popup은 일반 씬 오브젝트이며 PauseMenuRoot가 프리팹 인스턴스다. 메뉴 스타일은 기존 PauseMenuRoot.prefab에서 수정한다. Canvas 전체를 Apply하거나 기존 Canvas_Popup.prefab으로 씬 구조를 교체하지 않는다.

### 13-2. 기존 PauseMenuRoot의 중앙 배치 확인

Prefab Mode에서 기존 PauseMenuRoot를 선택하고 아래 Rect Transform 값을 확인한다. 저장값이 이미 맞으면 변경하지 않는다.

| 항목 | 값 |
| --- | --- |
| Anchor Min | X 0.5 / Y 0.5 |
| Anchor Max | X 0.5 / Y 0.5 |
| Pivot | X 0.5 / Y 0.5 |
| Pos X / Y / Z | 모두 0 |
| Width / Height | 480 / 400 |
| Rotation | 모두 0 |
| Scale | 모두 1 |

### 13-3. 기존 자동 세로 배치 확인

### 13-5. 공통 버튼과 글자 설정

버튼 부모 Image는 활성 상태를 유지하고 Color Alpha 0, Raycast Target 켜기로 설정한다. 각 Label은 전체 Stretch, Left/Right/Top/Bottom 0, 한글 TMP Font Asset, Font Size 48, Auto Size 끄기, 가로 Center/세로 Middle, Vertex Color 흰색/Alpha 1이다.

| 상태 | 임시 시작 색상 — 모두 Alpha 1 |
| --- | --- |
| Normal | #9B7C24 |
| Highlighted | #FFD84A |
| Selected | #FFD84A |
| Pressed | #E6A02A |

## 15. 4일차 수동 작업 안내 — 공통 실행 확인창 화면 제작

참고는 [재시도 R45](UI_References/R45_RetryConfirm.png), [캠페인 복귀 R46](UI_References/R46_LeaveCampaignConfirm.png), [전체 환불 R63](UI_References/R63_RefundAllConfirm.png)이다. 세 화면 모두 중앙 제목·설명·가로 두 버튼을 사용하므로 공통 프리팹 하나에 문구를 교체한다.

현재 HelpPromptRoot.prefab과 ConfirmDialogRoot.prefab의 저장된 구성을 확인했다. 아래 복제/이름 변경은 확인창이 없을 때만 필요한 초기 안내이며 현재 과제에서는 기존 확인창을 열어 값과 문구를 보완한다. 이 문서 작성으로 씬/프리팹을 수정하거나 실행 확인한 것은 아니다. 배치 수치는 1920×1080 기준의 시작값이며 참고 화면의 실측값이 아니다.

### 15-1. Project 창에서 기존 프리팹 복제

1. Unity Project 창에서 Assets/04. Prefabs/HelpPromptRoot.prefab을 선택한다. Hierarchy 인스턴스 대신 Project의 프리팹 파일을 선택한다.
2. Ctrl+D로 복제하고 새 파일 이름을 ConfirmDialogRoot로 바꾼다. 기존 HelpPromptRoot는 유지한다. 이미 공통 확인창을 만들었다면 그 프리팹을 사용하고 다시 복제하지 않는다.
3. ConfirmDialogRoot.prefab을 더블클릭해 Prefab Mode로 연다. 상단 프리팹 이름이 ConfirmDialogRoot인지 확인한다.
4. 내부 Root의 이름도 ConfirmDialogRoot인지 확인하고 Root 활성 상태를 켠다.
5. 수정은 복제본에만 저장한다. 새 Canvas·EventSystem·암막을 추가하지 않는다.

### 15-2. 내부 이름과 구성 정리

1. QuestionText를 TitleText로 바꾼다.
2. YesButton을 ConfirmButton, NoButton을 CancelButton으로 바꾼다.
3. DescriptionText·AnswerRow·각 버튼의 Label은 그대로 사용한다.

```text
ConfirmDialogRoot
  TitleText
  DescriptionText
  AnswerRow
    ConfirmButton
      Label
    CancelButton
      Label
```

기존 자식이 모두 있으면 새로 추가하지 않는다. 아래 값은 이 복제본의 외형을 정리하는 기준이며 도움말 원본을 덮어쓰는 지시가 아니다.

### 15-3. 제목·긴 설명을 위한 영역 배치

Root·TitleText·DescriptionText·AnswerRow의 Anchor Min/Max와 Pivot은 모두 (0.5,0.5)로 둔다. Pos X/Z와 Rotation은 0, Scale은 (1,1,1)이다.

| 오브젝트 | Width / Height | Pos Y | Font Size |
| --- | --- | --- | --- |
| ConfirmDialogRoot | 1600 / 640 | 0 | — |
| TitleText | 1600 / 140 | 200 | 64 |
| DescriptionText | 1400 / 220 | -10 | 32 |
| AnswerRow | 440 / 72 | -210 | — |
| 버튼 각각 | 200 / 72 | Row에서 배치 | Label 40 |

1. TitleText와 DescriptionText에 1일차에 준비한 한글 TMP Font Asset을 적용한다.
2. 두 TMP의 가로 Alignment를 Center, 세로 Alignment를 Middle로 맞춘다. 기존 저장본의 왼쪽/위쪽 정렬이 복제되었을 수 있으므로 직접 확인한다.
3. Auto Size는 끄고 Text Wrapping Mode는 Normal, Vertex Color는 흰색/Alpha 1로 설정한다.
4. Extra Settings → Raycast Target은 두 텍스트 모두 끈다.
5. 15-5의 전체 환불 설명을 먼저 넣어 4줄이 들어가는지 확인한다. 실제 Enter로 줄바꿈한다.
6. 설명이 넘치면 Height와 버튼 Pos Y 간격을 함께 조정한다. 줄바꿈·가독성이 확보된 뒤 짧은 재시도 문구도 확인한다.

Root/제목/설명에 새 Image 배경을 추가하지 않는다. 기존 PopupRoot의 암막 위에 글자를 표시하며 Blur는 이후 폴리싱 항목이다.

### 15-4. 가로 버튼 외형 보완

1. AnswerRow의 기존 Horizontal Layout Group을 확인한다. 없을 때만 Add Component로 추가한다.
2. Padding 모두 0, Spacing 40, Child Alignment Middle Center로 설정한다.
3. Control Child Size·Use Child Scale·Child Force Expand의 Width/Height와 Reverse Arrangement를 모두 끈다. 기존 복제본의 Force Expand가 켜져 있다면 이 확인창에서 끈다.
4. Hierarchy 순서는 ConfirmButton → CancelButton이다. 버튼 Rect Transform Width 200, Height 72, Scale 1로 둔다. 버튼 위치는 Row가 배치하므로 Pos X를 따로 조정하지 않는다.
5. 각 버튼 Image의 Color Alpha를 0으로 설정해 글자만 보이게 한다. Image 컴포넌트와 Raycast Target은 켠다.
6. 각 Label은 전체 Stretch, 네 여백 0, 한글 Font Asset, Font Size 40, Auto Size 끄기, Center/Middle, Vertex Color 흰색/Alpha 1, Raycast Target 끄기로 설정한다. 어두운 Label 색상이 복제되었으면 흰색으로 바꾼다.
7. Button의 Transition은 Color Tint, Target Graphic은 각 버튼 내부 자기 Label로 둔다. 이는 표시용 참조이며 실행 함수 연결이 아니다.
8. Color Multiplier 1, Fade Duration 0.1, Interactable 켜기와 다음 외형 색상 값을 준비한다.

| 상태 | 색상 — 모두 Alpha 1 |
| --- | --- |
| Normal | #D9D9D9 |
| Highlighted / Selected | #FFD84A |
| Pressed | #E6A02A |
| Disabled | #777777 |

On Click()은 비워 둔다. 신규 Navigation 설정이나 실제 클릭/키 이동 검증을 오늘 과제로 추가하지 않는다.

### 15-5. 문구 3종을 같은 화면에서 확인

아래는 참고 이미지의 문구다. 세 프리팹을 만들지 않고 TitleText·DescriptionText·두 Label만 차례로 바꿔 표시한다. 상태별 표시 확인 결과를 기록하며 현재 게임의 실행/환불 규칙을 구현한 것으로 기록하지 않는다.

**재시도 — 버튼 확인 / 취소**

TitleText:

```text
시나리오 재시도
```

DescriptionText:

```text
정말로 재시도하시겠습니까? 현재
시나리오의 진행 상황이 사라집니다.
```

**캠페인 복귀 — 버튼 확인 / 취소**

TitleText:

```text
캠페인으로 나가기
```

DescriptionText:

```text
정말 캠페인으로 돌아가시겠습니까?
현재 시나리오의 진행 상황이
사라집니다.
```

**전체 환불 — 버튼 예 / 아니요**

TitleText:

```text
모든 업그레이드 환불!
```

DescriptionText:

```text
모든 장비 업그레이드가 초기화되고
해골이 모두 환불됩니다. 진행하면
취소할 수 없지만, 원하는 만큼 얼마든지
할 수 있습니다.
```

해골은 참고 게임의 재화 명칭이다. 지금은 참고 문구로 배치를 확인하고 프로젝트 적용 때 실제 강화 재화 명칭으로 교체한다. 실제 환불/초기화 정책은 연결 단계에서 다룬다. 스크램블 초기화 문구는 현재 참고 본문이 없으므로 오늘 추가 과제로 넣지 않는다.

3. PopupRoot·DimmedBackground·ConfirmDialogRoot를 켜고 PauseMenuRoot·HelpPromptRoot는 잠시 끈다.

## 16. 5일차 수동 작업 안내 — 가이드 공통 부품과 첫 배치

목표는 **GuideOverlayRoot 공통 부품 제작 → 기존 장비 바에 안내 배치 → 다음/계속 표시 상태 확인 → 프리팹·씬 저장**이다. 전체 튜토리얼을 오늘 모두 만드는 일정이 아니다. 버튼 연결과 자동 단계 진행은 전체 UI 화면 제작 후 진행하고, 연결 규칙도 그때 다시 안내한다. FX도 전체 UI 화면 제작 완료 후 작업한다.

참고는 [기초 안내 R41](UI_References/R41_BasicGuide.png), [인벤토리 첫 단계 R48](UI_References/R48_InventoryGuideStep1.png), [인벤토리 마지막 단계 R50](UI_References/R50_InventoryGuideStep3.png)이다. 노란 제목·노란 화살표·어두운 설명 상자·청록 테두리를 공통으로 만든다. R48은 다음 + 1/3, R50은 계속이며 마지막 진행 숫자는 보이지 않는다. 오늘은 공통 부품의 표시 상태만 확인한다.

2026-10-10 저장 파일에서 Canvas_HUD/PlayerStatus/Loadout 장비 바와 GuideOverlayRoot.prefab 및 View 씬 인스턴스를 확인했다. 기존 가이드를 보완한다. 현재 날짜별 계획의 2일차는 [17절](#17-2일차-수동-작업-안내--가이드카드슬롯키-안내)을 따른다. 이 16절은 가이드 부품별 참고이며 아래 수치는 1920×1080 기준의 시작값이다. 실제 렌더링이나 참고 이미지의 실측값으로 확정한 것은 아니다. 문서 작성으로 Unity 씬·프리팹을 제작하지 않았다.

### 16-1. View에서 가이드 Root 준비

1. View 씬을 열고 Canvas_HUD와 Canvas_Popup을 확인한다. 기존 Canvas_Popup의 Overlay·Reference Resolution 1920×1080·Match 0·Sort Order 100을 사용한다.
2. PopupRoot를 잠시 끈다. R41처럼 HUD가 보이는 안내 시안을 만들기 위해 기존 암막과 메뉴를 함께 숨긴다.
3. 이미 있는 GuideOverlayRoot를 사용한다. 외형 수정은 Project에서 GuideOverlayRoot.prefab을 더블클릭해 Prefab Mode에서 진행한다. 같은 Root를 새로 만들지 않는다.
4. GuideOverlayRoot가 PopupRoot의 **형제인 Canvas_Popup 직계 자식**인지 확인한다. 현재 마지막 자식은 확인용 UIPatsPreviewRoot이므로 기존 순서는 바꾸지 않는다.
5. 기존 Root에는 Image가 없다. Rect Transform과 현재 자식 구조를 유지한다.
6. Root Anchor Min (0,0), Max (1,1), Pivot (0.5,0.5), Left/Right/Top/Bottom 모두 0, Pos Z 0, Rotation 0, Scale (1,1,1)로 설정한다. 전체 Stretch에서는 Width/Height 대신 네 여백을 설정한다.
7. 새 Canvas·EventSystem·암막을 만들지 않는다. 오늘 가이드 Root에 Layout Group·단계 진행 스크립트를 추가하지 않는다.

최종 구성:

    Canvas_Popup
      PopupRoot                         ← 시안 확인 중 끄기
        기존 암막·Pause·질문·확인창
      GuideOverlayRoot
        Highlight
          Top / Bottom / Left / Right
        Arrow
          Shaft / LeftHead / RightHead
        Callout
          TitleText
          BodyPanel
            Top / Bottom / Left / Right
            BodyText
        NextContinueButton
          Label
        ProgressText

Highlight·Arrow·Callout·다음 버튼·진행 숫자가 이미 있으므로 재사용한다. 실제 이름의 Top (1)·Bottom (1) 등도 이름 차이만으로 변경하지 않는다. 아래 새 생성 설명은 향후 누락 부품이 있을 때만 참고한다. BodyPanel과 테두리·화살표 막대에는 Image를 유지한다. 텍스트는 UI → Text - TextMeshPro, 버튼은 UI → Button - TextMeshPro를 사용할 수 있다.

### 16-2. 첫 안내 대상과 주요 배치

첫 대상은 기존 Canvas_HUD → PlayerStatus → Loadout의 하단 장비 바다. 장비 아이콘과 비용을 함께 감싸는 테두리를 만들고 그 위에 설명을 둔다.

| 오브젝트 | Anchor Min = Max | Pivot | Pos X / Y | Width / Height |
| --- | --- | --- | --- | --- |
| Highlight | (0.5,0) | (0.5,0.5) | -100 / 125 | 730 / 180 |
| Arrow | (0.5,0) | (0.5,0.5) | -100 / 260 | 100 / 90 |
| Callout | (0.5,0) | (0.5,0.5) | -100 / 390 | 660 / 240 |
| NextContinueButton | (1,0) | (1,0.5) | -80 / 100 | 240 / 72 |
| ProgressText | (1,0) | (1,0) | -80 / 20 | 240 / 36 |

1. 각 부모/부품의 Pos Z와 Rotation은 0, Scale은 (1,1,1)로 둔다.
2. 저장된 HUD에서 장비 아이콘·비용을 포함한 영역은 기준 화면의 대략 X 510~1210, 아래에서 Y 50~200이다. 위 Highlight는 여유를 둔 시작값이다.
3. Game 뷰에서 현재 장비 바가 다르게 보이면 **HUD를 이동하지 않고** Highlight의 위치/크기와 Arrow·Callout 위치를 조정한다.
4. 장비/비용 일부가 편집 화면에서 비어 있다면 기존 표시 가능한 아이콘을 기준으로 먼저 배치하고, 빈 항목은 표시 확인 메모로 남긴다. 이를 위해 게임 데이터 연결을 시작하지 않는다.

Anchor Min/Max는 Rect Transform의 Anchors를 펼쳐 숫자로 입력할 수 있다. 앵커와 Pivot을 먼저 정하고 위치·크기를 입력한다.

### 16-3. Highlight — 속이 빈 청록 테두리

Highlight 아래 이미 있는 테두리 Image 4개를 선택한다. 각 Image의 Source Image는 None, Image Type은 Simple, Color는 #64D8FF / Alpha 1, Raycast Target은 끈다. 기존 이름을 유지하고 가운데를 채우는 큰 Image는 두지 않는다.

| 테두리 | Anchor Min / Max | Pivot | 나머지 Rect Transform 값 |
| --- | --- | --- | --- |
| Top | (0,1) / (1,1) | (0.5,1) | Left 0, Right 0, Pos Y 0, Height 4 |
| Bottom | (0,0) / (1,0) | (0.5,0) | Left 0, Right 0, Pos Y 0, Height 4 |
| Left | (0,0) / (0,1) | (0,0.5) | Pos X 0, Width 4, Top 0, Bottom 0 |
| Right | (1,0) / (1,1) | (1,0.5) | Pos X 0, Width 4, Top 0, Bottom 0 |

모든 테두리의 Rotation은 0, Scale은 1이다. 두께가 너무 강하면 3으로 조정하되 네 변을 같은 값으로 둔다. 발광·점멸·움직임 없이 정적인 테두리 외형을 완성한다.

### 16-4. Arrow — 이미지 없이 아래 화살표 제작

Arrow 아래 이미 있는 Shaft·LeftHead·RightHead를 사용한다. Anchor Min/Max와 Pivot을 모두 (0.5,0.5)로 둔다. 2026-10-10 재확인한 저장 파일에서는 머리 둘의 Pos Z 0, Rotation Z -45/+45가 이미 맞다. 아래 표는 확인 기준이며 맞는 값을 다시 수정할 필요는 없다.

| Image | Pos X / Y | Width / Height | Rotation Z |
| --- | --- | --- | --- |
| Shaft | 0 / 4 | 8 / 68 | 0 |
| LeftHead | -13 / -17 | 38 / 8 | -45 |
| RightHead | 13 / -17 | 38 / 8 | 45 |

1. 세 Image의 Source Image None, Image Type Simple, Color #FFD84A / Alpha 1, Raycast Target 끄기, Scale 1로 설정한다.
2. Arrow 부모는 Rotation 0으로 두면 아래 방향을 가리킨다.
3. 화살표 끝이 Highlight 위쪽을 가리키고 장비 아이콘/비용을 덮지 않는지 확인한다.
4. 다른 방향의 안내는 나중에 Arrow 부모의 Rotation Z를 바꿔 재사용한다. 오늘 두 번째 방향까지 만들 필요는 없다.

### 16-5. Callout — 노란 제목과 어두운 설명 상자

Callout 아래 기존 TitleText와 BodyPanel을 선택한다. 두 자식의 Anchor Min/Max와 Pivot은 (0.5,0.5)로 확인/보완한다. 2026-10-10 재확인한 저장 파일에서 BodyPanel은 이미 중앙 앵커/Pivot, Pos (0,-20), 크기 660×140이다. 맞는 Rect Transform은 유지하고 아래 색상·폰트 설정을 보완한다.

| 오브젝트 | Pos X / Y | Width / Height | 표시 |
| --- | --- | --- | --- |
| TitleText | 0 / 90 | 660 / 60 | Font Size 48, #FFD84A |
| BodyPanel | 0 / -20 | 660 / 140 | Image #071B24, Alpha 약 0.92 |

1. TitleText에 준비한 한글 TMP Font Asset을 적용하고 Center/Middle, Auto Size 끄기, Text Wrapping Mode Normal, Raycast Target 끄기로 설정한다.
2. TitleText 문구는 장비창 막대로 시작한다.
3. BodyPanel의 Source Image는 None, Image Type은 Simple, Raycast Target은 끈다.
4. BodyPanel 아래 이미 있는 테두리 4개를 사용한다. 16-3 표의 앵커·Pivot·여백·두께를 확인해 작은 상자의 사방에 맞추며 색·두께도 보완한다. 같은 테두리를 중복 생성하지 않는다.
5. BodyPanel 아래 기존 BodyText를 선택한다. 전체 Stretch, Left/Right 24, Top/Bottom 18, Pivot 중앙, Rotation 0, Scale 1로 설정한다.
6. BodyText는 한글 Font Asset, Font Size 30, 흰색/Alpha 1, Center/Middle, Auto Size 끄기, Wrapping Normal, Raycast Target 끄기로 맞춘다.
7. 다음 문구를 실제 Enter로 두 줄로 넣는다. 이는 오늘 배치용 시안이다.

    무기와 설치물을 확인하고
    사용할 장비를 선택하세요.

설명이 길어져 넘치면 BodyPanel Height와 Callout 주변 간격을 먼저 조정한다. 제목·설명 상자·화살표 사이가 겹치지 않게 확인한다. 참고의 빛 번짐 효과는 오늘 제작 범위에 넣지 않는다.

5. Artwork는 준비된 UI Sprite를 넣고 Preserve Aspect를 켠다. 없으면 단색 Image와 `이미지 영역` 문구로 배치만 준비한다. 오늘 새 아트·3D Preview Tool 제작을 시작하지 않는다.
6. 이름/설명/잠금 이유는 한글 Font Asset, 흰색·Alpha 1, Center/Middle, Auto Size 끄기, Wrapping Normal, Raycast Target 끄기로 만든다. 길어진 이름과 설명 2~3줄을 시험한다. 설명 영역을 늘리면 비용 영역과의 간격도 같이 조정한다.
7. CostRow는 왼쪽에 아이콘 28×28과 가격 영역, 오른쪽에 `비용 부족` 문구 영역을 나눈다. 왼쪽 중앙 Anchor/Pivot (0,0.5)을 기준으로 아이콘 Pos X 0, 가격 Pos X 32/Width 124, 부족 문구 Pos X 160/Width 168로 시작하면 간격 4씩·총 Width 328에 맞는다. 아이콘이 없으면 재화 아이콘 공간만 마련하고 비워 둔다. 긴 가격 `999,999`로 겹침을 확인한다.
8. SelectedFrame은 전체 Stretch·네 여백 0, 기본 Image 없는 부모다. 가이드의 얇은 테두리 4개와 같은 방식으로 #64D8FF·두께 4의 가장자리를 만든다. 가운데를 채우는 큰 Image로 카드를 가리지 않는다.
9. LockedGroup은 Artwork 아래 전체 Stretch로 만든다. Dim은 검정 Alpha 0.55, LockIcon 또는 `잠금` TMP는 중앙에 배치한다. LockReasonText는 DescriptionText와 같은 영역을 쓰되 둘을 동시에 켜지 않는다. 상태 표를 따른다.

| 시안 | SelectedFrame | LockedGroup | Description / LockReason | 가격·부족 문구 |
| --- | --- | --- | --- | --- |
| 일반 | 끄기 | 끄기 | 설명 켜기 / 이유 끄기 | CostRow 켜기, 가격 기본색, 부족 끄기 |
| 선택 | 켜기 | 끄기 | 설명 켜기 / 이유 끄기 | CostRow 켜기, 가격 기본색, 부족 끄기 |
| 잠금 | 끄기 | 켜기 | 설명 끄기 / 이유 켜기 | CostRow 숨김 시안 |
| 비용 부족 | 끄기 | 끄기 | 설명 켜기 / 이유 끄기 | CostRow 켜기, 가격 #FF6B6B, `비용 부족` 켜기 |

이 표는 외형 시안의 켜기/끄기 조합이다. 실제 선택·잠금·가격 판정이나 입력 허용 규칙을 확정한 것이 아니다. 카드 상태는 Inspector의 활성 체크와 TMP 색상으로 직접 바꿔 확인한다.

10. 일반 시안으로 복원하고 현재 저장된 SelectionCardVertical.prefab에 해당 카드 변경을 저장한다. 같은 이름의 새 프리팹이나 상태별 프리팹4개를 만들지 않는다. 확인용 씬 인스턴스를4개 배치해 상태를 비교할 수 있다.
11. 세로 카드와 같은 구성의 가로 카드 `SelectionCardWide`도 준비한다. Project에서 오늘 새로 저장한 세로 카드 프리팹을 선택해 Ctrl+D로 복사한다. 생성된 복사본만 SelectionCardWide로 이름을 정하고 Prefab Mode에서 크기를 보완한다. 원본 세로 카드나 기존 프리팹의 이름을 변경하거나 덮어쓰지 않는다.
12. 가로 카드 시작값은 Root 520×320, Artwork 488×168·상단 Y -16, NameText 488×40·상단 Y -196·글자30, Description/LockReason 488×40·상단 Y -240·글자22, CostRow 488×28·하단 Y 8·글자22다. 이 크기는 이름·설명 각각 한 줄 기준이다. 설명/잠금 이유가 두 줄이면 Root Height 360, Description/LockReason Height 64를 함께 적용한다. 나머지 위치는 유지하며 세부 입력은 19절을 따른다. 비용이 없는 모드/영웅 카드 시안에서는 CostRow를 숨긴다. 세로/가로 확인 그룹은 번갈아 켜고, 가로 카드 4개는 2×2로 배치해 화면 폭을 넘지 않게 한다.

Root 기준 상단은 Anchor Min/Max와 Pivot (0.5,1), 하단은 (0.5,0)이다. 선택 테두리·잠금 이미지·본문 그림/텍스트의 Raycast Target은 끈다. 기존 Button이 있으면 보존하고 실제 클릭 처리는 전체 UI 제작 후 연결한다. 오늘 새 상태 관리 스크립트·자동 Layout·Content Size Fitter는 필요하지 않다.

### 17-3. 장비 슬롯 공통 부품 — 1시간

기존 Canvas_HUD의 Loadout에는 무기 슬롯과 설치 슬롯 5개가 있다. 설치 슬롯은 Root Image + Installation Image + InstallationFee TMP 구조다. 현재 Root 100×100, 아이콘 사방 여백 6, 비용 200×50·글자36·New Text로 저장되어 있다. 오늘 원본 이름/참조/슬롯 수를 변경하지 않고 이 구조를 참고해 작업용 부품을 준비한다. 기존 구조를 자유롭게 복사할 수 있으면 복제본을 쓰고, 프리팹 제약이 있으면 같은 최소 자식 구조만 확인용 Root 아래에 만든다. 이를 위해 Canvas_HUD 전체를 Unpack/교체하지 않는다.

```text
EquipmentSlot
  SlotBackground
    Icon
    KeyText
    SelectedFrame
    LockedGroup
    UnavailableText
  CostText
```

1. 확인용 Root 아래 작업용 EquipmentSlot을 만든다. 새 작업용 Root는 100×150, SlotBackground는 상단 중앙 100×100을 시작값으로 둔다. 원본 HUD의 크기를 강제로 바꾸는 지시가 아니다.
2. Icon은 SlotBackground 안의 전체 Stretch·사방 6 여백, Preserve Aspect 켜기로 만든다. 기존 아이콘이 있으면 재사용하고 없으면 단색 자리표시자를 쓴다.
3. CostText는 Root 하단 중앙·100×34·Font Size 22·한글 Font Asset·Center/Middle·흰색으로 시작한다. `300`, `9,999`, `999,999`를 차례로 넣어 본다. 가격 영역이 겹치면 표시 영역/샘플 간격을 먼저 조정한다.
4. KeyText는 SlotBackground 왼쪽 위의 28×24·글자20, 샘플 `1`로 둔다. 배경과 겹쳐 읽기 어려우면 작은 어두운 키 배경을 둔다. 실제 키 배정은 나중에 정한다.
5. SelectedFrame은 슬롯 가장자리 4개의 얇은 Image로 만든다. LockedGroup은 어두운 덮개와 중앙 `잠금` 표시, UnavailableText는 슬롯 하단의 `비용 부족` 작은 글자로 만든다. 그림/문구는 Raycast Target 끄기다.
6. 일반·선택·잠금·비용 부족을 각각 수동 표시한다. 비용 부족은 잠금과 구분해 가격을 빨간색으로 표시하고 부족 문구를 켠다. 실제 구매 가능 여부는 판정하지 않는다.
7. 일반 시안으로 복원해 새 슬롯 부품만 저장한다. 확인용 인스턴스 3개를 간격 24 정도로 놓고 가격/키가 겹치는지 확인한다. 3개 샘플은 최종 슬롯 수가 아니다. 기존 HUD 교체/데이터 연결은 오늘 진행하지 않는다.

### 17-4. 키 안내 공통 부품 — 1시간

1. 확인용 Root 아래 `KeyHint`를 만든다. UI Panel로 만들었다면 Root의 기본 Image를 제거하고 크기를 420×88로 시작한다.
2. 아래 자식 구조를 만든다.

```text
KeyHint
  KeyBox
    KeyText
  ActionText
```

3. KeyBox는 Anchor Min/Max/Pivot (0,0.5), Pos X 10/Y 0, 64×64로 둔다. 어두운 배경 #071B24·Alpha 0.92와 얇은 밝은 테두리다. KeyText는 Stretch·여백 4, Font Size 28, 한글 Font Asset, 흰색, Center/Middle이다.
4. ActionText도 Anchor Min/Max/Pivot (0,0.5), Pos X 90/Y 0, 크기 320×88로 시작한다. KeyBox와 16의 간격이 생긴다. Font Size 28, Left/Middle, Wrapping Normal, Auto Size 끄기로 만든다. Root/부품 Scale은 1이다. 그림/텍스트 Raycast Target은 끈다.
5. `B / 방어 선택`, `G / 웨이브 시작`, `E / 함정 판매`를 표시 샘플로 넣는다. 참고 이미지의 임시 키이며 프로젝트 입력을 확정하지 않는다.
6. `Shift`처럼 긴 키 이름과 두 줄 행동 설명도 넣는다. 키 글자가 넘치면 KeyBox Width를 96, ActionText Pos X를 122, Root Width를 452로 늘려 간격 16과 설명 Width 320을 유지한다. 최소 글자 크기로 줄여 맞추지 않는다.
7. 기본 샘플로 복원해 KeyHint만 프리팹으로 저장한다. 실제 입력 감지/키 바인딩/컨트롤러 자동 Glyph 교체는 연결 단계에서 진행한다.

8. `부품/상태 · 1920 확인 · 1280 확인 · 남은 수정`을 기록한다. 준비하지 못한 아트는 교체 대상으로 기록하고 실제 기능 연결 완료로 처리하지 않는다.

## 18. 현재 저장 파일 기준 보충 — 세로 카드 배치

### 18-2. 먼저 일반 카드만 표시하기

1. View 씬에서 위의 기존 SelectionCardVertical을 펼친다. 카드 작업 중 PopupRoot·GuideOverlayRoot는 OFF, UIPatsPreviewRoot·SelectionCardVertical은 ON으로 둔다.
2. SelectedFrame·LockedGroup·LockReasonText·UnaffordableText를 각각 선택해 **Inspector 맨 위 오브젝트 이름 옆의 활성 체크**를 끈다. Image/TMP 컴포넌트의 체크를 끄는 작업과 구분한다. 오브젝트는 삭제하지 않는다.
3. Artwork·NameText·DescriptionText·CostRow·CostText는 ON으로 둔다. CostIcon에 사용할 아이콘이 없으면 CostIcon만 OFF로 둘 수 있다.
4. 비활성 오브젝트도 Hierarchy에서 선택해 설정을 수정할 수 있다. 배치가 끝난 뒤 상태 검수 때 다시 켠다.

### 18-3. Rect Transform과 Image를 구분하기

Rect Transform은 UI 영역의 위치·크기를 정한다. 빈 UI 오브젝트는 크기를 입력해도 스스로 배경이나 그림을 표시하지 않는다. 배경/그림에는 Image, 글자에는 TextMeshProUGUI가 필요하다. 부품을 묶는 부모는 Rect Transform만 있어도 된다.

| 기존 오브젝트 | 컴포넌트 작업 | Image 설정 |
| --- | --- | --- |
| SelectionCardVertical | Add Component에서 Image 검색·추가 | Source Image None, #32204F·Alpha 약 0.9, Raycast Target OFF |
| Artwork | Image 추가 | 임시 색 #654993·Alpha 1 또는 준비된 UI Sprite, Raycast OFF |
| Dim | Image 추가 | Source Image None, 검정·Alpha 약 0.55, Raycast OFF |
| SelectedFrame | **부모의 Image 컴포넌트만 제거** | 자식 Top/Bottom/Left/Right Image는 유지 |
| UIPatsPreviewRoot·LockedGroup·CostRow | Image 추가하지 않음 | 배치/묶음용 부모 |

Image 추가 시 필요한 CanvasRenderer는 함께 추가된다. SelectedFrame에서는 Image 컴포넌트 오른쪽 메뉴(⋮/톱니) → Remove Component를 사용한다. Rect Transform·GameObject·자식을 삭제하지 않는다. 남은 CanvasRenderer는 이 작업에 문제가 되지 않는다.

Source Image를 None으로 비우면 Image Type 필드가 숨겨질 수 있다. 보이는 경우 Simple을 사용하며, 없는 필드를 찾기 위해 컴포넌트를 재생성하지 않는다. Artwork에 Sprite를 넣을 때 Preserve Aspect를 켠다. 원본 PNG가 Project에서 Default Texture라 Source Image에 안 들어가면, UI용 이미지인지 확인한 후 그 파일의 Texture Type을 Sprite (2D and UI)로 준비한다. 여러 곳에서 쓰는 기존 텍스처 설정을 일괄 변경하지 않는다.

Color Picker의 Hex에 Alpha 포함 8자리 값을 입력하면 카드 배경 `32204FE6`, 임시 그림 `654993FF`, 암막 `0000008C`, 테두리 `64D8FFFF`를 쓸 수 있다. RGB 6자리만 입력할 경우 Alpha를 별도로 확인한다.

### 18-4. 앵커·Pivot를 먼저, 위치·크기를 나중에

1. Hierarchy에서 수정할 오브젝트를 선택한다.
2. Inspector의 Rect Transform에서 **Anchors 항목을 펼쳐 Min X/Y와 Max X/Y를 확인**한다.
3. Anchor Min/Max를 먼저 입력하고 Pivot X/Y를 입력한다. 그 다음 Pos X/Y/Z, Width/Height 또는 여백을 입력한다. 앵커/Pivot 변경 뒤 위치값이 다시 계산될 수 있으므로 이 순서를 지킨다.
4. 아래 표의 `(X,Y)`는 각각 두 입력칸이다. 예를 들어 `(0.5,1)`이면 X 0.5, Y 1이다.
5. 위쪽 중앙은 Anchor Min/Max `(0.5,1)`, Pivot `(0.5,1)`이다. 이때 Pos Y -16은 **직접 부모의 위쪽에서 16만큼 아래**다. 화면 전체의 위쪽 기준이 아니다.
6. 아래쪽 중앙은 Anchor Min/Max `(0.5,0)`, Pivot `(0.5,0)`이다. Pos Y 16은 부모 아래쪽에서 16만큼 위다.
7. 전체 Stretch는 Anchor Min `(0,0)`, Max `(1,1)`, Pivot `(0.5,0.5)`다. 이때 Width/Height 대신 Left/Right/Top/Bottom이 보이며 네 값을 0으로 입력한다. 이는 오류가 아니라 부모 크기를 따라가는 방식이다.

선택 카드 부품의 Rotation X/Y/Z는 0, Scale X/Y/Z는 1, Pos Z는 0으로 둔다. 이 지시는 카드 부품에 대한 것이며 Overlay Canvas 루트의 저장 Scale만 보고 표시 실패를 단정하거나 값을 강제로 바꾸지 않는다.

| 오브젝트 | Anchor Min = Max | Pivot | Pos X / Y | Width / Height |
| --- | --- | --- | --- | --- |
| SelectionCardVertical | (0.5,0.5) | (0.5,0.5) | 0 / 0 | 360 / 520 — 현재 맞음 |
| Artwork | (0.5,1) | (0.5,1) | 0 / -16 | 328 / 300 |
| NameText | (0.5,1) | (0.5,1) | 0 / -326 | 328 / 44 |
| DescriptionText | (0.5,1) | (0.5,1) | 0 / -374 | 328 / 72 |
| LockReasonText | (0.5,1) | (0.5,1) | 0 / -374 | 328 / 72 |
| CostRow | (0.5,0) | (0.5,0) | 0 / 16 | 328 / 36 |

NameText 입력 예: Min X 0.5/Y 1 → Max X 0.5/Y 1 → Pivot X 0.5/Y 1 → Pos X 0/Y -326/Z 0 → Width 328/Height 44. Artwork와 NameText는 형제이므로 NameText 위치는 Artwork 아래쪽이 아닌 카드 위쪽에서 계산한다.

이 배치에서 그림은 위에서 16~316, 이름은 326~370, 설명은 374~446, 가격은 468~504 영역을 쓴다. 그림/이름 간격 10, 이름/설명 간격 4, 설명/가격 간격 22가 생긴다. 설명이 넘치면 Auto Size로 먼저 축소하기보다 내용/영역 높이와 가격 간격을 함께 조정한다.

### 18-5. 가격 줄의 자식 배치와 TMP 설정

CostRow 자식 3개의 Anchor Min/Max와 Pivot를 모두 `(0,0.5)`로 입력한 뒤 아래 값을 넣는다. Pos Y/Z는 0이다.

| 오브젝트 | Pos X | Width / Height | 정렬·표시 |
| --- | --- | --- | --- |
| CostIcon | 0 | 28 / 28 | 준비된 재화 Sprite, Raycast OFF. 없으면 OFF |
| CostText | 32 | 124 / 36 | TMP 24, Left/Middle, `300` |
| UnaffordableText | 160 | 168 / 36 | TMP 24, Left/Middle, `비용 부족`, #FF6B6B, 일반 상태 OFF |

아이콘 28 + 간격 4 + 가격 124 + 간격 4 + 부족 문구 168 = 328이다. 현재 CostIcon은 100×100이므로 28×28로 바꿔야 한다. 아이콘이 없어 OFF인 경우에도 가격 Pos X 32는 유지할 수 있다. 나중에 Sprite를 준비했다면 CostIcon의 GameObject 활성 체크도 다시 켠다. Sprite 지정만으로 자동 활성화되지 않는다.

TMP는 Inspector의 TextMeshPro - Text (UI) 컴포넌트에서 설정한다. Font Asset 칸에는 한글을 지원하는 **TMP Font Asset**을 넣는다. TTF/OTF 원본 파일을 직접 넣는 칸이 아니다. 현재 6개 모두 LiberationSans SDF를 참조하므로 1일차에 준비한 Font Asset을 연결한다. 아직 준비하지 않았다면 11-4의 폰트 준비부터 마친다.

| TMP 오브젝트 | Text Input 시안 | Font Size | 가로 / 세로 정렬 |
| --- | --- | --- | --- |
| NameText | 샘플 카드 | 32 | Center / Middle |
| DescriptionText | 카드에 표시할 설명입니다. + Enter + 두 줄로 배치를 확인합니다. | 24 | Center / Middle |
| LockReasonText | [임시] 잠금 조건 안내 | 24 — 현재 36에서 변경 | Center / Middle |
| LockText | 잠금 | 36 | Center / Middle |
| CostText | 300 | 24 | Left / Middle |
| UnaffordableText | 비용 부족 | 24 | Left / Middle |

모든 TMP는 Auto Size OFF, Raycast Target OFF, Text Wrapping Mode Normal을 확인한다. 기본 글자 색은 흰색/Alpha 1이며 UnaffordableText는 빨간색이다. Inspector Alignment의 가로 정렬과 세로 정렬은 각각 확인한다. 두 줄 설명은 Text Input에서 실제 Enter를 사용한다. 문구는 배치 확인용이며 해금/가격 조건을 확정하지 않는다.

### 18-6. 잠금 영역을 그림에 맞추기

1. Artwork 아래 LockedGroup을 선택한다. Anchor Min `(0,0)`, Max `(1,1)`, Pivot `(0.5,0.5)`, Left/Right/Top/Bottom 0으로 입력한다.
2. 그 아래 Dim에도 같은 전체 Stretch·네 여백 0을 적용한다. Image는 검정 Alpha 약 0.55, Raycast OFF다. Dim이 카드 전체가 아닌 **그림 영역**만 덮도록 현재 부모 관계를 유지한다.
3. LockText는 중앙 Anchor Min/Max/Pivot `(0.5,0.5)`, Pos X/Y/Z 0, Width 200/Height 50, TMP `잠금`·Font36·Center/Middle로 둔다.
4. LockReasonText는 18-4에서 DescriptionText와 같은 영역으로 맞췄다. 잠금 표시 때만 이유를 켜고 DescriptionText는 끈다.
5. 일반 카드로 돌아갈 때 LockedGroup·LockReasonText를 끄고 DescriptionText·CostRow를 다시 켠다. 부모 LockedGroup만 끄면 Dim·LockText도 함께 숨는다.

### 18-7. 선택 테두리 4개를 가장자리에 놓기

SelectedFrame의 부모 Image만 제거한 뒤 전체 Stretch·네 여백 0으로 맞춘다. 현재 자식 4개의 중앙 100×100 값을 아래처럼 바꾼다. 모든 테두리는 Image Source None, Color #64D8FF·Alpha 1, Raycast OFF, Rotation0/Scale1/Pos Z0이다.

| 자식 | Anchor Min | Anchor Max | Pivot | Inspector에서 입력할 나머지 값 |
| --- | --- | --- | --- | --- |
| Top | (0,1) | (1,1) | (0.5,1) | Left 0, Right 0, Pos Y 0, Height 4 |
| Bottom | (0,0) | (1,0) | (0.5,0) | Left 0, Right 0, Pos Y 0, Height 4 |
| Left | (0,0) | (0,1) | (0,0.5) | Pos X 0, Width 4, Top 0, Bottom 0 |
| Right | (1,0) | (1,1) | (1,0.5) | Pos X 0, Width 4, Top 0, Bottom 0 |

Top/Bottom은 가로 Stretch여서 Width 대신 Left/Right가 보인다. Left/Right는 세로 Stretch여서 Height 대신 Top/Bottom이 보인다. 현재 SelectedFrame은 마지막 자식이므로 기존 계층 순서를 유지하면 테두리를 다른 카드 내용 위에 표시할 수 있다. 발광·점멸은 이후 FX 작업이다.

### 18-8. 상태를 하나씩 표시하고 일반 상태로 저장하기

현재 모든 자식이 ON이므로 먼저 아래 조합을 적용한다. 체크는 GameObject 활성 체크이며 On Click이나 상태 변경 코드를 추가하지 않는다.

| 표시 시안 | SelectedFrame | LockedGroup | DescriptionText | LockReasonText | CostRow | UnaffordableText | CostText 색 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 일반 | OFF | OFF | ON | OFF | ON | OFF | 흰색 |
| 선택 | ON | OFF | ON | OFF | ON | OFF | 흰색 |
| 잠금 | OFF | ON | OFF | ON | OFF | OFF | 흰색 |
| 비용 부족 | OFF | OFF | ON | OFF | ON | ON | #FF6B6B |

이 조합은 외형 검수용이다. 실제 게임의 잠금·선택 가능·비용 부족 판정 규칙은 연결 단계에서 다시 정한다. 잠금 상태 확인 후 CostRow를 다시 켜는 것을 빠뜨리지 않는다. 네 시안을 확인한 뒤 반드시 일반 행으로 복원한다.

### 18-9. 세로 카드 프리팹 저장과 다음 부품

1. 현재 카드는 View 씬의 일반 GameObject다. 지금까지의 수동 작업은 View에서 Ctrl+S로 씬 저장해야 남는다.

### 19-3. Root와 주요 자식의 Rect Transform

각 오브젝트에서 **Anchor Min → Anchor Max → Pivot → Pos → Width/Height** 순서로 입력한다. 표의 `(X,Y)`는 X와 Y 두 입력칸이다. 위치는 직접 부모를 기준으로 한다. 카드 부품의 Pos Z/Rotation X,Y,Z는 0, Scale X,Y,Z는 1로 확인한다.

| 오브젝트 | Anchor Min | Anchor Max | Pivot | Pos X / Y | Width / Height |
| --- | --- | --- | --- | --- | --- |
| SelectionCardWide | (0.5,0.5) | (0.5,0.5) | (0.5,0.5) | 0 / 0 | 520 / 320 |
| Artwork | (0.5,1) | (0.5,1) | (0.5,1) | 0 / -16 | 488 / 168 |
| NameText | (0.5,1) | (0.5,1) | (0.5,1) | 0 / -196 | 488 / 40 |
| DescriptionText | (0.5,1) | (0.5,1) | (0.5,1) | 0 / -240 | 488 / 40 |
| LockReasonText | (0.5,1) | (0.5,1) | (0.5,1) | 0 / -240 | 488 / 40 |
| CostRow | (0.5,0) | (0.5,0) | (0.5,0) | 0 / 8 | 488 / 28 |

Root만 520×320으로 바꿔도 자식의 크기·위치가 자동으로 이 표에 맞춰지지 않는다. 모든 행을 각각 입력한다.

Artwork 입력 예: Anchor Min X0.5/Y1 → Anchor Max X0.5/Y1 → Pivot X0.5/Y1 → Pos X0/Y-16/Z0 → Width488/Height168. 이때 그림 영역의 좌우 여백은 (520-488)/2=16이다.

기본 크기 520×320에서는 카드 위쪽에서 Artwork16~184, 이름196~236, 설명240~280, 가격284~312 영역을 쓴다. **이름과 설명/잠금 이유를 각각 한 줄**로 확인하는 시안이다. 복사 원본의 DescriptionText에는 두 줄 문구가 있으므로 우선 19-4의 한 줄 샘플로 교체한다. 두 줄이 필요한 경우 19-7의 크기를 적용한다.

### 19-4. Image와 텍스트 설정

기존 Image를 사용하며 같은 오브젝트에 Image를 중복 추가하지 않는다.

| Image 오브젝트 | 설정 |
| --- | --- |
| SelectionCardWide | Source Image None, Color #32204F, Alpha 약0.9 (`32204FE6`), Raycast Target OFF |
| Artwork | 준비한 UI Sprite, Color 흰색/Alpha1, Preserve Aspect ON, Raycast OFF. Sprite가 없으면 Source None과 임시 색 #654993 (`654993FF`) |
| Dim | Source None, 검정/Alpha 약0.55 (`0000008C`), Raycast OFF |
| 선택 테두리 4개 | Source None, #64D8FF/Alpha1 (`64D8FFFF`), Raycast OFF |
| CostIcon | 아이콘 준비 후 Sprite, 흰색/Alpha1, Preserve Aspect ON, Raycast OFF. 없으면 OFF |

Source None에서 Image Type이 숨겨지면 그대로 두며, 보이는 경우 Simple로 설정한다. 색은 Image 컴포넌트의 Color, 글자 색은 TMP의 Vertex Color에서 바꾼다. Hex를 6자리로 입력했다면 Alpha를 별도로 확인한다. Preserve Aspect로 그림 주변에 빈 공간이 생기면 원본 그림과 488×168 영역의 비율이 다른 것일 수 있다. 최종 그림 교체 시 함께 확인한다.

| TMP | Text Input 시안 | Font Size | 가로 / 세로 Alignment |
| --- | --- | --- | --- |
| NameText | 가로 카드 | 30 | Center / Middle |
| DescriptionText | 가로 배치 확인용 설명입니다. | 22 | Center / Middle |
| LockReasonText | [임시] 잠금 조건 안내 | 22 | Center / Middle |
| LockText | 잠금 | 36 | Center / Middle |
| CostText | 300 | 22 | Left / Middle |
| UnaffordableText | 비용 부족 | 22 | Left / Middle |

모든 TMP에 한글 Font Asset을 적용하고 Auto Size OFF, Raycast OFF, Wrapping Normal을 확인한다. 기본 글자는 흰색/Alpha1이며 UnaffordableText는 #FF6B6B다. Font Asset은 TMP 에셋이며 TTF/OTF를 직접 넣는 칸이 아니다. 문구는 배치 확인용이며 게임 조건을 정하지 않는다.

### 19-5. CostRow 자식을 488×28에 맞추기

CostIcon·CostText·UnaffordableText의 Anchor Min/Max/Pivot를 각각 모두 `(0,0.5)`로 설정한다. Pos Y/Z는 0이다.

| 자식 | Pos X | Width / Height | 보충 |
| --- | --- | --- | --- |
| CostIcon | 0 | 24 / 24 | 아이콘 준비 후 ON |
| CostText | 32 | 196 / 28 | 글자22, Left/Middle |
| UnaffordableText | 244 | 244 / 28 | 글자22, Left/Middle, 일반 상태 OFF |

24 + 간격8 + 196 + 간격16 + 244 = 488이다. 부모 CostRow의 크기만 변경하면 자식은 원래 높이36 등으로 남으므로 세 자식 모두 입력한다. 가격을 999,999로 바꿔 겹침을 확인한 뒤 300으로 복원한다.

가격이 없는 모드 카드 시안은 **해당 표시 샘플의 CostRow 전체를 OFF**로 둔다. 가격 자식을 삭제하지 않는다. 공통 프리팹은 일반 상태의 CostRow ON으로 저장한다.

### 19-6. 선택 테두리와 잠금은 Stretch 유지

LockedGroup은 Artwork, Dim은 LockedGroup, SelectedFrame은 SelectionCardWide 아래의 기존 부모 관계를 유지한다. 이 세 부모/부품의 Rect Transform은 Anchor Min(0,0)/Max(1,1)/Pivot(0.5,0.5), Left/Right/Top/Bottom0이다. 잠금은 488×168의 그림 영역, 선택 테두리는 520×320의 카드 전체를 따라간다. SelectedFrame 부모에는 Image를 추가하지 않는다.

LockText는 중앙 Anchor Min/Max/Pivot(0.5,0.5), Pos X/Y/Z0, 크기200×50을 유지한다. 텍스트 설정은 19-4를 따른다.

| 테두리 자식 | Anchor Min → Max | Pivot | 나머지 Rect Transform |
| --- | --- | --- | --- |
| Top | (0,1) → (1,1) | (0.5,1) | Left0, Right0, Pos Y0, Height4 |
| Bottom | (0,0) → (1,0) | (0.5,0) | Left0, Right0, Pos Y0, Height4 |
| Left | (0,0) → (0,1) | (0,0.5) | Pos X0, Width4, Top0, Bottom0 |
| Right | (1,0) → (1,1) | (1,0.5) | Pos X0, Width4, Top0, Bottom0 |

현재 세로 카드에서는 위 테두리 배치가 저장되어 있으므로 복사 후 확인하고 유지한다. Top/Bottom의 Width 대신 Left/Right, Left/Right의 Height 대신 Top/Bottom이 보이는 것은 Stretch 때문이다. 테두리를 고정 크기520×320 자식으로 바꾸지 않는다.

### 19-7. 두 줄 설명이 필요한 경우

기본520×320은 이름/설명이 각각 한 줄인 시안에 쓴다. 설명 또는 잠금 이유에 Enter를 넣어 두 줄로 만들 때는 다음 세 값을 함께 바꾼다.

| 오브젝트 | 변경값 |
| --- | --- |
| SelectionCardWide | Height360, Width520 유지 |
| DescriptionText | Height64, Pos Y-240, Width488 유지 |
| LockReasonText | Height64, Pos Y-240, Width488 유지 |

Artwork·NameText의 위치/크기, CostRow의 하단 Y8/488×28은 유지한다. 설명은 위에서240~304, 가격은324~352가 되어 간격20이 남는다. SelectedFrame은 Stretch 상태이므로 높이360에 맞춰진다. Font22로 실제 한글 Font Asset의 표시를 확인한다. 이름도 두 줄이거나 설명이 세 줄 필요하면 그 텍스트 영역·Root Height·후속 간격을 다시 계산한다. Auto Size로 먼저 줄여서 완료로 처리하지 않는다.

### 19-8. 네 가지 상태와 View 표시 확인

| 표시 시안 | SelectedFrame | LockedGroup | DescriptionText / LockReasonText | CostRow·가격 |
| --- | --- | --- | --- | --- |
| 일반 | OFF | OFF | ON / OFF | ON, 가격 흰색, UnaffordableText OFF |
| 선택 | ON | OFF | ON / OFF | ON, 가격 흰색, UnaffordableText OFF |
| 잠금 | OFF | ON | OFF / ON | OFF |
| 비용 부족 | OFF | OFF | ON / OFF | ON, 가격#FF6B6B, UnaffordableText ON |

Inspector 맨 위의 GameObject 활성 체크로 바꾼다. TMP/Image 컴포넌트의 체크와 구분한다. 외형 확인용 조합이며 선택·해금·가격 판정 규칙은 연결 때 다시 설명한다.

1. 검수 후 일반 상태·Root ON으로 복원하고 Prefab Mode에서 Ctrl+S로 저장한다. 상단 경로가 SelectionCardWide인지 확인한다.
2. Prefab Mode에서 View로 돌아온다. 기존 UIPatsPreviewRoot 아래 세로 카드는 잠시 OFF로 둔다. Project의 Wide 프리팹을 이 Root 아래로 드래그해 하나 배치한다. 시작 위치는 중앙0/0이다.
3. PopupRoot·GuideOverlayRoot OFF, UIPatsPreviewRoot ON으로 두고 Game 뷰1920×1080/1280×720에서 확인한다. Play 없이 네 상태를 수동 표시한다.
4. 네 개를 함께 비교하려면 Wide 씬 인스턴스만 세 번 복제해 2×2로 둔다. 네 개를 가로 한 줄로 놓지 않는다. 모두 중앙 Anchor/Pivot이고, 왼쪽 위 Pos(-280,200), 오른쪽 위(280,200), 왼쪽 아래(-280,-200), 오른쪽 아래(280,-200)로 시작한다. 520×320에서는 가로 간격40/세로 간격80, 520×360에서는 가로·세로 간격40이다.
5. 이는 비교용 씬 인스턴스 배치이며 공통 Wide 프리팹 안에 네 카드를 넣지 않는다. 표시 확인용 상태는 씬 Override로 유지하고 상태 차이를 Apply All로 공통 프리팹에 덮어쓰지 않는다.
6. 공통 Wide 프리팹은 일반 상태·Root ON으로 저장해 둔다. 작업 종료 시 View의 UIPatsPreviewRoot를 OFF로 하고 씬을 Ctrl+S로 저장한다. 아직 확인하지 않은 항목은 완료로 기록하지 않는다.

완료 기준은 가로 카드 안에 그림·이름·설명/잠금 이유·가격·선택 테두리가 들어가고 네 표시 상태와 두 해상도를 확인하는 것이다. 버튼 On Click·화면 전환·데이터 판정·FX는 이후 기존 일정에 진행한다.

## 20. 저장 파일 반영 검수 — 세로·가로 카드와 공통 팝업

이 절은 CampaignModeScreen 제작 전의 점검 기록이다. 이후 카드 크기·앵커와 Preview 활성 상태가 보완되었으므로 CampaignModeScreen의 최신 점검은 21절을 따른다.

재점검일: 2026-10-10. View.unity, SelectionCardVertical/Wide, GuideOverlayRoot, PauseMenuRoot, HelpPromptRoot, ConfirmDialogRoot와 폰트 참조를 읽기 전용으로 비교했다. Unity 실행·Play·화면 렌더링은 확인하지 않았다. 이 검수에서는 계획 문서만 갱신했으며 씬·프리팹·코드는 수정하지 않았다. 아래는 이 점검 시점의 저장값이며 실제 표시 확인 완료와 구분한다.

### 20-1. 저장값이 안내와 맞는 항목

- 두 카드 프리팹과 .meta가 있으며 View의 UIPatsPreviewRoot 아래에 각각 연결되어 있다.
- 카드 Root의 중앙 앵커/Pivot, 위치0/0, Vertical360×520, Wide520×320은 맞다.
- 카드 계층, 그림 아래 LockedGroup, 마지막 SelectedFrame, 가격 자식 관계는 맞다.
- LockedGroup·Dim·SelectedFrame은 전체 Stretch·여백0이다. SelectedFrame 부모 Image는 없고 사방 테두리의 Stretch·두께4는 맞다.
- 두 카드의 TMP 문구·폰트 크기·정렬·Auto Size OFF·Wrapping Normal·TMP Raycast OFF가 안내와 맞다.
- 일반 상태는 SelectedFrame·LockedGroup·LockReasonText·UnaffordableText OFF, DescriptionText·CostRow ON이며 카드 프리팹 Root는 ON이다.
- Wide 가격 자식은 CostIcon24×24/X0, CostText196×28/X32, UnaffordableText244×28/X244로 맞다.
- 가이드 화살표 Head의 Pos Z0·Rotation Z -45/+45, BodyPanel 중앙 배치·Pos0/-20·660×140은 맞다.
- View의 Canvas_Popup은 Overlay·Reference1920×1080·Match0·SortOrder100, PopupRoot OFF·Guide OFF·Help/Confirm OFF·Pause 내부 ON으로 저장되어 있다.
- Pause의 메뉴5개·세로 Layout·480×400과 자기 Label Target Graphic, Confirm의 중심 정렬·흰 글자·투명 버튼 Image·AnswerRow 중심 배치가 반영되어 있다.

### 20-2. Wide — 주요 자식 크기 수정 필요

Wide의 아래 앵커·Pivot·Pos는 이미 맞다. **Width/Height만 세로 값으로 남아 있어** 우선 이 다섯 오브젝트를 수정한다. Root520×320·한 줄 설명 시안 기준이다.

| SelectionCardWide 자식 | 현재 Width×Height | 목표 Width×Height |
| --- | --- | --- |
| Artwork | 328×300 | 488×168 |
| NameText | 328×44 | 488×40 |
| DescriptionText | 328×72 | 488×40 |
| LockReasonText | 328×72 | 488×40 |
| CostRow | 328×36 | 488×28 |

현재 그림은 카드 위에서16~316을 차지해 이름196~240·설명240~312·가격276~312와 겹칠 수 있다. 가격 자식은 폭488 배치인데 부모 CostRow가328이라 영역이 맞지 않는다. 위 크기로 바꾸면 19절의 그림16~184/이름196~236/설명240~280/가격284~312로 나뉜다. 두 줄 설명이 필요한 경우에만 19-7의 Root Height360·설명/이유Height64를 함께 적용한다.

### 20-3. Vertical — Anchor Min/Max Y 수정 필요

세로 카드의 해당 Pivot·Pos·크기는 맞지만 Anchor Min/Max Y가 중앙0.5로 남았다. Min과 Max 두 곳을 모두 바꾼 뒤 위치를 다시 입력/확인한다.

| SelectionCardVertical 자식 | 현재 Anchor Min = Max | 목표 Anchor Min = Max | 변경 후 Pos X/Y 확인 |
| --- | --- | --- | --- |
| Artwork | (0.5,0.5) | (0.5,1) | 0 / -16 |
| DescriptionText | (0.5,0.5) | (0.5,1) | 0 / -374 |
| LockReasonText | (0.5,0.5) | (0.5,1) | 0 / -374 |
| CostRow | (0.5,0.5) | (0.5,0) | 0 / 16 |

### 20-4. 폰트·색상과 가이드의 남은 설정

### 20-5. HelpPrompt의 씬 수정과 프리팹 저장을 구분

View의 HelpPrompt 인스턴스에는 Question/Description Center/Middle, 예/아니요 글자 흰색, AnswerRow Middle Center·Force Expand Width/Height OFF가 적용되어 있다. **Project의 HelpPromptRoot.prefab 원본에는 이 변경이 아직 저장되지 않았다.** 따라서 미작업으로 단정하지 않고 공통 프리팹 반영이 남은 것으로 기록한다.

원본 프리팹에는 Question/Description Left/Top·Raycast ON, AnswerRow Upper Left·Force Expand ON, 예/아니요 글자#323232가 남아 있다. 버튼 부모 Image Alpha1도 원본과 씬 모두에 남아 있으므로 공통 외형 기준의 Alpha0으로 보완한다. 기존 HelpPromptRoot를 Prefab Mode에서 열어 해당 값만 반영하고 저장한다. Canvas_Popup 전체를 교체하거나 Apply All로 다른 수정까지 일괄 반영하지 않는다.

### 20-6. 씬 표시와 실제 검수의 남은 항목

현재 View의 UIPatsPreviewRoot는 ON이며 두 카드 인스턴스는 중앙0/0에서 모두 활성이다. 함께 켜면 겹칠 수 있다. Wide 검수 때는 Vertical **씬 인스턴스**를 OFF로 두고, Vertical 검수 때는 Wide 인스턴스를 OFF로 둔다. 프리팹 기본 Root ON은 유지한다.

작업 종료 시 UIPatsPreviewRoot를 OFF로 하고 View 씬을 저장한다. 네 가지 상태의 실제 표시·긴 가격/한글·1920×1080/1280×720 검수는 저장 파일만으로 완료 여부를 확인할 수 없다. 버튼 On Click·화면 전환·가격/해금 판정·FX는 기존 이후 작업 단계이므로 이번 미반영 오류로 분류하지 않는다.

### 25-1. 화면과 큰 영역

Canvas_Screens 아래 새 Root를 만든다. Root/Background는 전체Stretch/여백0/Scale1이다. Background는첫형제/#1B1430/Alpha1/RaycastOFF. 이름 예시는 새 오브젝트용이다.

여기서 전체 Stretch는 Anchor Min(0,0), Max(1,1), Pivot(0.5,0.5), Left/Right/Top/Bottom 0을 뜻한다. 고정 크기 표의 "모두(0,1)" 같은 표기는 Anchor Min, Anchor Max, Pivot 세 값을 모두 해당 좌표로 맞추라는 뜻이다. 앵커와 피벗을 먼저 설정한 뒤 Pos와 Width/Height를 입력한다. 모든 Pos는 해당 오브젝트의 바로 위 부모 기준이며 Scale은 (1,1,1), Rotation은 (0,0,0)으로 시작한다.

MissionListRoot, Content, MissionRow, MissionPreviewRoot, SummaryPanel, PageArea, 각 PageRoot, 각 Group/List는 배치용 빈 UI 오브젝트(RectTransform)다. 그림에는 Image, 글자에는 TextMeshPro - Text (UI)를 사용한다. Viewport는 RectTransform에 RectMask2D를 추가한다. BackButton/PlayButton/CancelButton/SpellbookButton/FullLeaderboardButton은 MenuTextButton 인스턴스 자체를 가리키는 예시 이름이며, 그 이름의 빈 부모 아래 프리팹을 다시 넣으라는 뜻이 아니다. 버튼 인스턴스의 Label은 그대로 유지한다.

### 25-2. 미션 목록의 작은 행

MissionListRoot 내부 아래Rect는AnchorMin/Max/Pivot 모두(0,1)이다.

| 대상 | Pos X/Y | Width/Height |
| --- | --- | --- |
| UpArrow | 106/0 | 48/32 |
| Viewport | 0/-48 | 260/560 |
| Content | 0/0 | 260/716 |
| 각 MissionRow | 0/0,-104,-208,-312,-416,-520,-624 | 260/92 |
| DownArrow | 106/-620 | 48/32 |
| LockReasonText | 0/-676 | 260/64 |

Viewport에RectMask2D를추가한다. Content는Viewport의자식이다. 여기서는ScrollRect나참조/이벤트를연결하지 않는다. Content716은7×92+6×12로계산된다. 첫/마지막행 검수는Content PosY를수동으로0과156으로바꿔확인한뒤0으로저장한다. Viewport560/Content716의높이차156이다. DownArrow는Viewport끝608이후620부터놓아목록과겹치지않게한다.

RectMask2D가 자르는 대상은 Viewport 아래 Content/행/그림/글자다. UpArrow, DownArrow, LockReasonText는 Viewport의 자식이 아니라 MissionListRoot의 직접 자식으로 유지한다. Viewport에는 배경 Image나 일반 Mask가 필요하지 않다. 행의 Image/TMP는 Maskable ON을 유지한다. PosY 0에서 아래쪽 행 일부가 잘리는 것은 의도된 표시이며, PosY 156에서는 마지막 행 하단이 Viewport 하단에 맞는다.

각새MissionRow의NumberText는상단왼쪽/Pos0,0/32×92/Font24,Thumbnail은상단왼쪽/Pos44,0/208×92이다. SelectedFrame/LockedGroup/Dim은Thumbnail전체Stretch/여백0이다. SelectedFrame안에는기존카드의Left/Right/Top/Bottom4개Image자식을복사하고두께4/#64D8FF를사용한다. Dim검정Alpha0.55,LockText중앙100×40/Font28/잠금으로 시작한다. 자물쇠Sprite가준비되면중앙40×40Image로교체할수있다.

SelectedFrame은 기존 카드에서 복사한 테두리 Group을 Thumbnail 아래 두고 전체 Stretch로 맞춰도 된다. 원본 자식을 이동하거나 공통 카드 프리팹에 Apply하지 않는다. SelectedFrame 부모에 불투명 Image를 추가하지 않고 4개 테두리 Image에만 색을 적용한다. LockedGroup 안에서는 Dim을 먼저, LockText를 나중 형제로 놓는다. LockText는 Anchor Min/Max/Pivot 모두(0.5,0.5), Pos(0,0), CenterMiddle이다. NumberText는 CenterMiddle로 맞춘다. 첫 행 하나를 완성한 뒤 복제해 7개를 만들고 번호/PosY/활성 상태만 바꾼다.

기존Wide/Vertical프리팹전체를작은행에그대로축소하지않는다. 번호/썸네일/선택/잠금만있는새행을만들고공통테두리구조를재사용한다. 7개는표시샘플이며실제미션수는확정데이터에맞춘다. 처음에는1번SelectedON,2번일반,3번잠금으로비교한다. 잠금사유는임시문구로넣고조건판정은연결단계에정한다.

## 26. 현재 HUD 다음 작업 — H03 준비/판매 안내

2026-10-12 저장 파일 재확인에 따른 수동 제작 안내다. 기존 6일차의 남은 H03을 진행하며 전체 일정이나 UI → 버튼 연결 → FX 순서를 바꾸지 않는다. 에이전트는 씬/프리팹/코드를 수정하지 않았다. [최신 저장 파일 검수](UI_REVIEW_2026-10-12.md), [6일차 시간 배분](UI_WEEK1_DAILY_PLAN.md), [준비 참고 R43](UI_References/R43_PreparationHud.png), [판매 참고 R54](UI_References/R54_TrapSellPrompt.png)를 함께 사용한다.

### 26-1. 현재 파일에서 이어가기

Canvas_HUD의 PlayerStatus, StageStatus, Loadout은 전체 Stretch/여백 0/Scale 1이다. 동료/남은 적/중요 알림/미니맵/콤보/스킬/아이템 바가 이미 있으므로 큰 그룹을 다시 만들지 않는다. H03은 공통 KeyHint 파일과 Canvas_Check 아래 확인용 샘플만 있고 실제 HUD 배치는 없다. 이번 결과물은 방어 선택, 웨이브 시작, 함정 판매의 세 가지 정적 키 안내다.

권장 작업 순서와 시간: 공통 KeyHint 배치 보완 20분 → 준비 안내 두 줄 20분 → 판매 안내 10분 → 수동 상태 비교/두 해상도/저장 20~30분. 원래 6일차 준비/판매 1시간과 마감 확인 시간의 일부를 사용한다.

### 26-2. 기존 KeyHint 공통 배치 보완

Project의 Assets/04. Prefabs/KeyHint.prefab을 더블클릭해 Prefab Mode에서 연다. 현재 KeyBox는 중앙 64×64, ActionText는 중앙 Pos(0,-16)/320×88, KeyText는 중앙 고정 200×50이다. 이 값을 기존 17-4의 가로 배치로 보완한다. 새 KeyHint 에셋을 만들지 않는다.

| 대상 | Anchor Min/Max/Pivot | Pos X/Y | Width/Height |
| --- | --- | --- | --- |
| KeyHint Root | 모두 (0.5,0.5), 기존 중앙 유지 | 0/0 | 420/88 |
| KeyBox | 모두 (0,0.5), 왼쪽 중앙 | 10/0 | 64/64 |
| ActionText | 모두 (0,0.5), 왼쪽 중앙 | 90/0 | 320/88 |
| KeyText | Min(0,0), Max(1,1), Pivot(0.5,0.5) | Left/Right/Top/Bottom 모두 4 | 부모 안쪽 56×56 |

모든 Scale은 1/1/1이다. Root는 RectTransform만 유지한다. KeyBox에는 기존 Image를 사용하고 색 #071B24, Alpha 0.92로 둔다. Sprite가 없으면 우선 단색 배경으로 확인한다. KeyText와 ActionText는 BMDOHYEON_ttf SDF 및 그 폰트의 기본 Material Preset, Font 28, 흰색, Auto Size OFF를 사용한다. KeyText는 Center/Middle, ActionText는 Left/Middle, Wrapping Normal이다. Image/TMP의 Raycast Target은 OFF다.

KeyBox의 밝은 테두리는 기존 카드의 선택 테두리처럼 정적 Image 4개로 만들 수 있다. KeyBox 아래 빈 KeyBorder를 전체 Stretch/여백 0으로 두고 Left/Right/Top/Bottom Image를 자식으로 배치한다. 색 #D9EEFF, Alpha 1, 두께 2, Raycast OFF다. Left는 왼쪽 세로 Stretch/Pivot(0,0.5), Right는 오른쪽 세로 Stretch/Pivot(1,0.5), Top은 위쪽 가로 Stretch/Pivot(0.5,1), Bottom은 아래쪽 가로 Stretch/Pivot(0.5,0)이다. 세로 선은 Width 2/Top·Bottom 0/PosX 0, 가로 선은 Height 2/Left·Right 0/PosY 0으로 둔다. KeyText는 KeyBorder보다 뒤 형제로 배치한다. Glow/애니메이션은 만들지 않는다.

공통 샘플은 B / 방어 선택으로 두고 Ctrl+S로 저장한다. 이것은 공통 배치 수정이다. 다음 HUD 인스턴스의 화면 좌표와 다른 문구는 원본 KeyHint에 Apply하지 않는다.

### 26-3. HUD의 준비 안내 두 줄

Canvas_HUD.prefab을 Prefab Mode에서 열고 기존 StageStatus 아래에 PreparationHintRoot를 만든다. 빈 UI RectTransform 그룹이며 Image/Button/추가 Canvas/Layout Group을 붙이지 않는다. 일반 Transform으로 생성되었다면 UI Panel로 만든 뒤 기본 Image를 제거해 RectTransform 그룹으로 만든다.

```text
Canvas_HUD
  StageStatus
    ImportantNoticeRoot         기존 중요 알림
      NoticeText
    PreparationHintRoot         새 빈 RectTransform 그룹
      DefenseHint               KeyHint 프리팹 인스턴스
        KeyBox
          KeyBorder             테두리를 만든 경우
          KeyText
        ActionText
      StartWaveHint             KeyHint 프리팹 인스턴스
    SellHint                    KeyHint 프리팹 인스턴스
```

DefenseHint와 StartWaveHint는 각각 끌어 놓은 KeyHint 인스턴스 자체의 이름이다. 같은 이름의 빈 부모를 만들고 그 안에 KeyHint를 넣는 구조가 아니다. SellHint도 인스턴스 자체이며 PreparationHintRoot 밖, StageStatus의 직접 자식이다.

1920×1080 기준의 시작값:

| 대상 | Anchor Min/Max/Pivot | Pos X/Y | Width/Height |
| --- | --- | --- | --- |
| PreparationHintRoot | 모두 (0,1), 상단 왼쪽 | 44/-560 | 420/196 |
| DefenseHint | 모두 (0,1), 상단 왼쪽 | 0/0 | 420/88 |
| StartWaveHint | 모두 (0,1), 상단 왼쪽 | 0/-104 | 420/88 |

먼저 Project의 KeyHint를 PreparationHintRoot에 드래그해 DefenseHint로 이름을 바꾸고 Root의 Rect만 위와 같이 설정한다. 내부 KeyBox/KeyText/ActionText는 보완한 공통 값을 상속한다. 이를 복제해 StartWaveHint를 만들고 PosY -104와 문구만 바꾼다. 두 줄 사이 간격은 16이다.

| 인스턴스 | KeyText | ActionText | 설명 색 |
| --- | --- | --- | --- |
| DefenseHint | B | 방어 선택 | #FFCC4D |
| StartWaveHint | G | 웨이브 시작 | #FFFFFF |

이 그룹은 동료 정보 아래/아이템 바 위의 왼쪽 공간을 사용하는 시안이다. 부모 StageStatus나 기존 아이템 바의 앵커/좌표를 다시 초기화하지 않는다.

### 26-4. 고정 테스트 위치의 판매 안내

Project의 KeyHint를 StageStatus에 직접 드래그하고 인스턴스를 SellHint로 이름을 바꾼다. Root의 Anchor Min/Max/Pivot을 모두 (0.5,0.5), Pos X 0/Y 100, Width 420/Height 88, Scale 1로 설정한다. 이는 화면 중앙보다 위쪽에 두는 고정 확인 위치이며 판매 대상의 실제 위치/추적 좌표가 아니다.

KeyText는 E, ActionText는 함정 판매, 설명 색은 #64D8FF로 둔다. 공통 KeyHint 원본에는 이 문구/색/화면 좌표를 Apply하지 않는다. B/G/E는 참고 이미지의 표시 샘플이며 우하단 스킬의 Q/E와 실제 입력 계약을 확정하는 작업이 아니다. 기능 키와 표시 조건은 전체 UI 외형을 만든 뒤 연결 단계에서 정한다.

### 26-5. 수동 시안 확인과 저장

| 확인 시안 | PreparationHintRoot | SellHint |
| --- | --- | --- |
| 일반 HUD | OFF | OFF |
| 준비 안내 | ON | OFF |
| 판매 대상 안내 | OFF | ON |

두 Root의 Active 체크만 수동으로 바꾼다. 준비/판매 시안 확인 중 기존 NoticeText의 '전투 시작!'이 함께 보이면 ImportantNoticeRoot도 잠시 OFF로 둔다. 문구를 지우거나 알림 그룹을 재생성하지 않는다. 웨이브 시안은 다음 H04에서 기존 알림을 다시 켜서 확인한다.

Canvas_HUD를 Ctrl+S로 저장한 뒤 View 씬으로 돌아와 인스턴스를 확인한다. Game 뷰에서 다른 전체 화면/팝업/가이드를 잠시 숨기고 HUD를 켠 상태로 1920×1080과 1280×720을 선택한다. Play 모드는 필요하지 않다. 키와 설명 겹침, 한글 잘림, 동료 정보/아이템 바와의 간격, 판매 문구와 중앙 조준 영역의 겹침을 확인한다. 위치값은 저장 파일과 참고 영역에 따른 시작값이며 실제 표시를 보고 작은 조정을 한다.

Shift 표시도 확인하려면 해당 인스턴스만 KeyBox Width 96/ActionText PosX 122/Root Width 452로 바꾸어 설명 Width 320과 간격 16을 유지한다. 비교 후 B/G/E 시작값으로 복원한다. 두 줄 설명은 ActionText 88 높이 안에서 확인한다.

최종 기본 HUD 시안은 PreparationHintRoot/SellHint 모두 OFF로 저장한다. 준비 화면을 다시 확인할 때는 PreparationHintRoot만 ON으로 켠다. 공통 KeyHint는 ON인 원본으로 유지한다. View 확인 중 만든 상태 Override는 기본값으로 복원한 뒤 씬을 저장한다. 완료 기록은 'H03 안내 3종의 외형/수동 표시/저장 확인'으로 남기고 입력, 대상 추적, 판매 판정, FX 완료로 기록하지 않는다.

다음 작업은 기존 7일차 H04 웨이브 알림이다. 이미 있는 ImportantNoticeRoot/NoticeText에서 3/2/1, 시작!, 다음 웨이브 시안을 수동 교체하고 필요한 글자 크기를 인스턴스에서 비교한다. 그 후 H08 설치 가능/불가 안내와 목표/재화 기초 가이드를 만든다. H02 슬롯 상태·남아 있는 Material Preset·정적 리소스는 1주차 표시 마감 목록으로 유지한다.

## 27. H03 저장 이후 — H04 웨이브 알림 3종

2026-10-12 후속 저장 파일을 읽기 전용으로 확인했다. H03의 PreparationHintRoot, DefenseHint, 현재 이름 StarWaveHint, SellHint와 B/G/E 문구·좌표가 저장되어 있다. 26절의 생성 안내를 다시 실행하지 않고 남은 외형만 마감한 뒤 기존 7일차 H04로 이어간다. Unity 화면 실행, 씬/프리팹/코드 수정은 에이전트가 수행하지 않았다.

### 27-1. 준비/판매 안내의 짧은 마감

KeyHint 공통 프리팹에서 KeyBox Image가 흰색이며 KeyText도 흰색이다. KeyBox를 #071B24/Alpha 0.92로 맞추고 Image/KeyText/ActionText의 Raycast Target을 OFF로 둔다. KeyHint 루트의 Left/Right/Top/Bottom 장식은 준비 인스턴스에서 제거되었으나 판매 인스턴스에는 남아 있어 형태가 다르다. 이 루트 장식 4개는 공통 원본에서 OFF로 두어 표시를 통일한다. 키박스 내부 테두리는 별도의 정적 외형 마감으로 만들 수 있다.

Canvas_HUD에서 DefenseHint의 ActionText를 #FFCC4D, SellHint의 ActionText를 #64D8FF로 맞춘다. 현재 이름 StarWaveHint의 G/웨이브 시작 인스턴스는 올바른 위치에 있어 이름 때문에 재생성하지 않는다. H04 검수 중 PreparationHintRoot와 SellHint를 OFF로 둔다. 기본 HUD 저장도 두 안내 OFF로 한다.

### 27-2. 기존 공용 알림 영역 재사용

Canvas_HUD.prefab을 열어 StageStatus/ImportantNoticeRoot/NoticeText를 선택한다. 카운트다운, 시작, 다음 웨이브마다 별도 화면이나 TMP를 복제하지 않고 같은 NoticeText의 표시 문구/크기/색을 수동 교체한다.

현재 ImportantNoticeRoot는 상단왼쪽 (728,-180)/460×88이고 Objective는 상단중앙 (0,-164)/320×40이다. 1920×1080에서 두 Rect 영역의 세로 범위 180~204가 겹치므로, 글자 크기를 늘리는 이번 작업에서는 알림을 목표 정보 아래에 여유를 두고 놓는다. 실제 글자 겹침 여부는 별도 Game 뷰 확인 대상이다.

| 대상 | Anchor Min/Max/Pivot | Pos X/Y | Width/Height |
| --- | --- | --- | --- |
| ImportantNoticeRoot | 모두 (0.5,1), 상단 중앙 | 0/-220 | 560/112 |
| NoticeText | Min(0,0), Max(1,1), Pivot(0.5,0.5) | 네 여백 모두 0 | 부모 전체 |

ImportantNoticeRoot와 NoticeText Scale은 1/1/1이다. StageStatus 등 다른 그룹은 재설정하지 않는다. 이 위치는 남은 적/통과수 아래의 중요 알림 영역을 유지하는 시작값이다. 화면 중앙의 큰 별도 배너나 새 Canvas를 추가하지 않는다.

### 27-3. TMP 설정과 3개 시안

NoticeText는 기존 BMDOHYEON_ttf SDF 및 해당 기본 머티리얼을 유지한다. Center/Middle, Auto Size OFF, Wrapping Normal, Overflow Truncate, Rich Text ON, Vertex Gradient OFF, Raycast Target OFF, Margin Left/Right/Top/Bottom 4를 시작값으로 사용한다. 잘림이 발생하면 영역/글자 크기를 조정하고 Auto Size로 감추지 않는다.

| 표시 시안 | 문구 | Font Size | 글자 색 |
| --- | --- | --- | --- |
| 카운트다운 | 3, 2, 1을 하나씩 수동 교체 | 72 | #FFFFFF |
| 시작 | 시작! | 56 | #FFCC4D |
| 다음 웨이브 | 다음 웨이브 + 실제 줄바꿈 + 2 / 5 | 40 | #64D8FF |

다음 웨이브는 입력 칸에 실제 두 줄로 넣는다. 2/5는 정적 샘플이며 총 웨이브 수/실제 타이밍을 확정하지 않는다. 각 시안은 같은 글자 오브젝트에 입력하여 표시 비교한다. 시간 경과, 웨이브 이벤트, 자동 문구 변경, 화면 전환, Tween, 파티클, 발광/왜곡 FX는 전체 UI 외형 이후 단계로 둔다.

### 27-4. 수동 확인과 저장

준비/판매/가이드를 OFF로 두고 ImportantNoticeRoot를 ON으로 켜서 세 시안을 1920×1080과 1280×720에서 차례로 확인한다. 72 크기 숫자와 두 줄 문구가 잘리지 않는지, 위쪽 통과수/남은 적 및 우상단 웨이브/시간과 겹치지 않는지 본다. 알림 OFF 상태에서는 다른 HUD가 그대로 보이는지도 확인한다.

기본 저장은 문구 '시작!'/Font 56/#FFCC4D로 복원하고 ImportantNoticeRoot OFF, PreparationHintRoot OFF, SellHint OFF로 둔다. Canvas_HUD와 View 씬을 저장하고 표시 비교 결과를 기록한다. 세 문구·크기·색의 시안은 이 표에 보관하며 실제 표시 로직 연결 완료로 체크하지 않는다.

Screen Space Overlay Canvas 루트의 저장된 Scale/Size 값만으로 표시 오류를 단정하지 않는다. 루트 Canvas의 Rect는 Unity가 관리하므로 이 작업에서 Scale을 일괄 변경하지 않는다. 내부 그룹의 설정과 실제 Game 뷰 표시를 기준으로 확인한다.

H04 외형 확인 이후 다음 작업은 기존 7일차 H08 설치 가능/불가·사유·회전/확정/취소 안내다. 일정과 FX 시작 조건은 변경하지 않는다.

## 28. 다음 새 작업 — H08 설치 가능/불가 안내

2026-10-12 후속 저장 파일에서 ImportantNoticeRoot의 상단중앙 (0,-220)/560×112 배치는 확인했다. NoticeText는 여전히 '전투 시작!'/40/흰색/알림 ON인 샘플 상태이므로 세 시안의 수동 검수 완료로 판단하지 않는다. 이번 새 작업은 기존 7일차 H08이며, UI 상태·금지 표시·사유·회전/설치/취소 안내의 외형을 만든다. 실제 설치 판정·월드 대상 추적·입력·고스트 메시·FX는 연결/후속 제작 단계로 유지한다. 에이전트가 씬/프리팹/코드를 수정한 작업이 아니다.

참고: [설치 불가 R22](UI_References/R22_PlacementInvalid.png). 참고의 금지 아이콘은 정식 리소스로 교체하고, 이번 시작값에서는 TMP의 ×를 자리 표시로 사용한다. 현재 BMDOHYEON_ttf SDF에 해당 문자(U+00D7)가 저장되어 있다. 배치는 실제 표시를 본 뒤 작은 조정이 필요한 시작값이다.

### 28-1. 같은 HUD 안에 빈 UI 그룹 만들기 — 20분

Canvas_HUD.prefab을 열고 기존 StageStatus 아래에 PlacementGuideRoot를 만든다. RectTransform만 있는 빈 UI 그룹이다. UI Panel로 만들었다면 기본 Image를 제거한다. 추가 Canvas/Button/Layout Group을 붙이지 않는다.

```text
Canvas_HUD
  StageStatus
    ImportantNoticeRoot       기존 웨이브 알림
    PreparationHintRoot       기존 준비 안내
    SellHint                  기존 판매 안내
    PlacementGuideRoot        새 빈 RectTransform
```

### 28-2. 상태·금지 표시·사유 만들기 — 20분

StateText/ReasonText/ForbiddenIcon은 UI의 Text - TextMeshPro로 만든다. BMDOHYEON_ttf SDF/해당 기본 머티리얼, Auto Size OFF, Center/Middle, Raycast OFF를 사용한다. StateText는 Font 32, ReasonText는 Font 24, ForbiddenIcon은 Font 42/문구 ×/색 #FF5C5C다. StateText와 ReasonText는 각각 한 개만 만든다. 가능/불가마다 별도 글자 오브젝트를 복제하지 않는다.

### 28-3. KeyHint 인스턴스 세 개 배치 — 25분

현재 KeyHint 공통 프리팹의 KeyBox Image는 흰색/Alpha 1이고 키 글자도 흰색이다. 먼저 공통 원본에서 KeyBox를 #071B24/Alpha 0.92, Image/KeyText/ActionText의 Raycast Target을 OFF로 마감한다. 루트 바로 아래의 Left/Right/Top/Bottom 장식도 OFF로 둔다. KeyBox 내부의 정식 테두리와 혼동하지 않는다.

긴 키 표기를 위해 세 인스턴스 내부 KeyBox Width를 96, ActionText PosX를 122로 설정한다. 공통 배치의 왼쪽중앙 Anchor/Pivot, KeyBox Pos(10,0)/Height 64, ActionText Width 320/Height 88, KeyText Stretch/여백 4, Font 28을 유지한다. 키박스 오른쪽 106과 설명 왼쪽 122 사이 간격은 16이고, Root 오른쪽 여백은 10이다. 인스턴스 사이 간격은 32다. 이 H08 전용 크기/문구/좌표는 KeyHint 원본에 Apply하지 않는다.

| 인스턴스 | KeyText | ActionText |
| --- | --- | --- |
| RotateHint | R | 회전 |
| ConfirmHint | Enter | 설치 |
| CancelHint | Esc | 취소 |

R/Enter/Esc는 정적 시안용 임시 키다. 기존 입력 계약을 변경하거나 실제 바인딩으로 확정하지 않는다. 가능 시안의 ConfirmHint는 설명/키를 #FFCC4D로, 불가 시안에서는 #858D99로 바꿔 실행 가능/불가의 외형을 비교한다. Hint에 Button을 붙이거나 클릭/입력을 연결하지 않는다.

### 28-4. 상태 비교·두 해상도·저장 — 25분

H08 시안 확인 중 ImportantNoticeRoot/PreparationHintRoot/SellHint/가이드는 OFF, PlacementGuideRoot는 ON으로 둔다. 이는 비교용 표시 상태이며 실제 UI 우선순위를 정한 규칙이 아니다.

일반 HUD는 PlacementGuideRoot OFF, 설치 가능은 Root ON/금지 표시 OFF/녹색 상태/금색 설치 안내, 설치 불가는 Root ON/금지 표시 ON/붉은 상태·사유/회색 설치 안내로 비교한다. 같은 StateText/ReasonText 값과 Active/색만 수동으로 바꾼다.

1920×1080과 1280×720에서 Enter가 키박스 안에 들어가는지, 상태/사유/금지 표시가 겹치지 않는지, 아이템 번호키/아이템 바/우하단 스킬을 가리지 않는지, 긴 사유가 잘리지 않는지 확인한다. 실제 Game 뷰 검수는 Play 모드 없이 진행한다. 루트 Overlay Canvas의 저장 Scale 값은 오류로 단정하거나 일괄 수정하지 않는다.

가능 시안의 문구/색으로 복원하고 ForbiddenIcon OFF, PlacementGuideRoot OFF로 기본 저장한다. Canvas_HUD와 View 씬을 저장하고 확인한 외형/임시 키/금지 Sprite 교체 필요를 기록한다. 판정, 입력, 추적, FX 완료로 기록하지 않는다.

다음 순서는 기존 7일차 기초 가이드의 목표·재화·장비 바 설명 마감이다. 전체 UI 외형 제작 → 버튼/화면 전환/데이터 연결, FX는 전체 UI 외형 이후라는 사용자 순서를 유지한다.

## 2026-10-16 도움말 제작 기준 갱신

[도움말 최신 계획](UI_HELPBOOK_PLAN.md)이 기존 도움말 7페이지 고정 및 이전 임시 배치 안내를 대체한다. 기존 페이지를 보존하며 새 이미지 중심 페이지를 추가한다. 18장 원본 참고는 `Docs/UI_References/HelpBook_2026-10-16`에 저장했다. 스크린샷 준비 전에는 틀·본문까지만 제작하고 Arrow는 OFF로 보관한다. 실제 게임 이미지 삽입 후 최종 배치한다. 전체 UI 외형→버튼/전환 연결 및 검증→후속 FX라는 기존 작업 기준은 유지한다.

## 2026-10-16 사용자 추가 연출 계획

[UI·게임 연출 계획](UI_VFX_WORK_PLAN.md)에 설치 완료·피격 화면/캐릭터·무기 사용·도움 부유·카드 호버·강화 버튼 밝기·기지 효과·적 수 변화 연출을 추가했다. 실제 게임 데이터 연결을 먼저 진행하며, 튜토리얼/관련 부품은 사용자 요청에 따라 후반으로 보류한다. UI 최종 리소스와 상세 미술 검수는 리소스 수령 후 진행한다. 이번 항목은 구현 완료가 아닌 계획이다.

## 2026-10-17 현재 구현 기반 UI 연결 계획

사용자 진행 보고와 현재 로컬 API/프리팹을 대조한 [UI 연결 계획](UI_CONNECTION_PLAN.md)을 추가했다. HP/에너지/재화/웨이브부터 연결하며, 최신 콤보·궁극기·활·설치 확장 코드는 실제 작업본과 공개 API 확인 후 이어 붙인다. 다음 연결 작업의 예상 예산은 기존 전체 6주 안의 7일·56시간이며 전체 UI/게임 연결 완료 보장이 아니다. 튜토리얼/스크린샷 정렬은 후반으로 유지한다. 이번 변경은 계획 문서이며 코드·씬·프리팹 연결 및 실행 검증 완료를 뜻하지 않는다.
