# UI·게임 연출 추가 계획 — 2026-10-16

## 범위와 순서

사용자 요청: 설치 완료 이펙트, 피격 화면 테두리 빨강/캐릭터 깜빡임, 무기 발사 효과, 도움 표시 상하 움직임, 카드 호버 상승/테두리 반짝임, 무기 강화 버튼 밝아짐, 기지 위 이펙트, 통과/남은 적 수 변화 연출.

현재 실제 게임과 UI 데이터/버튼 연결을 우선한다. 튜토리얼과 튜토리얼 공통 부품은 후반으로 보류한다. 기존 화면은 유지하며 UI 담당자 리소스 수령 전에는 임시 그림과 교체 가능한 색/시간/크기로 구조를 준비한다. 이번 변경은 계획 문서이며 실제 연출 코드/씬/프리팹을 구현하지 않았다.

## 저장 코드에서 확인한 기반

- Assets/Plugins/Demigiant/DOTween 및 Assets/Resources/DOTweenSettings.asset 존재. 새 설치 불필요. 모듈 실제 실행은 미검증.
- Combat/DamageReceiver.OnDamaged(DamageInfo, float): 적용 피해 이벤트 존재. 피격 표현 연결 후보. 피해 0/회복/초기화에서 피격 연출이 나오지 않도록 의미 확인 후 연결.
- Combat/Attacker.OnAttackStarted / OnAttackEnded / OnFirstValidHit 존재. 공격 시작은 발사체가 실제 생성되는 순간이나 개별 적중 위치 이벤트와 동일하지 않다. 무기 발사/스킬 실제 실행 시점은 해당 실행 모듈과 연결한다.
- Hero/Skill/SkillCaster.OnSkillStarted / OnSkillEnded 존재.
- KMB/Installation/BuildPlacementController: 점유·생성·TryInitialize 성공 후 wasPlaced=true. 설치 성공 공개 이벤트는 현재 읽은 코드에서 확인되지 않았다. 실패/롤백/프리뷰 OnEnable에 설치 완료 효과를 연결하지 않는다.
- KMB/Wave/WaveController: ActiveEnemyCount, PassedEnemyCount, DiedEnemyCount 및 웨이브 상태/이벤트 존재. 활성 적 수는 미출현 적을 포함하는 '웨이브 전체 남은 적'과 다를 수 있다. UI가 의미를 임의 확정하지 않는다.
- Presentation/UI/PlayerHudView, StageHudView 존재. 값을 표시하는 기존 책임을 유지하며 연출은 작은 별도 컴포넌트 또는 명확한 호출로 분리한다.

## 연출별 구현 방향 — 사용자 지정 시작 시안

DOTween은 움직임·크기·색·투명도를 담당하고, 불꽃·먼지·발사 효과는 Particle System이나 Trail과 조합한다.

| 요청한 연출 | 작업 방식 | 시작 시안 |
| --- | --- | --- |
| 설치물 설치 효과 | 설치 성공 위치에 먼지·빛·바닥 링, 시각 부분만 크기 변화 | 약 0.3초 |
| 피격 시 시야 빨강 | 화면 가장자리의 붉은 이미지가 나타났다 사라짐 | 빠르게 나타나고 약 0.25초 복원 |
| 주인공 깜빡임 | 캐릭터 재질의 색·발광 변화 | 약 0.3초 |
| 무기 발사 효과 | 발사 위치 효과＋궤적＋적중 효과를 구분 | 실제 발사·타격 순간에 재생 |
| 도움 표시 위아래 이동 | 아이콘이나 화살표만 반복 이동 | 상하 6~10, 편도 약 0.7초 |
| 카드에 커서를 올리면 상승 | 카드 그림 부분 이동＋테두리 밝기 변화 | 위로 8~12, 약 0.15초 |
| 강화 버튼 밝아짐 | 기존 Button Color Tint 우선 사용 | 약 0.1초 |
| 기지 위 효과 | 월드 파티클＋느린 빛 맥동 | 대기 효과부터 제작 |
| 적 수 변화 강조 | 숫자 즉시 변경＋작은 확대·색 강조 후 복원 | 약 0.2초 |

위 수치는 최초 제작 기준이며 최종 리소스 적용 시 조정한다. 아래 상세 제작안의 시간 범위는 조정 여유이며 별도 중복 작업이 아니다.

## 공통 구조

- 연출 컴포넌트와 프리팹은 Presentation 담당 영역에 둔다. 기존 게임 로직/공용 이벤트 계약은 임의 변경하지 않는다.
- 카드 Root 아래 VisualRoot를 두어 Layout/클릭 영역과 이동 연출을 분리한다. 장식 Graphic Raycast Target OFF.
- DOTween은 위치/크기/알파/색 전환에 사용하고, 불꽃·먼지·발사체/궤적은 Particle System/Trail과 조합한다.
- 기준 위치/크기/색을 기억하고 재진입 시 트윈을 중첩 생성하지 않는다. 비활성화·파괴 시 소유 트윈 종료 및 기준값 복원, 풀링 시 재사용 상태 초기화.
- 메뉴 호버·도움 아이콘은 일시정지 중에도 필요하면 unscaled time. 전투/월드 효과는 게임 정지 정책을 따른다. 파티클과 Tween 시간을 함께 확인한다.
- 이벤트 구독은 대상 수명과 맞추고 씬 전환·플레이어 사망·장비 변경 시 이전 대상 구독/효과를 정리한다.
- 코드 연결 검증은 실제 이벤트 1회에 효과 1회, 중복 구독/누적 Tween/원복 실패를 우선 확인한다. 상세 미술·다중 해상도 검수는 사용자 요청대로 최종 리소스 적용 시 진행한다.

## 실제 작업 순서

1. 데이터 연결: HP/에너지/재화/웨이브/통과 수/남은 적 의미 확정, 공격·설치 성공·피격 호출 지점 확인.
2. UI 공통: 기존 버튼 Tint 정리→카드 VisualRoot 호버/테두리→숫자 변화 강조.
3. 피격: 화면 가장자리 표시→캐릭터 히트플래시. 유효 피해/연속 피격/사망 복원 확인.
4. 전투: 무기 1종의 실제 발사/타격 시점으로 먼저 구현→다른 무기/스킬로 확장.
5. 설치·기지: 설치 성공 신호 연결 협의 후 완료 VFX→기지 Idle/피격 상태.
6. 도움 표시 부유와 튜토리얼 적용: 후반 작업으로 유지.
7. 최종 UI/VFX 리소스 교체와 강도·시간·화살표 위치·해상도 폴리싱.

## 연결 전에 정할 두 항목

- '기지 위'가 방어 목표인지 포털/던전 출입구인지 실제 게임 오브젝트를 지정해야 한다. 현재는 위치/효과 종류를 확정하지 않는다.
- '통과/남은 적' 중 현재 숫자가 무엇인지 Stage별 HUD와 연결 계약을 먼저 구분한다. 통과 수는 실패 위험 증가, 남은 적은 진행 감소라는 의미에 맞춰 연출한다.
